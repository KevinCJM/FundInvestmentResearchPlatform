# AI 助手上下文管理：调研、设计与验收

日期：2026-09-20。范围：现有 Chat Completions harness 的容量、压缩、恢复及对应设置/状态展示。

## 1. 问题与边界

真实故障：61 字的 ETF 动量需求执行了 38 次目录查询、3 次压缩，最后两组消息约 48,561 字符即被拒绝。原实现把 60,000 字符的 70% 预警阈值和“两组以内不能压缩”结合，误报模型容量不足。继续后单条 reasoning_content 41,038 字符，保留最近整组的固定策略再次失败。

Boundary：本次仅修复上下文持续工作能力及必要配置/验收；容量判断错误阻断正常研究，必须替换。复用现有 HTTP 客户端、SQLite 事件/工具回执、取消机制、前端状态和测试框架，不引入 agent 框架。指标数学、PIT、产品选择、校验与保存确认、API 唯一选用、已有草稿/试算归属、无进展检测均保持原契约。默认仍不限制工具次数和模型往返次数。

方案选择：模型容量计量 + 完整交互检查点 + 持久回执回读。单纯增加字符上限不能解决网关差异及单条巨大消息；纯滑动删除会丢研究口径；完全依赖模型摘要容易失败或失真；压缩插件/多智能体重构超出本次必要范围。

## 3. 容量契约

每组 LLM API 增加 `context_window_tokens`：0 表示自动，显式值为 8,192–2,000,000。省略字段保留现值，0 可恢复自动。配置是客户端容量声明，不会扩大供应商实际限额。

自动只匹配已确认的端点和精确模型 ID：OpenCode Go 的 deepseek-v4.1-flash 使用 1,000,000；其他未知路由保守使用 32,768。用户可覆盖网关额度。不同 API 不串配置，不改变 key/effort/timeout。

输入可用量 = 窗口 − min(32,768, 窗口/4) 输出余量。85% 触发整理，优先以可用量的 60% 为目标选择近期内容；确定性回退仍须实际缩小且低于硬限制，不承诺所有材料都能缩至 60%。这是请求大小门槛，不是会话总预算。估算覆盖 system、历史摘要、用户原文、消息（含 reasoning_content）和工具 schema。用 UTF-8 文本估算并根据同一端点/模型的真实 prompt_tokens 向上校准；统计明确是估算，非精确 tokenizer。

`AGENT_CONTEXT_CHAR_LIMIT` 不再有隐含默认值；已明确设置时仍作为额外字符硬限制以兼容运维配置。软阈值只触发整理，不能因为消息少就拒绝本来可发送的请求。

## 4. 检查点算法

1. 只在 pending tool batch 完成后整理。assistant 的 calls 与所有 tool 回执组成不可拆分单元；不产生孤立 call/result，不执行历史工具。
2. 按序列化大小选近期完整单元，允许保留零个工具单元；超大最新单元也能进入检查点。最新用户消息及最近退休用户原文作为明确的请求材料保留。
3. 检查点包含此前摘要、已完成动作与证据引用、最新需求和未决事项。当前草稿、哈希、校验和 PIT 上下文仍从服务端状态装配。
4. 摘要输入是普通回复、工具参数/结果与引用的有界投影；不转述模型私有思考。已退休组的 reasoning 不放入摘要提示；未退休组绝不删 reasoning 字段。
5. 投影较小时直接形成确定性检查点；较大时向当前已选 API 请求一次简短摘要。输入先控制大小，不把超大原历史原封不动交给摘要器。
6. 摘要失败可使用事实投影，前提是它能装下且保留必要材料；否则在原请求仍可发送时继续，真正无法容纳时暂停，保留原状态。模型摘要作为标记过的历史消息注入，不升级为 system 指令。
7. 仅安装更小、满足硬限制的完整检查点。成功后更新压缩源 hash、前后估算和阶段事件；取消/失败不写“已经压缩”标记。相同无收益候选不反复调用摘要模型。

工具来源按前置 assistant 调用批次与消息顺序确定，不能用整段历史的 call_id 首次/末次映射。已结束批次可复用同一 ID；发送准入、恢复净化、摘要投影及待执行调用收束共用同一规则。孤立结果、同批重复及不完整交互不得借后续调用取得来源；旧未知工具按既有省略契约处理。执行占用与身份边界见 [AI 功能设计第3.4节](ai-functions-design.md#34-执行生命周期与调用身份)。

运行循环和压缩边界也从上述批次解析结果判断待执行项，不以旧 `pending_calls` 的存在或内容决定派发及是否允许整理。尾批已有结果的调用保持关闭；旧队列残留不能重复派发或永久阻止压缩。历史净化若修改待执行工具名称或参数，原计划关闭后重新规划；净化较早已完成历史不妨碍合法余项继续。详见 [消除重复执行权威](ai-functions-design.md#35-消除重复执行权威)。

最近退休的四条用户消息保留原文，更早原文进入摘要源；全部原始用户消息仍在 SQLite 审计记录中。旧版已有摘要但没有原文锚点的 checkpoint，从会话最近消息页补回最多四条未在活动历史中的用户原话。中断后提交新要求会清除旧 deferred_user，避免旧“继续”排到新指令之后。无进展收尾请求也经过容量检查。改变配置的有效窗口后清除旧的自学习容量上限，保留同一模型的 reasoning，不串用旧窗口检测状态。

摘要本身有损，不承诺记住无限文本。最新原文、服务端指标定义/编译状态优先；历史工具证据保留可回读，不能凭摘要生成虚假计算证据。

## 5. 工具证据回读

继续使用工具层现有 8,000 字符结果约束；工具执行回执保存模型实际收到的完整结果。每条成功完成的工具消息带回执引用。整理时长结果可替换为引用和明确标记的片段。

`context.read(operation_id, offset, limit)` 仅查询当前 session 已应用的完成回执；按字符分页（limit ≤ 6,000），返回总长度、下一页、内容哈希及正文。跨会话、未完成、取消后丢弃或不存在的记录统一不可用。工具只回读历史，不重新试算或改写定义；历史内容不能自动成为当前数据有效性的证明。无私有 reasoning/API key 回传。

重复回读仍受原有无进展检测约束；新页属于新证据。原始事件、已保存草稿和试算不被压缩删除。

## 6. 真实上游超限恢复

HTTP 客户端只读取有界错误体，识别明确 context_length_exceeded 等错误码/容量信息；原文不返回用户、不记录密钥。401/403/429、一般参数错误、输出 length 不当作输入超限。

正常请求 → 明确输入超限 → 强制生成更小检查点 → 重试同一模型步骤一次。第二次仍超限、无可退休交互或没有实际收缩则暂停；不能递归压缩或盲重试。成功后利用实际用量修正估算。工具只在成功完整解析模型回复后执行，因此这个恢复不会重复业务工具。

## 7. 前端与恢复兼容

LLM 编辑表单增加可选“上下文窗口（tokens）”，留空自动，列表和帮助文案解释覆盖值。仍需点击编辑/新增才展开。

助手在 `compacting` 阶段显示“正在整理上下文，稍后继续…”，可停止。历史错误消息保留原记录；部署后点击继续可读取旧 checkpoint，经新容量判断和压缩策略继续。没有自动替用户发送消息或保存指标。

## 8. 验收要求

- 原“两组、约 48k 字符”轨迹及“单条 41k reasoning”不再误拒；在小窗口强制整理时也能继续。
- 工具配对和被保留 reasoning 不变；用户口径原文、草稿/预览哈希、无进展状态、全量审计历史保留。
- 摘要成功/失败/超长/取消、没有可压缩历史、超大 system/schema、连续整理、旧会话恢复、模型切换均有离线回归。
- 明确上游超限只重试一次；鉴权/配额/一般 400 不压缩；不重复工具；超长错误体有界且脱敏。
- 回执读取跨会话/未应用拒绝、分页可重建原文、原文未被摘要替换。
- LLM 配置的自动/显式值、旧配置兼容、API 独立性、前端阶段/停止及 320/768/1440 浏览器状态验证。
- 后端 agent/settings 回归、前端测试/类型/构建/设计/i18n 检查；旧故障 checkpoint 只读离线重放。真实供应商验证单独记录，不能把 MockTransport 当成真实调用。

## 9. 验收记录

实现与测试结果：

- 后端六个 agent/settings 测试文件：117 passed（38.45 秒）；包括实际 HttpLLMClient + MockTransport 的完整超限/压缩/重试工具链。保留既有 FastAPI TestClient 弃用警告。
- 前端 Vitest：157 文件、1,275 用例通过；TypeScript、Vite 构建、设计棘轮、i18n、diff 格式检查通过。Vite 保留既有大 chunk 提示。
- 浏览器两套流程共 45 项，最终全部通过（1.2 分钟）。首轮发现一项新测试在请求尚未被接受时切换模拟状态；改为等待 POST 接受响应，随后完成全量重跑。覆盖 320/768/1440 截图、文字对比度、表单自动/显式值与清空恢复、整理期间停止。
- 用户两份故障 checkpoint 只读离线重放：在自动 1M 窗口下估算 26,449 / 31,152 tokens，均无需压缩即可继续；32K 窗口下分别压缩到约 9,585 / 9,914 tokens。后者使用离线摘要夹具，证明容量与状态流转，不认证真实模型摘要质量。
- OpenCode Go / deepseek-v4.1-flash / max 的独立侦察、复核各一轮，主模型绑定经返回元数据确认；Codex 负责实现与验收。复核提出的 deferred_user 顺序问题已修复并新增回归。
- 未修改真实 LLM 配置、用户会话、指标库；没有将原始私有推理写入公开报告或前端。真实模型请求成功率及所有供应商容量识别并未由离线测试认证；未知路由仍需按实际服务额度覆盖配置。
- 路由覆盖检查已执行：agent/settings 新文件仍为本任务之前即存在的未跟踪实现，新测试/设计同样未提交，因此没有将它们提升为要求 Git 可复现的稳定路由事实；覆盖缺口记录在本地验收报告。本次不暂存或提交用户已有工作。
