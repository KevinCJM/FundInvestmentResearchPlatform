# LTCMA 中心：前后端实施设计与验收

- 日期：2026-09-18。
- 上位设计：`pre-investment-dual-path-cma-saa-design-2026-09-16.md` 第 3、6–12、19–21 节。
- 范围：独立长期资本市场假设中心、五类生成方法、版本生命周期、单 CMA SAA 选择与必要的下游冻结契约。
- 不包含：多 CMA SAA、联合 QCQP、TAA 算法、产品实施优化、数据下载、已完成的风险等级／投资目标界面重做。
- 在当前工作区实施；保留已有未提交改动。不提交、推送或合并。

## 1. 业务边界

`资产范围／代理 → LTCMA → 冻结 CmaVersion → Mandate + CMA → SAA`。

LTCMA 回答各大类的预期收益、实现风险及估计不确定性，不选择投资目标、不分配组合权重、不重新定义 C1–C5。创建 LTCMA 不需要 Mandate 或实施产品映射。长期预测期限与历史估计窗口分别记录。

旧 CMA/API 的来源、数值和时点语义保持不变。新中心创建的版本显式标记新契约，不能把历史版本改标签后冒充新结果。产品代理变化会改变依赖该代理的 CMA；与研究代理无关的实施产品变化不应改变新 CMA。

## 2. 前端：先列表，后研究

正式入口：`/pre-investment/ltcma`，名称“LTCMA 中心”，说明“研究长期收益与风险，保存后供 SAA 使用”。

列表先显示名称、方法、资产范围、研究日、预测期限、状态；支持筛选、查看、复制新研究和停止新引用。草稿允许删除，已确认版本退役而不物理删除。不存在自动采用最新版本。

编辑页两个步骤：

1. **研究输入**：名称、研究日、资产范围、预测期限、生成方法及对应少量业务参数。币种来自所选范围／明确确认。历史窗口不是预测期限。
2. **结果与确认**：资产收益／波动表、相关矩阵、数据覆盖与限制；高级详情包含原始参数、模型血缘、均值协方差和执行信息。先预览，确认限制后发布，发布成功提供“用于 SAA”。

主要交互：
- Manual 主要填收益和依据；可明确读取历史风险，人工覆盖后解除旧来源认证。
- Historical 选择 1/2/3/5/10 年、共同起点或自定义窗口；收缩参数放高级设置。
- BL 复用现有绝对／相对观点编辑器，不重写其数值算法；风险、基准与无风险收益须有明确来源，缺失不猜值。
- Bayesian 选择先验版本、证据窗口及等效样本强度；不隐藏先验强度常数，不把“强”解释为置信概率。
- Scenario 保留人工情景，增加历史状态来源；原占用率和应用概率分开，修改需说明理由。

统一使用现有 UI 原语、数值输入、设计令牌与中英文词条。字段有可见标签；负数、空值和未完成输入不自动变零。加载、空态、错误、禁用及过期状态完整。窄屏按区域排版，宽矩阵仅在自身区域横向滚动，不缩小字号。数据和风险提示旁不放吉祥物。

切换资产、日期、模型、输入或知识截止日均使未确认预览失效；用 AbortController 与请求代次忽略旧响应。冻结历史版本可读取，不因打开页面重新取市场数据／训练模型。

## 3. 后端职责与复用

继续使用 `backend/strategic_allocation/`，不另建数值系统或成果数据库。

| 模块 | 职责 |
|---|---|
| `cma_service.py` | 唯一 CMA 预览、发布、读取、列表与退役编排；原服务方法作有测试的薄委托 |
| `cma_evidence.py` | 窗口、共同收益轴、代理来源、数据质量与信息时点；复用已有数据读取及收益内核 |
| `cma_model_contracts.py` | 生成方法及参数的唯一判别联合 |
| `cma_models.py` | 模型输入到统一有效矩；已有 BL/Scenario 委托原内核 |
| `cma_statistical_kernels.py` | Historical、NIW、状态条件统计的固定签名 NJIT 数值内核 |
| `cma_application.py` | 校验冻结结果与血缘，提供下游只读数组；不取新数据或重新拟合 |
| `ArtifactRepository` | 原有 JSON 元数据、校验 NPY、mmap、幂等发布及治理锁 |

必须保留研究来源和产品应用资格的区别。新 CMA 不绑定实施映射；需要交接现有 TAA 的 SAA，在政策请求中单独选择映射并沿用原产品门禁。不能直接删除原 `require_policy_application`。

## 4. 契约与生命周期

现有 `/api/strategic-allocation/cma/preview`、`POST /cma`、`GET /cma/{id}` 保持兼容；新增列表、能力、研究选项、草稿和退役接口。固定路径先于 `/{id}` 注册。

新请求至少声明：契约版本、资产来源与有序轴、研究日、预测期限、币种、收益矩语义、费用／FX 口径、生成方法、数据窗口、来源和人工覆盖。

统一输出：`effective_returns[N]`、`effective_covariance[N,N]`、可选 `posterior_mean_covariance[N,N]`、不确定性状态及半宽、资产轴、基础频率矩、数据／模型血缘、质量、限制和执行记录。

- `mu` 为预期输入，不冒称 CAGR。
- 资产协方差与均值估计协方差分别保存，不能相加后仍称原资产风险。
- 未估计不确定性记录 unknown；旧接口中的数值 0 只表示未施加惩罚，不表示没有不确定性。
- 发布请求核验 preview hash，明确确认并支持幂等重试；预览不创建正式成果。
- 修改已发布版本创建新版本。退役阻止新引用，保留历史 SAA/TAA 的冻结结果。
- 当前可用性独立于历史可读性，不能给旧结果重新打时间戳延长有效期。

## 5. 数据和五类模型

### 5.1 共同证据

优先复用产品大类读取器与 `ReferenceSources`。指数／产品用真实类型，不伪装 ETF。用有来源的代理绑定对齐战略资产轴；不能凭同名大类匹配。

日频统计按已验证的 SSE 开放日、合法相邻净值区间计算；先算合法收益再对齐，缺日不生成跨日的“单日收益”。不填零、不悄悄缩短窗口、不按剩余成分重新归一化。数据可得时点必须不晚于研究日。默认共同样本；共享缓存限本请求，底层输入只读。

当前原始代理读取能力以 CNY/SSE 日频为边界；未实现的币种转换、完整跨市场日历及频率切换明确拒绝，不静默换算法。纯人工同币种前瞻输入沿用旧合法路径。

### 5.2 Historical

共享样本均值与 `ddof=1` 协方差；可选显式对角收缩。独立增量近似下年化均值／资产协方差乘 a；均值标准误乘 a。原风险参考的固定收缩不改名为 Ledoit–Wolf。输出历史统计基线及样本不足／周期不足提示。

### 5.3 Manual、BL 和人工 Scenario

沿用已有计算真相，不重新实现 BL 更新或情景混合。Manual 风险读取属于显式来源操作，自动值与人工覆盖分别留痕。BL 的后验均值协方差不作为资产风险；基准权重不是实施产品权重；无观点恢复 rf+先验溢价。

人工 Scenario 的同期间混合包含 within 与 between 项；没有明确概率则不混合。其单期矩不自动生成多年状态切换或尾部预测。

### 5.4 Bayesian NIW

使用同频先验和同频样本的解析后验；保存 kappa、nu、Psi 和样本截止。资产协方差乘 a，均值后验协方差乘 a²。先验来源、等效样本强度和数据重叠明确核验。先验续更仅用新增证据；跨频率不沿用旧信息量。可信半宽用 t 尺度及相应自由度，不把 t 的尺度当协方差，不统一用 1.96 代替。

### 5.5 Historical Regime

读取冻结 run，不重新执行识别。用同一状态轴切分所有资产的合法收益，记录收益归属规则、未知状态与样本覆盖。默认共同样本时间占用率；基础期条件矩先混合再年化。原样 ML 混合应还原全样本 ML 矩；不把分组重构冒充新增预测。无样本的正概率状态、未来信息或非法状态阻止发布。

## 6. SAA 衔接

SAA 保留政策比较和采纳流程，仅把“编辑长期假设”替换成“选择已确认 LTCMA”。选择器按资产身份、币种、期限、研究日和退役状态解释兼容性；缺失版本保持不可用，不自动换成最新版。

新建／复制 LTCMA 从 SAA 跳转时只携带可验证引用；返回时加载精确 ID。Mandate 不反向决定模型参数。SAA 继续执行实际目标、现金及风险校验。本次不加入多 CMA 或改变原有限候选算法。

## 7. 数值、内存和算子审查

- 所有新增数值计算默认固定签名 NJIT；启动按 PID 预热，未预热失败关闭，不允许请求临时编译或 Python 回退。
- 样本统计、年化、模型更新、结果诊断各有独立接口和测试；不把整套投资流程变成黑盒算子。
- NIW 解析更新共享散点统计，BL/Scenario 复用唯一内核；不为每个模型复制整份收益面板。
- 只读 ndarray/mmap 与基本切片共享；非连续样本用索引进入内核。必要解码、对齐和持久化复制单独记录。
- 验收包括 shares_memory、只读和非连续输入、空样本、NaN/Inf、PSD／奇异矩阵、确定性、实际内核调用与签名不增长。

四问：1）新增页面、契约和计算属于本次 LTCMA 需求；2）来源、生命周期、SAA 选择及冻结消费不改会阻塞独立使用；3）原算法、存储、RiskScale/Mandate 最大限度复用，只抽取必要编排；4）不做无关重构、旧 Bug 清理或数据下载，替代的编辑入口与无真实调用代码同步清理，兼容 API 保留测试。
