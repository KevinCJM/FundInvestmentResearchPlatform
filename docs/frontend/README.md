### 1.1 品牌风格与信息优先级

- 品牌气质为**专业、克制、亲切的现代金融科技风（Modern FinTech）**。用清晰的信息层级、稳定的交互和可追溯数据体现专业，用适量的品牌插画体现亲和力。
- 首页以浅色背景、深色标题、品牌蓝强调和静态 3D 场景表达品牌；工作台以数据阅读和任务操作为中心，不复制首页的大标题、大插画和宣传式信息布局。
- 柔和光照、磨砂材质和少量层次服务于内容，不要求全站采用 3D 或毛玻璃。具体边界见第 7.2、10.1 和 15.5 节。
- 参考图片中的颜色、字号、栏宽和阴影是视觉参考，不是新增令牌的依据。不得因风格说明另引入一套相近蓝色、字体、圆角或动画依赖。

## 3. 令牌层（唯一真相源）

所有跨页面共享的值以 `frontend/tailwind.config.js` 为真相源。页面内不得新增同义字面量；首页既有 CSS 变量的有限例外和同步要求见 3.1。

### 3.1 颜色

`accent` 是围绕品牌蓝 `#1662f5` 展开的完整色阶（50-950），定义在 `frontend/tailwind.config.js`。

**首页既有变量例外**：`homepage.css` 目前仍手写 `--home-blue`、`--home-blue-hover`、`--home-blue-soft`，分别镜像 `accent.600`、`accent.700`、`accent.100`，尚未自动派生。任意一端改色必须在同一变更同步另一端，并运行第 14 节的一致性命令；不允许新增第二套品牌色。`--home-blue-on-dark` 是深色品牌面板的对比度专用色，不能替代主操作蓝，调整时另做实际表面对比度验证。

| 语义 | 令牌 | 用途 |
| --- | --- | --- |
| 主操作 | `bg-accent-600` / `hover:bg-accent-700` | 工作台提交、保存、运行、发布；与首页 `.home-button-blue` 同色，首页深色入口例外见 7.1 |
| 链接与选中 | `text-accent-700` / `bg-accent-50` | 链接、选中态、当前步骤、图标底 |
| 成功 | `emerald-*` | 已实现、校验通过、运行成功 |
| 警告 | `amber-*` | 部分实现、口径提醒、待确认 |
| 危险 | `rose-*` | 删除、冲销、强制覆盖、请求失败 |
| 中性 | `slate-*` | 唯一中性色阶 |

规则：

1. **全站唯一强调色是 `accent`。** 阶段身份靠色调（下方 3.1.1）与序号表达，不靠换强调色。
2. **`gray-*` 禁用。** 中性色只用 `slate-*`。同一文件混用两套色阶是回归项（`neutral-ramp-mix`）。
3. **`indigo` / `violet` / `purple` / `fuchsia` / `sky` / `cyan` / `teal` / `blue` 一律不得直接出现在类名里。** 装饰性蓝紫是 skill 点名的 AI 默认色，全部走 `accent-*`。例外为 3.1.1 的阶段身份色和第 10 条有明确分类语义的图表色。
4. **实心按钮底色只允许 5 种语义色相**：`accent`（主操作）、`slate`（中性）、`emerald`（成功）、`amber`（警告）、`rose`（危险）。金融界面需要成功与警告两种状态底色，压到三种会把状态挤回纯文字。
5. **焦点环全站一种**：`focus-visible:ring-2 focus-visible:ring-accent-500`。未被 Tailwind 覆盖的元素由 `index.css` 的全局 `:focus-visible` 兜底。
6. **页面级背景只能声明一处**：`App.tsx` 根 div 的 `bg-slate-100`。
7. **次要文字分浅底、深底两套令牌，不能只有一套。**
   - **浅色表面（白 / `slate-50` / `slate-100` / `accent-50`）用 `text-slate-600`，不用 `slate-500`。** `slate-500` 在纯白上是 4.76:1 过线，但落在 `slate-50` / `slate-100` / `accent-50` 上只有 4.3-4.5，而调用处根本看不出自己压在哪层底上。一个只在三种底色中的一种上安全的令牌不是令牌。`slate-600` 在三种底色上分别是 7.58 / 7.24 / 7.0。
   - **深色表面（`slate-800` 及更深、深色渐变横幅）用 `text-slate-200`。** 在 `slate-900` 上 14.48:1，在 `slate-950` 上 16.36:1，在 `accent-950` 上 12.13:1。
   - 只写"次要文字一律 slate-600"会把横幅里的说明文字压到 1.8-2.4:1。这条正是 2026-09-12 复核查出的回归：换色脚本按行判断深浅底，而底色写在父元素那一行。**改次要文字颜色前先确认所在表面**，判断不了就跑 `frontend/e2e/contrast.spec.ts`。
8. **文字不叠透明度，深底浅底都一样。** 深色文字：`text-amber-700/70` 压在 `bg-amber-50/60` 上只有 2.89:1，两个透明度分开写，谁也算不出结果。浅色文字同样不行：`text-white/90` 压在 `accent-600` 上 4.45:1、压在 `orange-700` 上 4.48:1，都差一点到 4.5；`bg-white/10` 还会把底色提亮，`text-white/75` 压上去只剩 3.76:1。要弱化层级用字号和字重，不要用透明度。
9. **占位符按正文门槛并随表面选择。** `index.css` 既有全局 `slate-500` 仅适用于不透明纯白输入表面；不能把该兜底当作所有输入框的安全默认值。新增或修改输入框时，浅色表面统一显式使用 `placeholder:text-slate-600`，深色表面使用 `placeholder:text-slate-200`，均保持 `placeholder:opacity-100`；透明表面须按实际合成背景验证 ≥4.5:1。占位符是输入格式提示，不代替 label。Tailwind preflight 的选择器为 `input::placeholder, textarea::placeholder`，覆盖时须保证生效。此处规定后续修改要求，不声称全站输入框已完成迁移。
10. **分类色不是界面色。** 图表、堆叠条、图例里的颜色承载"是哪一类"，必须单独定义（如 `app/portfolioSolutionDemoData.ts` 的 `ASSET_CLASS_COLORS`），不得跟着强调色一起改，同一组里也不得有两类同色。另外，**分段边界不能只靠色差**：堆叠条要有分隔线，图例要有色块。

### 3.1.1 阶段色调

九个阶段的色调只在 `app/processRegistry.ts` 的 `TONE_CLASSES` 定义一次，首页 `homepage/catalog.ts` 从这里读取，两处不再各写一份。

| 阶段 | tone | 类名 |
| --- | --- | --- |
| 产品研究 / 组合中心 / 方案展示 / 设置 | `blue` | `bg-accent-50` `text-accent-700` |
| 投前决策 / 基金会计 | `teal` | `bg-teal-50` `text-teal-700` |
| 投中执行 | `orange` | `bg-orange-50` `text-orange-700` |
| 投后管理 | `purple` | `bg-violet-50` `text-violet-700` |
| 反馈与迭代 | `pink` | `bg-pink-50` `text-pink-700` |

1. **色调只标身份，不标交互。** 它只能出现在图标底、区块眉标和阶段工作台横幅上。不得将阶段色调用于链接、按钮或焦点环；这些交互按 3.1 的语义令牌与明确的首页例外处理。
2. **徽章保持中性 `bg-slate-100`。** 原来九个阶段各有一种徽章与主按钮颜色，颜色因此不再表示「这是主操作」。
3. **不得把阶段色调选成 `emerald` / `amber` / `rose`。** 那会让「投后管理」的标签和「运行成功」的状态长得一样。这正是改造前的实际状态。
4. 文字色一律取 700 档：五种色调在白底上都不低于 4.7:1。

### 3.2 字体

```
font-sans: Avenir Next, -apple-system, BlinkMacSystemFont, Segoe UI,
           PingFang SC, Microsoft YaHei, Noto Sans SC, sans-serif
```

1. **不自托管 webfont。** 一份 CJK 字体 3-8MB，直接毁掉 LCP 预算。中文用系统字体栈是本项目的正确解，不是妥协。
2. **不用衬线体做显示字体。** 投研工作台没有编辑/奢侈品语境，标题用同一 sans 的更重字重。
3. **字重只用 400 / 500 / 600 / 700。** 系统 CJK 字体不是可变字体，`450 / 550 / 650 / 710 / 750 / 760` 会被浏览器吸附到相邻档位，写了也不生效，只会让代码说假话。
4. **强调词用同族的 italic 或 bold，不混排第二种字族。**

### 3.3 字号

| 用途 | 类 | 尺寸 |
| --- | --- | --- |
| 工作台页面标题 | `text-2xl sm:text-3xl font-bold` | 24 / 30px |
| 区块标题 | `text-lg font-semibold` | 18px |
| 正文与表格 | `text-sm` | 14px |
| 辅助说明、表头、徽标 | `text-xs` | 12px |

首页主标题按第 7.1 节响应式排版，不将参考图的 48–56px 固定值或 1.2 行高外推到工作台。

**12px 是硬下限。** 任何 `text-[9px]` / `[10px]` / `[11px]` 都是回归项（`tiny-font`）。中文在 12px 以下没有可靠的屏显字形，Windows 上尤其糊。首页作用域 CSS 同样受此约束（`homepage-subpixel-font`），`5px / 6px / 7.3px / 8px / 9px / 10px / 10.5px` 全部要抬到 ≥ 12px。

### 3.4 圆角与阴影

- **卡片一律 `rounded-xl`（12px）。** 改造前 `rounded-2xl` / `xl` / `lg` / `md` / `full` 五档混用，现已收敛到一档。
- 交互控件 `rounded-lg`，胶囊徽标 `rounded-full`。这是文档化的三档规则，不是自由混用。
- **阴影只用 `shadow-sm`。** 悬浮层（下拉、弹窗）用 `shadow-xl`。中间档不用。不用纯黑投影。

### 3.5 共用原语

`frontend/src/components/ui.tsx`。新代码优先用这里的组件，不要再复制一串 className。

| 组件 | 用途 | 约束 |
| --- | --- | --- |
| `Card` | 卡片外壳 | 圆角、描边、底色不接受调用方覆盖 |
| `Button` | 按钮 | `tone` 只有 `primary` / `secondary` / `danger`；`min-h-10` 是触控下限 |
| `Badge` | 状态徽章 | `tone` 只有 `neutral` / `success` / `warning` / `danger`；**颜色只表示状态，分类靠文字** |
| `SectionHeader` | 区块标题 | 眉标不加 `uppercase` |
| `EmptyState` | 空态 | 必须同时说明「为什么空」和「下一步做什么」；默认带吉祥物 |

1. **只写「暂无数据」不算空态。** 空态要回答用户下一步该做什么。
2. **`EmptyState` 默认渲染吉祥物，一屏只能有一个。** 页面的主空态用它；局部面板的空态传 `mascot={false}` 或直接用纯文字。禁区见第 15.2 节，`mascot-in-forbidden-zone` 会连同 `EmptyState` 的间接引用一起拦截。
3. 旧页面顺手替换，不做大爆炸重写。334 处卡片外壳靠复制粘贴维持一致性，必然漂移。

## 4. 硬规则与棘轮阈值

`npm run design:check --prefix frontend` 的每条规则都是机械计数。语义是棘轮：`budget` 是基线实测值，只允许下调；`current > budget` 即退出码 1。`target` 是本准则要求的终值。

| 规则 | 含义 | 首测 | 现值 = budget | target |
| --- | --- | --- | --- | --- |
| `tiny-font` | 换算后小于 12px 的字号 | 299 | **0** | 0 |
| `low-contrast-text` | 浅色底上的 `text-slate/gray-300/400` | 224 | **0** | 0 |
| `neutral-ramp-mix` | 同时含 slate 与 gray 的文件数 | 5 | **0** | 0 |
| `card-radius-variants` | 卡片外壳圆角档数 | 5 | **1** | 1 |
| `focus-ring-hues` | 焦点环色相数 | 10 | **1** | 1 |
| `solid-button-hues` | 实心按钮底色相数 | 13 | **5** | 5 |
| `page-bg-declarations` | 页面级背景声明处数 | 2 | **1** | 1 |
| `english-em-dash` | 英文界面文案里的破折号 | 56 | **0** | 0 |
| `uppercase-on-cjk` | 作用在中文上的 `uppercase` 行数 | 48 | **11** | 0 |
| `homepage-subpixel-font` | 首页 CSS 中 < 12px 的字号数 | 27 | **0** | 0 |
| `homepage-nonstandard-weight` | 首页 CSS 中非 400/500/600/700 的字重数 | 13 | **0** | 0 |
| `unscoped-tables` | 没有 `scope` 的 `<th>` 个数 | 439 | **0** | 0 |
| `bare-chart-hex` | 散落的十六进制色字面量种数 | 57 | 57 | 0 |
| `homepage-accent-variants` | 首页饱和蓝变体数（令牌 3 档） | 3 | 3 | 3 |
| `mascot-in-forbidden-zone` | 吉祥物出现在禁区文件中（含 `EmptyState` 间接引用） | 0 | 0 | 0 |
| `same-element-contrast` | 同一元素/同一三元分支内底色与文字色不足 4.5:1 | 37 | **0** | 0 |
| `duplicate-category-color` | 同一数组里重复的分类色 | 3 | **0** | 0 |

以下预算保留明确边界，`target` 与预算的含义不能混淆：

- `solid-button-hues` **5**：见 3.1 第 4 条。
- `uppercase-on-cjk` 预算 **11**、目标 **0**：剩下的是英文眉标（`Data governance`、`Immutable run` 等），只因同一行上另有中文才被计入，属规则的行级近似。

**静态检查够不到的部分由浏览器量。** 祖先的底色常写在三元里（`selected ? 'bg-accent-700' : 'bg-accent-50'`），
纯文本扫描无法判定子元素到底压在哪一层上；渐变底色写在 `background-image` 上，连 `backgroundColor` 都读不到。
`frontend/e2e/helpers/contrast.ts` 在渲染结果上估算纯色、渐变色标、文本与祖先分组透明度的对比度，并检查可见的表单值与占位符。
`contrast.spec.ts` 从 `processRegistry` 派生阶段与节点路由，严格核对最终路径，使用固定的 API 离线错误态检查外壳。
`indicator-studio.spec.ts` 使用已加载的固定夹具覆盖指标库、编辑和预览切换；历史情景工作台也验证模板载入后的文字。
可见的 `aria-hidden` 信息照常检查；失效控件、完全透明或未显示的文字不计。颜色过渡结束后再断言稳定状态。
算法自检包含可见 `aria-hidden`、半透明深色组、已填写输入框和占位符，不能用“用例通过”代替完整无障碍验收。
图片、视频、滤镜、遮挡和未覆盖的交互状态仍需人工验证。

阈值只降不升。需要上调时说明理由并同步本表，不得静默改脚本。

## 5. 颜色与对比度

WCAG AA：正文 ≥ 4.5:1，大号文字（≥ 18.66px 且加粗，或 ≥ 24px）≥ 3:1。本项目背景有 `#ffffff` / `slate-50` / `slate-100` 三层，实测：

| token | 白底 | slate-50 | slate-100 |
| --- | --- | --- | --- |
| `slate-500` `#64748b` | 4.76 ✅ | 4.55 ✅ | **4.34 ❌** |
| `slate-400` `#94a3b8` | **2.56 ❌** | 2.45 ❌ | 2.33 ❌ |
| `slate-300` `#cbd5e1` | **1.48 ❌** | 1.42 ❌ | 1.35 ❌ |
| `slate-600` `#475569` | 7.58 ✅ | 7.24 ✅ | 6.92 ✅ |

规则：

1. **`slate-300` / `slate-400` 只能用于浅色底上的边框与分隔线。** 压在深色面板上时它们是正确的文字色，那是另一回事。
2. **文字色必须与表面一起选择。** 浅底次要文字用 `slate-600`，深底用 `slate-200`；不能全局统一压深。占位符遵守相同的表面规则。
3. 辅助文字的字号下限是 `text-xs`；颜色按浅底 `slate-600`、深底 `slate-200` 选择。改造前有 120 处「≤ 11px + slate-300/400/500」的叠加，是最直接的可读性缺陷，现已清零。
4. **按钮文字必须与按钮底色对比达标。** 透明按钮压在图片或深色面板上时必须带描边或遮罩。
5. **每个按钮的有效点击区 ≥ 40px 高**（`min-h-10`）。当前 `min-h-8`（12 处）不合格。

## 6. 工作台构图

1. **任务页优先展示当前任务。** `StageLayout` 仅在阶段总览显示阶段大标题、眉标和描述；子页面保留紧凑面包屑、当前上下文和必要的配置旅程。因子参考证据默认收起，业务口径与错误状态仍由工作区直接提示。
2. **阶段内节点导航响应式展示。** ≥1280px 使用常驻左侧栏；窄屏用展开按钮，Escape 关闭并把焦点交回按钮，切换路由后收起。历史情景全幅画布保留独立布局。指标与历史情景工作台在 <1280px 通过区域页签切换，避免平板双栏内再挤三列输入。**已实施**：#12 已将阶段侧栏、窄屏展开及区域页签合入 Dev，见第 13 节；后续修改仍需浏览器验收。
3. **一个页面一个滚动容器。** 不做嵌套滚动区域。
4. **容器宽度 `max-w-[1600px]`**，画布类全幅页面除外。首页用 1280/1440，两者不互相套用。
5. **分组优先用 `divide-y` 与留白。** 只有当层级真的需要抬升时才用卡片。`VISUAL_DENSITY: 7` 下卡片套卡片是禁止的。
6. **表格**：数字列 `text-right tabular-nums`，`<thead>` 内表头 `scope="col"`、`<tbody>` 内行首表头 `scope="row"`，`<caption>` 或 `aria-label` 必填；只在行间用一条 `border-b`，不要同时加 `border-t`。`index.css` 已对 `td` / `th` 全局开启 `tabular-nums`。
7. **中文标签不用 `uppercase`。** 对中文是空操作，只留下被拉开的字距。eyebrow 类微标签在工作台每页最多 1 个。
8. **超过 5 项的列表换组件**，不要加长 `<ul>`：两列分组、卡片栅格、标签页、横向 scroll-snap 任选。
9. **响应式坍缩逐区块显式声明**，不依赖「Tailwind 会处理」。

## 7. 首页构图（仅 `/`）

### 7.1 品牌区布局与入口

1. **桌面可用左文右图，内容优先。** 主标题、说明与主要入口保持明确的阅读顺序；插画不遮挡文字、焦点或点击区域。40%–50% 的文字区比例仅作参考，不设为所有屏幕的固定约束。
2. **小屏重排，不整体缩小。** 手机优先显示内容和主要入口，再安排视觉区域；可缩小、裁切或隐藏纯装饰部分。中英文分别检查换行，在 320/768/1440px 及导航断点两侧验证无溢出、重叠或不可达的操作。
3. **标题尺度随内容和视口变化。** 大标题只用于首页主视觉区域，中文行高必须容纳实际字形，不能强制沿用英文 1.2 行高。英文眉标可使用适量字距，全首页最多 2 个；不得将全大写或宽字距套在中文标签上。
4. **深色入口是首页例外。** 首页主视觉及导览可复用既有 `.home-button-primary` 深藏青按钮；品牌蓝入口复用 `.home-button-blue`。两者沿用已有样式与对比度要求，不新建近似颜色。工作台的提交、保存、运行、发布仍使用 `accent`；箭头只表示前进或进入，播放图标只用于导览或媒体类操作，不给所有按钮强加装饰图标。
5. **概览数据条作为独立信息组。** 可用细分隔线组织数量与单位，不为了贴合参考图把更多内容塞入 hero。模块数、阶段数从实际目录或配置派生，不照抄参考图的“5 个”“4 类”；无法核实的统计不展示为事实。动态统计需有来源和更新时间，装饰性曲线不能充当真实收益证据。
6. **层次来自留白与柔和光照。** 首页品牌背景可有轻微冷色环境光，不能压低文字对比度或覆盖操作。真实控件继续使用第 3.4 节的圆角和阴影档位，不新增逐页面的强投影或悬浮动效。

### 7.2 毛玻璃与视觉降级

1. **毛玻璃是可选效果，不是全站默认组件。** 仅用于首页品牌视觉区域；业务表格、表单、指标结果和风险/PIT 提示的内容表面保持不透明、稳定可读。模态遮罩既有的背景模糊不代表内容面板也应透明化。
2. **先区分图片与真实控件。** 当前 hero 主体使用 WebP 场景图；图片内的玻璃质感不需要再叠加 `backdrop-filter`。真实控件不能被合成图片替代，装饰图表遵守第 10.1 节。
3. **模糊与透明度按实际背景验收。** 不直接将 `blur(12px)`、白色透明度 `0.6` 或示例投影写成全站标准。承载文字的面板须在背景变化、响应式裁切和效果关闭后仍达到第 5 节对比度门槛；不能给整个内容组叠加透明度来获得玻璃效果。
4. **先有不透明回退，再渐进增强。** 未支持或关闭 `backdrop-filter` 时使用可读的不透明底色与边框；增强效果的背景规则与特性检测配套，不能只移除模糊却保留不安全的透明底色。效果降级不能隐藏文字、操作或状态。
5. **控制渲染成本。** 不做全屏或多层叠加模糊，不动画模糊半径；保留第 9 节性能与减少动态效果要求。使用该效果的变更须附正常及关闭效果后的浏览器证据，核对实际背景、焦点和操作；现有静态对比度检查不能认证滤镜效果。

## 8. 交互状态

每个数据区块必须四态齐备。当前 `Skeleton` 0 处、`animate-pulse` 7 处、`aria-live` 仅 21 个文件覆盖，缺口明确。

1. **加载态**：骨架屏，形状与最终布局一致。不用居中转圈。
2. **空态**：说明为什么空，并给出填充它的入口。不伪造记录。
3. **错误态**：表单内联在字段下方；请求失败就近展示并提供重试。不要只 toast 了就算完。
4. **禁用态**：说明为什么禁用。当前 1021 处 `disabled` 中大部分没有解释。
5. **按下反馈**：`active:translate-y-px`。不用缩放。
6. **表单**：label 在输入框上方，帮助文字可选但要在 DOM 里，错误文字在下方。**禁止用 placeholder 当 label。**

## 9. 可达性与性能

1. **焦点可见**：Tailwind 控件统一 `focus-visible:ring-2 focus-visible:ring-accent-500`，不得 `outline: none` 而不补替代。既有 `index.css` 使用 `accent.DEFAULT`（600 档）绘制全局 outline，首页另有作用域 outline；这是兜底样式的现状，不是 `ring-accent-500` 的别名。修改焦点样式时检查实际可见效果。
2. **表格语义**：`<th scope="col">` 必填。`unscoped-tables` 逐个 `<th>` 计数（按文件计数会让同一张表里漏标的表头永远查不出来），当前 0 处。
3. **`prefers-reduced-motion`**：`MOTION_INTENSITY` 虽为 2，所有 `transition` 与 `transform` 仍需在 reduce 下退化为静态。
4. **深色模式**：`darkMode: 'class'` 已在配置中声明。**必须先完成第 3 节令牌收敛再实现**，否则 9672 处 `className` 要改两遍。这是 P2，不是 P0。
5. **只动画 `transform` 与 `opacity`。** 不动画 `width` / `height` / `top` / `left`。
6. **禁止 `window.addEventListener('scroll')`。** 用 IntersectionObserver 或 CSS 滚动驱动动画。
7. **z-index 只用于系统层**（sticky 顶栏、弹窗、遮罩），在常量里集中声明，不散写 `z-50`。
8. LCP < 2.5s、INP < 200ms、CLS < 0.1。首屏图片显式声明尺寸。

## 10. 图表（ECharts）

1. **单一主题**。用一次 `echarts.registerTheme` 定义调色板、字号、网格线、tooltip，页面不再传 `color: [...]`。当前 57 种散落的十六进制字面量收敛到这里。
2. 单序列强调、轴线和网格优先从 `accent` 与 slate 派生。多序列与资产分类使用有明确语义的独立分类色，遵守 3.1 第 10 条，不因品牌统一而合并不同类别的颜色。不使用高饱和霓虹色。
3. **涨跌色不靠红绿单独承载语义**，必须同时有符号或箭头（色盲可读）。
4. 坐标轴与图例字号跟随 3.3 的 12px 下限。
5. **不用 div 拼柱状图。** `PrototypeWorkspace` 的 `SampleChart` 当前用 `<div>` 高度模拟柱图，ECharts 已是既有依赖，直接用它；34 条原型路由共享这个组件，改一处即可。

### 10.1 装饰图表与业务图表的边界

- 首页品牌插画中的纯装饰折线、饼图或 K 线可省略刻度和复杂网格，以品牌蓝为主；不得呈现为实际产品收益、实时行情或已完成的研究结果。纯装饰图不承载唯一信息，使用空替代文本并避免进入交互焦点。
- 任何承载真实数据的图表，即使出现在首页，也按业务图表处理：提供理解数值所需的单位、时间范围、系列名称、图例和来源/口径；重要数据能通过文本、表格或键盘可达的详情读取，不能只依赖悬浮提示。
- 迷你趋势图可以省略视觉刻度，但相邻文字或可访问详情必须补齐必要信息，不能借“极简”隐藏比例、缺失状态或比较依据。多资产、多类别图表继续保留可区分的分类色及非颜色线索。
- 功能演示图若使用示例数据，必须在可见位置标明示例，不能与实际计算结果混排而不作区分。

## 15. 吉祥物（卡通牛）使用规范

小牛是本项目的品牌形象，卫衣上的柱状图标与 `brand.svg` 同源。源文件在仓库根目录 `images/`（已 git 跟踪）：`0001.png` 是首页 hero 场景、`0002.png` 是地球场景，两者已出货为 `hero-bull-*.webp` / `data-globe-*.webp`；`0003`-`0011.png` 是 9 个 1254×1254 透明背景姿势。

### 15.1 姿势与状态的一对一契约

形象出现必须承载一个状态。**一个状态一个姿势，姿势不得复用到第二个语义上**，否则它退化成随机装饰。语义重叠的姿势不出货。

资产宽度是显示宽度的 2 倍，用于高密度屏，因此不需要 `srcset`。

| `state` | 姿势 | 显示 | 资产文件 | 说明 |
| --- | --- | --- | --- | --- |
| `empty` | `0010` 站立侧指 | 120px | `mascot-empty-240.webp` 8.7K | 手指向创建/导入入口 |
| `noresult` | `0011` 抓头疑惑 | 120px | `mascot-noresult-240.webp` 7.7K | 唯一带「?」的姿势 |
| `error` | `0003` 正面垂手 | 120px | `mascot-error-240.webp` 8.4K | 读取/计算失败、404、错误边界 |

| `working` | `0006` 前伸行走 | 80px | `mascot-working-160.webp` 4.7K | 数据加载中；与骨架屏或加载指示并用，不替代它们 |

### 15.2 禁止出现的位置

这一节优先于任何视觉偏好。`AGENTS.md` 规定平台不输出投资建议、不提供下单能力；卡通形象紧邻收益数字会把研究材料读成营销材料，紧邻核算差错会直接损失可信度。

**不得出现在：**

1. 任何数值旁边：净值、收益率、回撤、权重、绩效、归因、风险指标。
2. 风险提示、PIT 口径警告（`PitBadge` / `PitDecisionNotice`）、因果性审计告警。
3. 基金会计的对账差异、关账错误、凭证错误、双账勾稽差额。
4. 表格内部、图表内部、图表 tooltip、画布节点。图表**尚未出图**时的整面板级占位区（读取中 / 读取失败 / 无数据）不算图表内部，按下述例外处理；图一旦画出来，这块区域就不再有吉祥物。
5. 交易计划、前置检查、订单分配相关的任何界面。
6. `VISUAL_DENSITY: 7` 工作区中承载业务数据的正文区域。无数据的页面主空态和明确标记为未实现的原型横幅按下述例外处理；例外不能覆盖第 1–5 条禁区。

**允许出现在：** 无业务数据的空态、无结果、首次进入、成功确认、404 / 错误边界、首页品牌区块，以及 `prototypePage` 的 `StaticDemoBanner`（明确标注为未实现原型的页面）。工作台主空态是第 6 条的明确例外，如 `FactorResearchCenter` 尚未运行检验时；局部面板仍按 3.5 使用纯文字。第 15.3 节按文件名限制的禁区保持有效，命中这些文件的空态须设置 `mascot={false}`；静态检查不能替代位置和内容语义审查。

共同点是：**这些位置都没有数据。** 有数据的地方交给数据。

### 15.3 技术契约

1. **资产管线沿用既有约定**：`images/NNNN.png`（源，已 git 跟踪）→ `frontend/public/homepage/images/mascot-<state>-<资产宽度>.webp`。**禁止在代码里引用 `images/*.png` 原图**，单个 1MB。新增姿势时复跑：

```sh
for map in "0010:empty:240" "0011:noresult:240" "0003:error:240" "0005:welcome:240" "0006:working:160" "0008:success:96"; do
  IFS=: read pose state w <<< "$map"
  magick "images/$pose.png" -resize ${w}x${w} -quality 82 -define webp:alpha-quality=90 \
    "frontend/public/homepage/images/mascot-$state-$w.webp"
done
```
2. **体积预算**：6 个资产实测合计 40.8KB。每个状态只出一档宽度，不做 `srcset`。
3. **装饰语义**：`alt=""` + `aria-hidden="true"`。状态含义由旁边的文字承载，屏幕阅读器不需要「一头牛在欢呼」。
4. **不做动画**。`MOTION_INTENSITY: 2` 下不做 CSS 弹跳、不做 Lottie、不做逐帧序列。
5. **单页最多 1 个实例**。同一页两处出现即为装饰滥用。据此，一个面板的读取中/失败/空态几个分支必须互斥地占用同一个位置；行内一句话的局部状态（如指标表上方的「正在批量计算…」、叠加指标的失败提示）保持纯文字，不配图。
6. **显示尺寸上限**：空态 120px 宽，内联确认 48px 宽（资产各为 2 倍）。不做全屏、不做背景水印。
7. **首屏之外的实例必须 `loading="lazy"`**，并显式声明 `width` / `height` 以保住 CLS。
8. **单一组件承载**，不逐页复制 `<img>`：`components/Mascot.tsx`，props 仅 `state` 与可选 `className`，由 15.1 的表驱动。姿势与状态的映射只存在一处。禁区由 `mascot-in-forbidden-zone` 规则按文件名机械拦截（`Accounting|Financial|Ledger|Booking|Reconcil|Statement|Trade|Risk|Pit|Performance|Attribution|Valuation|Allocation|Portfolio|Dashboard`）。

### 15.4 首页的具体机会

第 7.3 节第 8 条指出「核心能力」4 张卡全白、只有文字，违反 Bento Background Diversity。这是首页唯一适合加形象的位置：给其中 1 格换成带姿势图的图文格，既修掉那条不通过项，又不增加新区块。**hero 已有场景图，不要再叠一个姿势图**；第 7.3 节第 6 条要删的是 hero 的文字角注，不是 hero 的形象。

### 15.5 3D 资产材质与一致性

1. 新增或替换的首页场景与吉祥物延续现有小牛的角色比例、面部特征、服饰和品牌图形；姿势含义继续由 15.1 的状态契约决定，不能为视觉变化随机换角色或动作。
2. 材质以粘土或磨砂质感为主，使用柔和漫反射与低强度高光；避免镜面金属、强烈塑料反光和高饱和霓虹效果。保持同一画面内光源方向、阴影软硬和透视关系一致，新增资产与相邻既有资产并排审查。
3. 为文字和入口保留干净背景，装饰阴影不落入文字阅读区。用清晰轮廓和恰当构图表达品质，不引入实时 3D、自动旋转或弹跳效果。首页场景沿用响应式图片管线及第 9 节性能要求；状态姿势的显示尺寸、加载方式和体积遵守 15.3，不能把姿势图的尺寸上限套在首页场景上。
4. 材质与风格一致性属于视觉验收：记录桌面与移动端实际显示效果，检查裁切后是否仍保留角色语义、文字是否被遮挡，以及无图时相邻说明能否完整表达状态。新增规范不意味着已有所有资产已通过这些检查。


### 15.6 AI 助手悬浮入口与对话窗

按 2026-09-19 的用户反馈，指标助手使用举手小牛作为常驻入口，这是 15.1 首次会话限制的明确例外。复用 `Mascot` 的 welcome WebP，收起时小屏显示 64px、桌面 80px；按钮带「AI 助手」文字和可访问名称，图片失效时仍能打开对话。打开后外部入口隐藏，小牛以 32px 放在标题栏，保持同屏只有一个实例；消息、数值和错误区保持文字表达，不扩大其他禁区。

对话窗为右下角非模态浮窗，默认宽 480px，≥1024px 可展开为 720px；小屏保留至少 12px 边距，平板/桌面至少 20px。高度上限 760px，并给动态视口和顶部导航留出空间；页面保持可操作，不使用遮罩或焦点锁。通过 Portal 挂载到 body，浮层常量为 70，高于导航层 60。标题栏和输入区不参与消息滚动；关闭图标始终可见，Esc 可收起，关闭不等于停止任务。重开保留未发送输入、对话、公式展开和阅读位置；普通关闭焦点返回入口，查看试算结果则交给工作台结果标题。

恢复会话时显示加载状态，保留输入并禁用发送、快捷键发送、重试和继续；读取失败保留原会话引用并提供重新连接，不能误建新会话。消息重试保留原消息 ID、正文、页面快照及续接对象（包括原本没有续接对象），仅使用最新会话版本做并发校验；版本冲突会重新读取会话，仍由用户点击重试。已接受运行的重试不停止该运行；已接受的编辑恢复后可重放原请求并退出编辑，不要求被替换的旧消息仍存在。

“停止并发送”的待发消息在恢复会话和提交期间持续占用发送状态，不能被后来输入抢先发送。等待恢复时仍可取消排队；取消后迟到的读取不得发送原消息。读取或提交失败保留原消息及重试入口，不能留下无法取消或重试的排队气泡；未发送的新输入保持原文。

停止和研究口径变更请求的迟到失败，只能反馈给仍在运行的原会话、原轮次；已结束、被新轮替代或已卸载后，不覆盖当前成功状态。关闭浮窗不使原请求失效，仍属于当前运行的成功和失败继续正常处理。

发送或编辑请求回包前，若重开浮窗已从服务端恢复同一消息的运行回执，迟到的旧回包不能倒退运行状态，迟到的网络错误也不能回滚已确认的新文本或提示重发。会话中已恢复的记忆等字段同时保留；尚无服务端接受证据的失败仍保留原有重试方式。

如果重开时仍只读到上一轮，新消息回执到达后须同时切换运行和该消息的冻结研究口径，不能把上一轮口径用于新运行的失效判断。普通发送、编辑、排队及失败重试遵守同一规则。仅关闭重开不停止新请求；发送后确实改变产品、周期或日期等条件时，仍停止不再匹配的运行。

试算引起的程序回填仅能依据本轮的试算回执豁免口径变化；上一轮仍在客户端缓存的试算不能为新运行建立豁免。即使用户改回旧试算的相同周期或产品，也要相对新消息的冻结条件判断并停止失配运行。本轮有效试算的自动回填和显式历史结果查看保留原有行为。

会话元数据与当前运行绑定保存在单一 ConversationCore 中，对外的 active_run 与执行屏障按绑定派生。运行、独立冻结口径和合法采纳条件一起更新，不依靠多组 ref/state 互相回填。发送回执、完整恢复快照、运行回包及阶段事件使用明确的输入类型；阶段事件只改变状态提示，不重放旧回复或成果。发送回执、完整恢复快照、实时阶段事件、轮询、停止及口径失效回包共用运行接纳入口。切换运行必须同时提供其冻结口径，并校验会话、页面与运行接受顺序；同轮版本不得倒退，处理中状态不能覆盖终态或把正在停止改回运行中。完整会话与运行的版本分别判断：同版本会话仍可补齐记忆字段，但旧运行快照不能恢复已解除的执行屏障或覆盖新草稿。

只有读取会话本身明确返回404，才清除其本地引用和当前状态。已恢复会话后，事件或运行资源暂时返回404应显示断线并允许重连，保留会话、对话和未发送输入，不误建另一会话。

运行结束时，无论通过实时事件还是轮询获知，都同步读取最新会话，让本轮新增的记忆提案和已引用偏好及时显示，无需关闭重开。首次取得完整会话快照时，即使版本号与创建回执相同，也加载已确认记忆列表。每次终态转换只触发一次恢复；重复事件不反复读取，旧运行的迟到快照不覆盖新运行。读取失败保留原会话和输入，提供重新连接；成功恢复后清除断线提示。记忆仍须人类单独接受或拒绝，不因提案生成或回复完成而自动保存，也不触发指标保存。接受、拒绝和撤销后先读取会话提案状态，再刷新已确认记忆；读取中或失败时禁用记忆变更并保留错误及重新读取入口。响应丢失后的“重新读取”仅恢复服务端状态，不重发决定，不能把已接受的提案误当作新替换；成功恢复清除旧错误并保留未发送输入。

此浮窗由消息区承担内容滚动，是第 6 节页面滚动规则的限定例外。标题保持一行，小牛、标题和图标操作以紧凑工具栏排列；上下文与模型从信息图标展开到消息滚动区，避免占用常驻高度。模型名仅说明配置值，不承诺连通或代表旧回复所用模型。输入框一行起，最多六行并受可见视口高度约束，超出后允许输入控件自身滚动；这是第二项限定例外。使用不透明表面，无模糊或动画依赖；验收覆盖滚动页面、长消息、320/768/1440px、1023/1024px、短视口、键盘、对比度与图片加载失败。

按用户对紧凑布局的要求，关闭、展开、复制、发送、停止和回到底部使用现有 Heroicons 图标，图标20px，按钮命中区域至少40×40px；完整名称保留在 aria-label，悬停和键盘聚焦显示文字提示。提示通过 Portal 使用独立浮层常量71，避免被消息滚动区裁切；Esc 优先收起当前提示，再次按下可收起对话。桌面复制操作随所属回复悬停或聚焦显现，触屏持续可见。填入、保存、试算和停止并发送保持短文字，业务动作不得只有难以理解的符号。

消息组间距16px，消息区内边距12px；正文仍为14px。成果中的公式、参数、填入和保存合为工具栏，公式/参数按钮使用 aria-expanded/aria-controls 驱动按需详情；完整定义、参数约束和原始公式均保留。输入框和发送/停止操作共享同一容器，不设置输入帮助问号按钮。此对话输入使用视觉隐藏的真实 label，是第8节标签位置的局部例外，不用 placeholder 代替可访问名称。

仅使用局部 CSS 轻动效：浮窗打开180ms淡入并上移6px，按钮按压120ms反馈，复制成功图标160ms淡入。消息立即出现，不逐字播放或延迟回答；公式即时展开，不动画容器尺寸。关闭保持即时生效，避免动画改变取消或焦点语义。prefers-reduced-motion 下取消上述动画、位移与过渡；小牛不增加装饰动画，现有其他工作台动效规则不扩大。

指标草稿卡片只展示后端明确校验通过且未失效的当前草稿。设计中、校验失败及待重新校验的草稿和其诊断信息不展示为卡片；重新打开、刷新与实时更新遵守同一规则。助手运行时继续显示处理状态和对话，校验通过后才展示公式及人工填入、保存操作。

草稿以具体名称、结果类型和输出通道展示，“定义校验通过”不代表真实产品计算成功；参数详情按真实契约展示默认值、范围和步长。完整公式默认折叠，标量使用 `expression`，时序使用 `series_outputs` 中全部通道的名称与公式，不能因顶层公式为空而显示“等待公式”。展开后默认自动换行，可切换原始行；复制使用原始公式，不把视觉换行写回定义。填入和保存继续传递完整草稿，操作反馈归属该卡片；同一回执确认已保存后不因再次填入而重新启用保存。保存响应丢失后重试须沿用原确认与幂等键，关闭重开浮窗也不能重复创建；成功状态在浮窗重开后保留。刷新或离开再返回页面时，从服务端当前草稿的保存回执恢复“已保存”并禁用重复保存；客户端标识丢失时，服务端仍按会话内完整定义核对已有写入。恢复到成功保存回执时同步刷新宿主指标库，与直接保存成功使用同一通知入口；同一会话和定义在宿主存续期间只通知一次，重开浮窗或重新渲染不重复刷新。恢复成功回执后，卡片改为成功反馈并清除原保存失败提示；此后新的填入失败仍正常显示。服务端明确拒绝过期确认时，下次人工操作重新确认。

点击草稿保存后，先由服务端持久化确认预览，再用原生确认框展示冻结名称、完整公式、产品/周期/研究日和校验状态。同名冲突须在公式前明确提示“新增而非覆盖”；用户单独确认后才发送业务保存请求，取消不写入。预览本身会递增会话版本，客户端收到回执后立即通过统一状态入口仅推进同一会话的版本，再等待人工决定；取消或后续提交失败也不遗失该已发生的版本变化。较旧/其他会话回执不覆盖状态，不依赖额外读取成功才能继续对话。成功保存的版本回执也经同一入口接纳，随后刷新完整快照；即使该刷新失败，也不丢失已确认的保存版本。记忆接受、拒绝、替换和撤销也返回所属会话及当前版本，包括幂等重放；客户端先接纳版本，再读取完整快照。决定/快照读取错误与列表读取错误分别保存，迟到的列表成功不能清除未完成的决定核对或重新启用记忆操作。已经明确确认且结果不确定的重试继续沿用原确认与请求 ID，不重新预览；确认失效后须重新展示影响并由用户确认。

AI 回复正文由 `AgentMessageContent` 统一渲染 Markdown 与 KaTeX，消息标题使用 16px，正文沿用工作台 14px。公式、代码和表格只在各自区域横向滚动，不能撑宽浮窗；公式与代码区提供键盘焦点。普通正文兼容 `\(...\)`、`\[...\]` 和美元符号数学定界符，代码示例保留原文；列表和引用前缀不得混入数学内容。用户消息继续按原文显示，格式化结果不得回写原始对话或指标定义。

AI 请求试算后，“校验与预览”中的“AI 试算结果”显示独立快照，明确指标名称、真实产品、周期和历史截止日，复用工作台的标量、时序图表及可访问数据表。试算成功后同步选择区的真实产品、周期、有效历史截止日及后端实际参数；参数控件使用该试算定义的参数契约。调整后可按同一指标定义重新计算或导出，旧结果失效；编辑器未保存的公式不被覆盖。程序回填这些已验证条件不应取消正在完成回复的助手，用户另行变更研究条件仍按上下文变更处理。不能把模型回复当作成功回执。对话提供“查看试算结果”按钮，收起浮窗后定位到结果；加载、空结果、过期及旧会话缺失结果均须有明确文字提示。

助手的通用入口、标题和配置说明使用“AI 助手”；当前页的指标草稿与试算操作仍使用具体业务名称。草稿和试算入口必须放在产生它们的那轮回复内，不在整个会话底部常驻。新一轮仅讨论时不得携带上一轮的卡片；刷新和历史分页保持归属。历史草稿可填入编辑器后重新校验保存，历史试算按原产品与时间条件读取，过期时明确提示。

用户消息用浅品牌色气泡，AI 正文使用浅灰气泡（slate-50 底、slate-200 边框）与用户蓝区分，成果卡片仍保留独立边框；消息不显示“你”/“AI”可见角色标题，角色仅由消息的无障碍名称表达；气泡内直接开始正文（上下 8px 内边距），复制与编辑操作放在气泡下方的紧凑操作行内并右对齐，不占用正文上方的空间。输入的可访问 label 使用“发送消息”，Enter 换行，Ctrl/⌘+Enter 发送，输入法组合期间不发送；4000 字上限保留，3600 字起显示计数。建议问题只填入输入框，不自动发请求。已有回复后的新请求尚未获得运行回执时，发送状态显示在新消息后，不归入上一轮回复。正在运行时保留停止、停止并发送及取消待发送的既有串行语义。

所有含文字的用户与 AI 消息都有复制图标，复制原始全文，成功或失败反馈归属该条消息；运行中已显示的文字同样可复制，AI 回复的复制图标仍随所属回复悬停或聚焦显现。编辑入口只出现在最后一条用户消息上，且仅当该轮已由用户停止、没有真实正文或有效成果（校验未通过的草稿不算成果，系统“已停止”提示不算回复）、当前没有排队、发送、恢复、阻塞或人工保存操作时可用；服务端按同一资格复核，过期会话版本、非最后一条、已回答轮与忙碌会话一律拒绝。点击编辑把完整原文载入底部输入区，并显示“编辑消息”和取消；取消恢复进入编辑前的未发送草稿，空白或超长不能提交，Ctrl/⌘+Enter 与输入法语义不变，提交被接受前不能取消或重复提交。保存并重新发送后，该条消息显示新文本并触发新的计算；被替换的一轮连同其停止提示一起离开对话，原文只保留在服务端审计中，模型上下文与压缩记忆不得残留被替换的文本或中间结果，本轮之前的对话与成果保留。发送失败时保留编辑文本与原消息，可重试或取消，重试沿用同一请求标识避免重复；刷新、重连与历史分页合并同一替换事件，不回退旧文字，也不让被替换运行的迟到回复重新出现。

编辑消息不撤销独立作出的人工记忆决定或指标保存；已接受、拒绝、替换和撤销的状态不能被旧轮快照恢复为待确认。被替换轮未确认的提案与计划退出当前任务，其旧工具回执只留作审计，不能通过历史回读再次进入模型。用户已确认的长期偏好按原有范围和撤销规则单独处理。

标题栏提供“清空上下文”图标按钮，复用 Heroicons 的新对话图标、40px 命中区和文字提示。清空后保持浮窗打开，移除当前浏览器会话引用并重新挂载对话，下一次发送建立独立会话；旧消息、历史摘要、草稿、试算回执、继续运行引用及未发送输入不进入新会话。当前页面的产品和日期等显式研究条件保持可用；服务端历史记录保留审计用途，不自动导入新会话。运行中、保存/读取成果中或恢复会话中禁用清空，提示先完成或停止任务。清除浏览器引用失败时保留原对话并提示重试；清空后刷新不得恢复旧会话。

对话外壳由 `AgentPanel` 共用，指标建议、草稿与人工保存/试算由 `IndicatorAgentPanel` 适配；其他页面通过明确的成果渲染与宿主回调接入，不复制浮窗和会话控制。页面实例标识参与会话隔离；更换产品对象或页面时不能把旧请求的迟到结果带入新实例。对话及输入的可访问 ID 由实例生成。新增页面仍只展示一个助手入口，并遵守服务端工作域权限及人工操作门禁；接入方式见 [AI 助手共用架构与接入设计](../research/ai-agent-reusable-architecture-design-2026-09-21.md)。

产品研究、产品比较和持仓诊断复用同一入口。请求与最后已显示结果的冻结输入分别记录，加载、失败和过期状态不得把旧产品或旧结果配给新条件。产品研究明确标记当前页最多10项分析批次，选中/全选数量只是选择记录。比较保留混合产品类别、三个独立区间及原费用请求；全局比较研究日与指标矩阵显式截止日分别冻结，结果回包不能改写研究日或取消当前助手。持仓只绑定真实不可变 run；无快照保留构建入口并禁用发送，切换对象同时隔离业务请求与助手运行。情景首次失败与复算失败都向助手报告失败；错误状态独立记录，重试成功后才恢复就绪，旧成功结果继续保留其原请求引用。离开研究对象会取消该对象未完成的助手请求（包括稍后才被服务端接受的请求）；只关闭浮窗不取消。完整行情与图表仍由原业务接口展示，页面证据仅携带请求和来源引用，模型摘要由服务端重算和门控。

公开处理记录按 run/seq 归属及去重，只显示工具语义、状态和有依据的耗时；不展示内部推理或原始参数。界面仅保留最近 100 条，恢复读取最近 200 个事件窗口的一页；这是展示缓存边界，不限制实际工具调用次数。缺失记录时只显示真实阶段，不能配对推测操作树或伪造百分比。阶段变化及新增记录在接近底部时跟随，上翻时提示查看新消息；历史分页保留可见消息锚点。助手界面文案接入现有中英文词条，模型正文、用户输入、公式和业务名称保持原文。

LLM API 配置支持多组独立配置。新增及编辑不改变当前使用项；“设为使用”明确切换唯一使用项，“停止使用”后不回退到其他 API。旧单组配置保留为当前使用项。切换编辑对象须清空输入中的密钥，不把上一组密钥带入下一组；所有返回值仅展示脱敏信息。

LLM 配置的“思考等级”使用原生 select，每组 API 独立保存，默认“服务默认”；清楚说明档位依赖模型，不能将 max 宣传为所有模型都支持。单次请求超时与思考等级相邻，说明高等级可能耗时更长；已保存列表显示该组等级。桌面双列、小屏单列，帮助文字参与正常页面滚动；切换编辑对象不沿用另一组等级与超时。模型内部思考文本不展示为助手正文。

LLM 配置页面首次进入及刷新只展示配置列表；点击“编辑”或“新增 API”才展开表单。保存成功或取消后收起，并清空未保存的密钥输入、将焦点返回入口；保存失败保留表单及输入供重试。选用或停用 API 不自动展开表单，空列表提示点击“新增 API”。

LLM 编辑表单的“上下文窗口（tokens）”使用可留空的原生数字输入，留空表示自动匹配，列表区分“自动”与显式数值。说明未知接口的保守默认值，以及填写值不会扩大供应商容量；该设置随 API 独立保存。助手整理历史期间显示“正在整理上下文，稍后继续…”，继续允许停止，不能把内部压缩阶段显示成用户需求错误。

AI 指标适配中的 `useIndicatorPreview` 负责完整试算读取、定义匹配和本轮条件采纳；`useAdoptedIndicatorPreview` 管理工作台采纳状态。公共会话保留原成果 DTO、版本与取消隔离，不执行指标结果读取。此分工不改变上述交互、保存和条件回填契约，详见 [共用边界设计](../research/ai-agent-reusable-architecture-design-2026-09-21.md#8-共用边界优化设计2026-09-23)。
