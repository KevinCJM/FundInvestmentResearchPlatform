## 1. 核心设计决策

### 1.1 与上位文档保持一致的主线

```text
设置：风险等级配置中心
    选择／建立参考资产大类与代理
                  ↓
    选择／建立一套参考 CMA + 标准约束
                  ↓
    构建有效前沿 → 自动分档／人工阈值 → 检查参考画像
                  ↓
    发布不可变 RiskScaleVersion
                  ↓
    可选：设为本口径的系统默认
                  ↓
投前研究：投资目标引用版本 + 授权最高等级 + 数值上限
```

建立标尺不依赖任何 Mandate，也不依赖 SAA 或 TAA 结果，避免首次使用循环依赖。不存在标尺时，投资目标仍可保存资金事实，不能偷偷填入示例等级。

### 1.2 本文补充的产品决策

以下是对上位设计的工程细化，以及本次“默认一套、用户可做多套”的需求扩展，不把它们描述成既有功能。

| 决策 | 采用方式 | 原因 |
|---|---|---|
| 多套标尺 | 系统模板 + 项目默认版本 + 自定义方案／版本 | 保留统一默认，又允许不同市场与政策口径 |
| 大类／Proxy 共用 | 相同领域对象、编辑组件和数值服务；不同使用场景 | 不复制两个构建器，也不把业务职责混为一个对象 |
| 基础分级轴 | 年化波动率；ES、回撤等作为参考画像 | 与上位文档的前沿分档一致，不引入未经定义的综合分数 |
| 一套标尺的 CMA | 固定一套有效参考 CMA | 多模型生成多套标尺；不在这里再实现 Multi-CMA SAA |
| 默认入口 | 已有方案列表；新建才进入分步编辑 | 日常使用者不必每次学习并操作校准流程 |
| 数学执行 | 共用矩参数前沿 + NJIT 分段 | 不经历史 HTTP 接口绕行，不制造伪历史收益 |
| 存储 | 复用既有 ArtifactRepository 与 AtomicJsonStore | 不新建第二套成果数据库或平行版本存储 |
| 发布治理 | 草稿、计算预览、发布、设为默认分开 | 防止“看一眼就保存”和默认切换影响历史授权 |

### 1.3 风险等级的唯一解释

C1–C5 是本项目的研究和授权语言，不声称是跨机构统一的适当性评级。

假设某个**示例版本**的 C3 上限是年化波动 8%：投资目标选择 C3，表示“允许风险不超过 8%”，不是要求实际组合承担至少 C3 下界的风险。实际结果可以是 C1 或 C2。

一个完整引用必须同时包含：**标尺版本、币种、风险口径、最高授权等级、冻结数值上限**。仅保存字符串 `C3` 不构成完整契约。

### 1.4 明确不在本模块内做

不实施客户问卷、现金流推导风险偏好、SAA／TAA 优化、自动修改投资目标、产品准入审批、订单或自动交易。组织资金政策继续由 OrganizationPolicyVersion 表达。

不强制用户在本页使用画布；数值步骤仍需独立可追溯，但普通操作采用表格、表单与分步流程。

## 3. 方案、默认项与权限

### 3.1 三个对象，不混用“默认”

| 对象 | 含义 | 是否可直接被投资目标引用 |
|---|---|---|
| 系统模板 | 参考大类、参数建议和操作起点；可以尚未绑定真实数据 | 否 |
| 标尺方案 RiskScaleScheme | 一套持续维护的方案，包含多个发布版本和编辑草稿 | 否，必须选定版本 |
| RiskScaleVersion | 冻结资产、代理、CMA、约束、前沿、分档与证据 | 通过用途检查后可以 |

“系统默认”是指向某个已发布版本的配置，不是模板，也不是动态取最新版本。

### 3.2 默认与自定义的规则

允许系统维护者建立默认方案，用户从默认方案复制输入建立其他方案，也可从空白或已有资产／Proxy 版本开始。

默认绑定按兼容键维护：

```text
workspace_id + base_currency + risk_basis_id → risk_scale_version_id
```

同一兼容键最多一个系统默认。人民币和美元标尺可分别设默认，但页面不得只写一个没有币种的“默认 C3”。目标币种或风险口径不兼容时，显示“没有匹配的默认标尺”，不自动换汇或转换等级。

第一版不额外建设复杂的组织继承树。用户的“最近使用”只影响选择器便利性，不覆盖项目默认，也不修改任何已保存授权。

### 3.3 初始模板

提供一套可复制的“人民币多资产参考模板”，大类建议为现金／货币、利率债、信用债、权益、黄金。此为产品模板建议，不是已核验的具体投资产品名单。

代理选择优先展示具备真实数据与正确口径的指数，也允许来自冻结产品池的 ETF／基金。具体代码由现有目录选择；模板不伪造已存在的指数、费用或历史收益。

模板中未绑定来源、尚未生成参考 CMA、尚未完成校准的项明确标为“待配置”。系统可以交付经真实数据验证并发布的默认版本，但没有这些数据与证据时，不得把模板显示成已发布默认。

**不为了凑齐五类而制造现金的零波动序列。** 没有合格低风险锚时，应补齐来源或明确限制用途。

### 3.4 人与权限

| 操作 | 研究使用者 | 方案维护者 | 系统维护权限 |
|---|---|---|---|
| 查看可见的发布版本、用于目标选择 | 允许 | 允许 | 允许 |
| 建立自己的草稿、复制方案 | 按工作区权限 | 允许 | 允许 |
| 发布可见范围内的自定义版本 | 按发布权限 | 允许 | 允许 |
| 改系统默认、停用默认版本 | 不允许 | 不自动允许 | 允许 |
| 覆盖历史发布数值 | 不允许 | 不允许 | 不允许 |

权限由服务端解析真实身份与工作区授权，不能信任请求中的 `owner_id` 或前端按钮隐藏。当前代码是否具备完整身份体系须在实现接入时核验；没有身份隔离的本地运行模式只能表述为受信任工作区，不能声称实现了用户私有权限。

资产用途 `reference/research`、对象所有者和可见范围是独立字段，不能只加一个 `scope=system|mandate` 就代替版本、权限和业务关系。

## 4. 前端信息架构与布局

### 4.1 导航位置

新增 `/settings/risk-scales`，放在“研究口径与参数中心”附近。名称固定为“风险等级配置中心”，避免与现有“风险模型中心”混淆。

| 路由（待实现） | 页面 |
|---|---|
| `/settings/risk-scales` | 方案列表与当前默认 |
| `/settings/risk-scales/new` | 创建草稿 |
| `/settings/risk-scales/drafts/:draftId` | 分步编辑与预览 |
| `/settings/risk-scales/versions/:versionId` | 已发布版本只读详情 |
| `/settings/risk-scales/compare` | 两个版本的差异比较 |

静态路由先于通配 ID 注册。沿用 `StageLayout` 和 Settings 导航；进入详情后不重复显示阶段大标题，不在现有左侧导航之外再增加一列常驻方案树。

### 4.2 列表页：先回答“现在能用哪套”

页面从上到下：

1. 页面标题与一句用途说明；右侧一个主按钮“新建标尺”。
2. 当前本位币／风险口径的默认摘要：名称、版本、数据截止、复核状态、“查看版本”。没有默认时说明缺什么，提供配置入口。
3. 搜索与筛选：方案名称、币种、范围、状态；默认显示可见方案，不默认加载所有版本与数组。
4. 方案表：名称、币种／口径、当前发布版本、参考 CMA、数据截止、可用状态、操作。
5. 展开单个方案才读取版本列表；草稿通过“继续编辑”进入，不与发布版本混成一条历史。

避免一屏铺满资产数、方案数、均值等 KPI 卡；这些不帮助用户完成“选择、维护、引用”三项任务。

**列表操作语义：**“查看版本”“基于此版本新建”“比较版本”“设为默认”“停止新引用”。没有“编辑已发布版本”按钮。删除只作用于用户确认的草稿，发布成果只能改变使用资格，不能删除其审计来源。

### 4.3 分步工作台：五步，而非一张超长表单

```text
基本信息 → 大类与代理 → 参考假设与约束 → 前沿与五档 → 核对发布
```

| 步骤 | 用户主要回答的问题 | 主操作 |
|---|---|---|
| 1 基本信息 | 这套标尺给什么市场、币种和用途使用？ | 下一步：配置参考资产 |
| 2 大类与代理 | 用什么序列代表这些经济暴露？ | 检查数据 → 确认参考资产并继续 |
| 3 参考假设与约束 | 长期假设来自哪里，参考空间有哪些限制？ | 计算前沿与分档 |
| 4 前沿与五档 | 五档边界合理吗，是否稳定，需要覆盖吗？ | 核对发布内容 |
| 5 核对发布 | 发布哪些数值、限制和适用范围？ | 发布新版本 |

已完成步骤可返回修改；尚不具备依赖的步骤说明缺少项，并提供定位，不只显示灰色按钮。切换步骤不自动发布或自动重新运行。

### 4.4 宽屏结构

工作台内容最大宽度与外边距由 StageLayout 管理，不照抄存量页面里的嵌套 `max-w-6xl`。

```text
设置 / 风险等级配置中心 / 新建标尺

人民币多资产参考                       草稿未保存  [保存草稿]
1 基本信息  2 大类与代理  3 假设与约束  4 前沿与五档  5 核对发布
────────────────────────────────────────────────────────────
主工作区（弹性宽度）                    本次上下文（约 280px）
当前步骤的表单／表格／图表              币种与年化口径
                                      参考资产与 CMA 版本
内联问题与处理入口                     数据截止与质量摘要
                                      已变化、需重算的内容
────────────────────────────────────────────────────────────
[上一步]                               [当前步骤的唯一主操作]
```

仅当内容区宽度足够时显示右侧摘要；摘要不列完整矩阵、历史版本和所有警告。详细诊断在主区展开，避免“全站导航 + 方案树 + 表单 + 检查面板”四列挤压。

第 4 步以图表和五档表格为主体，摘要缩为顶部一行，给比较区域更多宽度。

### 4.5 响应式与现有风格

| 场景 | 规则 |
|---|---|
| 宽屏、内容区充足 | 主区与摘要两列；保留系统阶段侧栏 |
| 小于 1280px | 沿用阶段导航折叠；工作区摘要改折叠区，不再固定右栏 |
| 768px 左右 | 单列；步骤可分行；矩阵改为“按资产编辑”，不是缩小字体 |
| 320px 手机 | 展示当前步骤与进度；主操作全宽；五档按行展开；宽表只在表内横向查看 |

所有页面保持一个纵向滚动容器；必要的表格横向滚动不增加固定高度的内层纵向滚动。若使用底部固定操作区，须使用已有系统层级并为内容预留空间，不遮挡输入与焦点。

复用 `components/ui.tsx` 的 Card、Button、Badge、SectionHeader、EmptyState。工作台沿用 accent/slate、系统字体、12px 最小字号、数字等宽、卡片 rounded-xl、控件 rounded-lg、统一焦点环；不引入第二套组件库或动画库。

风险页空态使用 `mascot={false}`。C1–C5 是分类，不以“绿色成功到红色失败”表达；颜色只能辅助等级文字与边界线。图表使用 ECharts 和统一图表配置。现有规范中的全站主题收敛仍有待办，新页面不能假设这部分已经全部实现，也不能新增一套散落的十六进制配色。

## 5. 五步操作的字段与交互

### 5.1 第一步：基本信息

默认仅展示：名称、用途说明、本位币、参考研究日、风险口径、预计复核日、起始方式。

起始方式为“从系统模板”“从已有版本”“空白新建”；选择已有版本只复制可编辑输入与来源引用，清空发布身份及预览状态，原版本保持不变。

风险口径第一版固定为年化波动率，展示年化依据，不开放未经实现的综合打分。研究日、预测期限、数据截止与复核日分别命名，不用一个“有效期”承载所有含义。

默认复核节奏作为可修改的模板建议，不按天自动重算并改变 C1–C5。每日数据更新与授权更新是两件不同的事。

### 5.2 第二步：大类与代理

默认展示经济大类行，而不是要求用户从一堆产品代码开始。

| 默认列 | 操作 |
|---|---|
| 大类名称／稳定 ID | 改展示名称；经济定义变化建立新版本 |
| 经济角色与流动性 | 从明确枚举选择，附解释；不能凭名称自动认证低风险 |
| 代理摘要 | 例如“1 个指数”或“3 个基金”，点击查看成分 |
| 数据覆盖 | 实际开始／截止日期、币种、总收益口径、缺失状态 |
| 操作 | 更换代理、查看证据、移除本草稿行 |

“添加代理”使用共用选择器，分为指数和产品两个有类型的来源页签。支持单一及复合来源、代码和名称搜索；产品范围必须来自冻结产品池。所选行显示数据类型、费用口径、币种、覆盖与可得性，避免只显示名称。

复合代理展开成分权重编辑。权重合计必须为 100%；提供“等权填入”显式按钮，但不在输入、缺失或删除时自动归一化。跨币种必须选择受支持的 FX 规则，否则不能继续。

默认再平衡规则为模板中明确记录的规则，页面必须显示其含义，如“每月重设成分比例，其余时间随价格漂移”。权重合计校验、收益计算和年化由后端契约决定，前端不维护另一份数学真相。

大类编辑共用 `AssetClassVersion`、`ProxyBindingVersion`。自动分类可作为已有能力的辅助入口，但不由 SAA 反推类别，也不成为完成本步骤的必要操作。

“检查数据”只读取、计算和展示质量结果，不保存正式资产、代理或收益面板。需要跨页面继续时可显式保存草稿。

首次创建且尚无冻结上游版本时，检查成功后主按钮变为“确认参考资产并继续”。核对区明确列出将保存的资产、代理和必要收益面板；用户确认后才调用共用上游发布能力。已选中兼容的发布版本时直接引用，不重复发布。

多个上游成果的确认不伪装成跨文件原子事务：失败停在当前步骤，逐项显示已保存与未完成项，通过幂等重试补齐。所有必需引用完成后才进入 CMA；不能拿临时草稿 ID 代替不可变来源。第三步新建 CMA 同样先明确确认其版本，再返回本标尺草稿，这些步骤不自动发布风险标尺。

### 5.3 第三步：参考 CMA 与标准约束

首屏优先是“选择已发布参考 CMA”，展示方法、版本、资产轴、币种、数据截止、预测期限与口径。

不兼容版本默认不可选，但用户可展开“为什么不能使用”：缺失大类、代理版本不同、币种不一致、收益语义不一致、过期／时点不符。不能按名称猜测或静默选择最新。

“建立新参考 CMA”打开共用 CMA 编辑工作区，保留本次草稿及返回地址。当前独立 CMA 页尚未完成时，由同一个共用编辑组件承载，不能复制一套 RiskScaleCmaModelEditor 数学业务。

参考 CMA 的基础支持顺序：

| 方法 | 本模块要求 |
|---|---|
| 历史统计 | 作为共用 CMA 的正式生成器补齐；明确使用样本均值作为本次参考预期 |
| 手动假设 | 复用现有模型契约；风险来源与人工覆盖清楚可查 |
| Black–Litterman、Scenario Mixture | 只接受已实现且通过当前执行能力检查的冻结结果 |
| NIW 等尚未实现方法 | 显示具体不可用原因；不以名称占位假装可执行 |

标准约束首屏只展示无做空、无杠杆、权重合计 100%、大类上下限；分组上下限放在可展开区域。现金是显式资产，不是“剩余的钱”。这是校准参考空间，不自动继承本次客户目标约束。

CMA 参数表默认显示大类、预期收益、波动率与来源；相关矩阵和估计细节折叠。不能要求普通用户手填 JSON。

任何来源改变都使前沿、分档及发布确认失效；已冻结、明确选中的上游版本不随后台数据刷新自动改变。

### 5.4 第四步：有效前沿与 C1–C5

顶部展示一次计算摘要：输入版本、实际数据区间、有效网格点数／总数、端点状态、校准稳定性。计算失败时保留诊断，不出现伪造曲线。

图表横轴“年化波动率 %”，纵轴“年化预期收益 %”。显示有效前沿、四条等级分界、五个代表组合和可访问的详情。收益口径与参考 CMA 放在图旁，不藏在 tooltip 内。

下方五档表格默认列为：等级、风险区间、授权上限、代表组合预期收益、代表组合波动、校准状态。选择某档后展开成分权重、历史 ES／回撤及口径。避免默认一次铺开所有辅助指标。

重要交互：

- 点表格某档，同步高亮曲线区间和代表组合；反向选择同样有效。
- “分档方式”是显式选择项：默认 `前沿形状（推荐）`，同时允许选择 `风险等距`、`前沿弧长等分`；人工阈值是独立模式。以后新增算法通过统一注册契约扩展，不在页面增加一套特例逻辑。
- 切换分档算法只基于当前已经验证的同一条有效前沿重新计算四个切点、五档与代表点；不重新读取 Proxy、不重算 CMA、不重新求有效前沿。
- 页面在算法名称下用一句话解释含义，例如“根据风险增加带来的收益变化及前沿弯曲程度寻找自然分界”；具体 DP、角度、弧长、容差进入高级详情。
- 可提供“比较分档方法”只读视图，同时叠加各方法的四个边界，帮助维护者理解差异；发布时仍必须明确选择且只冻结一种方法，不把多个算法平均成一套边界。
- 算法失败不能静默改用另一算法。若用户主动改选“风险等距”或“弧长等分”，这是新的显式研究选择，不是 fallback。
- 人工模式提供五个上限输入框，自动生成相邻区间；不让用户分别填写十个上下界而制造间隙。
- 覆盖自动阈值时并列显示原值／新值／差异，要求填写原因；“恢复自动值”需要显式操作。
- 阈值编辑只重新做分档、代表点选择与必要画像，不重复读取数据、拟合 CMA 或求整个前沿。
- 超出参考范围的区间显示“该部分未校准”，不延伸曲线或编造代表收益。
- 101 点与 200 点不稳定时说明边界移动程度及可采取的操作，不用一个绿色“成功”掩盖警告。

**档内收益和回撤属于代表组合，不是本档所有组合的预期或损失承诺。** 此说明放在表头帮助文本及画像区域，不依赖页面最底部免责声明。

### 5.5 第五步：核对与发布

核对页只呈现最终采用内容：名称与币种、参考来源、五个上限、代表画像的有效范围、未完成项、人工覆盖理由、数据与日期、复核安排。

“发布新版本”必须显式确认；服务端重新核验与预览一致。发布成功转入只读详情，显示版本号及可引用状态。

“设为系统默认”是发布后的独立操作，只影响新目标的默认选择。确认框显示旧版本、新版本、兼容键及“已有目标继续引用原版本”。不在发布复选框里默认勾选，以免用户只想留存研究却切换全系统默认。

已发布详情主操作为“基于此版本重新校准”；不打开即计算，不用当前数据重新生成历史图。

### 5.6 比较版本

一次比较两个版本。先比较资产／代理／CMA／约束与日期，再显示边界差异和警告。

币种或风险语义不兼容时可并列阅读，但不叠加同一坐标轴、不输出有误导性的差值排名。页面不推荐“收益最高的标尺”，以免通过挑选更宽的标尺变相放松授权。

## 6. 前端状态、错误与可达性

### 6.1 编辑状态机

```text
editing → checking → computing → preview_ready → publishing → published_readonly
   ↑          ↓           ↓             ↓             ↓
   └──────── invalid / failed / stale / conflict ──────┘
```

计算状态与草稿保存状态分别管理；保存草稿不能把失败结果变成有效预览。

每次输入变化递增 `input_revision`，请求携带输入哈希；响应只应用到同一草稿与 revision。AbortController 负责取消不再需要的请求，generation 检查阻止已经返回的旧结果覆盖新输入。只取消浏览器请求不代表后端数值任务已安全结束。

失效粒度由依赖决定：修改说明文字不必重求前沿，但需要重建发布摘要；改阈值只失效分档与画像；改约束失效前沿以后；改资产／代理／CMA 失效全部下游。所有改变都会使旧的发布确认无效。

### 6.2 必须完整的状态

| 状态 | 用户能看到什么 | 后续操作 |
|---|---|---|
| 无默认／无方案 | 原因、模板尚未配置的状态 | 新建或选择匹配口径 |
| 加载 | 与最终布局同形的骨架与简短阶段文字 | 不展示示例数值 |
| 数据不可用 | 具体大类、来源、缺失日期或字段 | 返回该行修正或查看数据中心 |
| 不可行／数值失败 | 明确区分约束矛盾、未收敛、未验证 | 修改约束或重新研究，不自动松绑 |
| 旧预览 | “输入已变化，结果仅供对照” | 重算后才能发布 |
| 并发修改 | 当前版本与本次编辑的冲突 | 重新加载或另存草稿 |
| 磁盘／执行器不可用 | 原因与重试入口 | 不用旧缓存伪装计算成功 |
| 历史版本当前不可引用 | 历史结果仍可读，可用性另行提示 | 基于其新建，不静默换版本 |

百分比输入保留空串、负号、小数点等编辑中间态，失焦或提交时才严格解析。空白不等于 0，负值不被自动取绝对值。服务端返回字段路径，前端就近定位并把焦点移到首个错误。

### 6.3 可达性与国际化

新文案统一维护 `riskScales.*` 中英词条；不新增硬编码的中英文混合菜单。百分比与日期按既有展示组件格式化，计算使用未舍入数值。

键盘能完成步骤切换、表单、选择器、分档编辑与发布；抽屉／弹窗支持 Escape、焦点约束和关闭后归还焦点。图表重要信息有表格替代，等级状态不只靠颜色。

按前端准则验收 320、768、1279／1280、1440px 与 200% 缩放，覆盖加载、有数据、错误、禁用、已发布和冲突状态。不能以设计静态检查代替真实浏览器验收。

## 7. 领域契约与不可变版本

### 7.1 对象关系

```text
RiskScaleScheme
    ├─ RiskScaleDraft（显式保存，可修改，带 revision）
    └─ RiskScaleVersion（不可变）
          ├─ AssetClassVersion
          ├─ ProxyBindingVersion
          ├─ ReturnPanelVersion（需历史证据时）
          ├─ Reference CmaVersion
          ├─ StandardConstraintProfile
          ├─ FrontierResult + SegmentationResult
          └─ ReferencePortraits + ValidationEvidence

DefaultBinding ──→ 某个 RiskScaleVersion
MandateVersion ──→ 精确 RiskScaleVersion + cap 快照
```

用户复制方案时复用只读上游引用，不复制整个收益数组。修改其中的上游内容时建立新版本，不能覆盖被其他标尺引用的资产或 CMA。

### 7.2 核心字段

| 契约 | 必要字段 |
|---|---|
| Scheme | `scheme_id, name, description, workspace_id, owner_ref, visibility, revision` |
| Draft | `draft_id, scheme_id, revision, editable_definition, selected_refs, created_at, updated_at` |
| RiskScaleVersion | `id, scheme_id, version_number, artifact_type=risk_scale, definition_schema_version, created_at, content_hash` |
| 来源 | `asset_class_ref, proxy_binding_ref, return_panel_ref, reference_cma_ref, ordered_asset_ids, source_hashes` |
| 口径 | `base_currency, risk_basis_id, moment_semantics, moment_period, periods_per_year, annualization_method, forecast_horizon_years, fee_basis, fx_hedging_basis` |
| 时间 | `research_as_of, data_as_of, information_available_at, published_at, effective_at, review_due_at, valid_until` |
| 前沿 | `constraint_profile, algorithm_id, tolerances, grids, raw_statuses, endpoints, weights_ref, metrics_ref, diagnostics` |
| 分档 | `method, proposed_boundaries, applied_boundaries, segments, representative_indices, override_evidence, stability` |
| 画像 | `metric_contracts, values, statuses, source_refs, limitations` |
| 验收 | `mathematical_status, publication_evidence, acknowledged_warnings, execution_fingerprint` |

`valid_until` 可为空；复核到期和硬失效不是同一个字段。运行耗时、进程号等观测信息不进入确定性预览哈希，但随执行审计保存。

### 7.3 等级条目

```text
level_code: C1 | C2 | C3 | C4 | C5
lower_bound / lower_inclusive
upper_bound / upper_inclusive
authorized_volatility_cap
calibration_status: calibrated | partially_calibrated | not_calibrated
reference_node_ids / representative_node_id（可以为空）
reference_metrics（各自附 status 与口径）
```

下游统一读取上限，不按前端格式化后的百分比重建。等级显示名称可翻译，`level_code` 及边界等号不随语言变化。

### 7.4 状态不能合成一个布尔值

分别维护数学状态、发布状态、当前引用资格和默认身份。已发布的历史 artifact 不因到期而改写其内容哈希；退休、默认切换与资格变化由单独治理记录表达。

发布可以保留带限制的人工政策阈值，但 `calibrated_reference` 与 `policy_thresholds_only` 必须区分。存在数据损坏、参考 CMA 不合法、未解释的越权来源等硬错误时不能发布可用版本。

自动模式必须通过完整前沿与分段校验。人工模式可在有依据时发布含未校准区间的政策阈值，但不得伪装成通过自动校准。

设为全局默认另外检查：有合格低风险／流动性锚、用途覆盖说明、兼容口径、有效发布状态、必要警告已确认。只有股票与黄金等受限集合可保存研究，但不能不加限制地作为低至高风险的系统默认。

## 8. 共用代理、数据与参考 CMA

### 8.1 只建设一条共用数据管线

```text
来源目录与冻结版本
    → 类型化来源解析与时点检查
    → 相邻合法观测收益／必要 FX 转换
    → 代理权重规则与收益递推
    → 共同收益面板、有效性与数据质量
    → 共用 CMA Evidence Builder
    → 一套冻结有效 CMA
```

设置和投前研究调用同一条能力。只读选择器、资产／Proxy 编辑器以及后端来源契约共用；“风险标尺校准”和“本次策略研究”是不同编排，不共享可变草稿。

对于历史生成器，样本协方差、均值、年化与收缩调用已注册的统一内核。历史风险参考目前返回历史均值，不代表它已经是完整的 Historical CMA 生成器；须在共用 CMA 中补齐方法身份与来源确认。

### 8.2 代理计算契约

代理第 t 期收益与持有权重满足：

\[
r_{c,t}=\sum_i h_{i,t-1}r_{i,t},\qquad
h_{i,t}=\frac{h_{i,t-1}(1+r_{i,t})}{1+r_{c,t}}.
\]

第二式用于不再平衡期间；到约定再平衡时点才重置目标比例。期末收益不能使用同一期结束后才知道的目标权重。每期固定权重须明确标为每期再平衡代理。

若组合净值归零导致权重漂移式分母为零，终止并返回不可继续的路径状态，不能填零权重继续生成曲线。

外币未对冲转换使用 `(1+r_local)*(1+r_fx)-1`，冻结报价方向和时点。对冲口径只能选已实现的数据或模型，不靠更改名称实现。

持有成分缺失时，返回缺失状态；不对剩余成分重新归一化。明确为零权重的成分不参与当期收益，但不能利用未来缺失信息回头将其权重改为零。

### 8.3 样本、PIT 与收益单位

先从合法相邻 NAV 计算收益，再做日期／期间对齐，不能先删掉缺失日期再计算，把多日收益压成一天。跨市场序列必须用兼容的期间边界和日历；“市场休市”与“数据缺失”分别处理，禁止无规则前向填充。

历史窗口提供 1Y／2Y／3Y／5Y／10Y／共同起点／自定义。请求区间和实际可用区间并列显示，用户未确认时不缩短窗口。年化参数来自观察频率与日历契约，不一律乘 252。

生产质量规则版本化：样本数、共同覆盖率、尾部有效观测、异常值策略、低风险锚证据、数据可得性。阈值是研究政策，不伪称数学定理；技术最低样本数不表示长期预测可靠。

正式总收益标尺不得把价格指数当全收益指数。数据来源只有价格口径时可保留研究说明，但必须显式选择兼容的研究口径，不能获得总收益默认版本资格。

今天建立的成分组合对历史做的模拟可以是事后研究，不自动证明历史时点可投资。发布日、训练截止、源信息可得日分别冻结；历史 PIT 应用需要独立证据。

### 8.4 CMA 兼容与风险矩

`frozen_numeric_inputs` 提供有效 `mu[N]`、`Sigma[N,N]`；从已冻结结果读取，不在风险页重新拟合同一个模型。

校验资产身份与顺序、币种、收益语义、时间尺度、费用、风险协方差所含不确定性。年化算术参数不等于实际一年复合收益矩，也不等于资金所需 CAGR。

Sigma 允许半正定，不要求所有现金类资产严格正方差。对称性／PSD 在数值内核验证；显著不合法时拒绝。不得为让求解器运行而偷偷投影或加噪声改变模型。明确选择矩阵修复应产生新的 CMA 方法记录和版本。

## 9. 有效前沿：共用矩参数求解

### 9.1 数学输入

\[
\mu\in\mathbb R^N,\quad \Sigma\in\mathbb R^{N\times N},\quad
\mathcal W=\{w: \mathbf1^\top w=1,\ 0\le l\le w\le u,\ g_l\le Bw\le g_u\}.
\]

无做空、无杠杆、总敞口为 1。先核验边界自洽、分组轴、重复约束与可行性，后求前沿。

参考资产数量遵守现有 N≤30；默认 101 点，稳定性复核 200 点。不得用有限随机候选的上包络冒充已经求解的有效前沿。

### 9.2 求解器补齐与唯一实现

当前 `feasible_qp_kernel` 只能在给定可行点、首行等式的条件下求解。因此应在共享 QP 层补齐一般形式：

\[
\min_x\ \tfrac12x^\top Hx+f^\top x,
\quad Ex=e,\quad Gx\ge h.
\]

`E/e` 与 `G/h` 明确分开；不把多条等式偷偷编码成可以释放的普通活跃不等式。做行尺度归一、等式秩与一致性检查，保留原始尺度的最终校验。

原 `feasible_qp_kernel` 如仍有真实调用，只做有测试覆盖的单等式适配并委托唯一核心；不能在风险模块复制一份旧求解器。存量算法行为在证明等价前不得切换。无法等价的改变必须作为明确算法版本变更处理，不能借重构擅自改变原历史工具。

### 9.3 Phase-I 可行初点

不能将“初值不可行”直接解释为“约束无解”。基础路线：

\[
\min_{x,t}\ t,\quad Ex=e,\quad Gx+t\mathbf1\ge h,\quad t\ge0.
\]

先求解一致等式的一个解，再选足够大的 t 构造 Phase-I 可行初点。等式不一致与一般线性可行性分别处理。

Phase-I 结果接近 0 且原约束复核通过，才输出可行初点。t 为正但没有通过校验的最优性／对偶证据时，仅表示未找到可行点或数值失败，不宣称严格不可行。

对外仅在结构性矛盾或经验证证书成立时返回 `infeasible_certified`；浮点证据同时附残差与容差。迭代耗尽返回 `iteration_limit`，不能伪装成无解。

### 9.4 两个端点

左端：最小化 `w' Sigma w` 得 GMV。若最小方差解不唯一，在保持该风险面时最大化收益：增加 `Sigma*w = Sigma*w0`，做等式秩处理，再求有界 LP。复核原方差及收益，避免留下被支配的左端点。

右端：先求 `r_max=max(mu'w)`，再在 `mu'w>=r_max-epsilon_return` 下最小化方差。它是最高预期收益面的最小风险点，**不是全可行空间的最大方差组合**。

若仅有一个有效组合，或收益／风险跨度近零，仍返回真实端点和退化原因；不强行产生五档。

### 9.5 目标网格与可行热启动

在两个端点收益之间建立目标网格，各点求：

\[
\min_{w\in\mathcal W}w^\top\Sigma w,
\quad \mu^\top w\ge r_j.
\]

共享约束矩阵、协方差和工作缓冲区。可利用上一个解热启动，但更高的目标收益可能使其不再可行：先检查；必要时沿前一解与最大收益可行点的凸组合移动到新目标，再调用要求可行初点的内核。

不能只因按目标排序就直接复用不可行初值。因凸组合而产生的新点也要在原尺度下校验。相同网格内只有活跃结构与系数确实一致时才复用分解，不声称所有点都能共享同一 KKT 分解。

### 9.6 状态、容差与发布门禁

每点保存目标收益、实际收益／风险、权重、迭代数、原始约束残差、站立性／对偶／互补性诊断和状态。`optimal_to_tolerance` 需通过原问题复核；正则化仅可用于求解方向，不改变被声明的经济目标。

建议初始数值策略，正式阈值须由基准验证后冻结：

| 参数 | 工程起点 | 语义 |
|---|---|---|
| 最终权重／线性约束绝对容差 | 1e-7 | 用原始尺度复核，不取前端两位小数 |
| 归一化 KKT 容差 | 1e-9 的数量级 | 保留绝对／相对残差定义 |
| 目标收益端点容差 | 1e-8 的数量级 | 以小数收益表示，不是百分比点 |
| 最大迭代 | 每点不超过当前 1000 上限 | 耗尽是状态，不静默放宽 |

参数作为 NumericalPolicyVersion 或等价冻结契约，不散落在 UI、服务与内核。

去重与非支配性检查只生成展示／分段索引，不删除原始失败证据。自动发布需要用于分段的曲线连续有效；失败网格点不通过插值补齐，也不跨过缺口连成新边。可重新求解更密网格或人工处理，但必须形成明确的新预览。

第一版不引入生产 SciPy／CVXPY／OSQP 回退。离线测试中的外部求解器只能作为有明确依赖的参考，不属于生产执行路径。

## 10. C1–C5 分档算法与边界

### 10.1 分档算法策略与默认方法

分档算法本身是**可配置、可版本化的策略**，不是 RiskScale 写死的一段逻辑。所有自动方法消费同一组已经通过连续性、非支配性和数值校验的前沿节点，统一输出四个切点、五个风险上限、代表点及诊断；它们不得各自重算 CMA 或维护另一套前沿求解器。

第一版注册以下方法：

| UI 名称 | `algorithm_id` | 核心含义 | 定位 |
|---|---|---|---|
| 前沿形状（推荐） | `frontier_shape_dp_v2` | 同时利用标准化风险变化、收益变化、局部角度／曲率特征和弧长权重，寻找五段内部形状较一致的连续区间 | **系统默认** |
| 风险等距 | `equal_volatility_v1` | 在 GMV 到前沿右端的风险轴上按 20%／40%／60%／80% 等距切分 | 简单、可解释的基准方法，不作为默认 |
| 前沿弧长等分 | `equal_arclength_v1` | 按标准化风险收益曲线的累计弧长 20%／40%／60%／80% 切分 | 同时考虑风险和收益的几何距离，但不识别曲率结构 |
| 人工风险阈值 | `manual_volatility_bands_v1` | 维护者直接输入五个风险上限并说明依据 | 治理／外部政策模式，不属于自动失败 fallback |

这里**明确允许风险等距**，但不能把它误写成“有效前沿天然应当按 X 轴五等分”。它只是用户主动选择的一种校准规则。同理，弧长等分也是显式算法选择。

算法注册项至少声明：`algorithm_id / version / input_contract / parameter_schema / complexity / deterministic_tie_rule / supported_risk_basis / execution_kernel_id`。RiskScaleVersion 冻结实际采用的算法 ID、参数和执行版本；以后新增分档模型时扩展注册表，不修改已经发布版本的语义。

所有方法遵守统一输出契约：

```text
cut_node_indices[4]
risk_caps[5]
representative_node_indices[5]
segmentation_status
algorithm_id / algorithm_version / parameters
quality_diagnostics
```

切换方法只重新运行分档内核与代表点选择，复用同一前沿数组。后端应预先计算并复用标准化坐标、边长及累计弧长；各算法不得重复复制整条权重矩阵。数值实现继续使用预热、固定签名 NJIT；请求路径禁止临时编译或 Python fallback。

#### 10.1.1 默认：`frontier_shape_dp_v2`

沿用上位文档的形状分段作为系统默认，不替换为收益五等分、裸斜率聚类或风险等距默认值。它的目标是依据**风险增加、收益增加以及前沿方向／弯曲程度的变化**寻找分界，而不是只看 X 轴距离。

设经过连续性与非支配检查的前沿节点为 i=0…J，按照风险递增排列。标准化：

\[
x_i=\frac{\sigma_i-\sigma_0}{\sigma_J-\sigma_0},\qquad
y_i=\frac{\mu_i-\mu_0}{\mu_J-\mu_0}.
\]

跨度小于冻结数值阈值返回 `DEGENERATE_FRONTIER`。不从重复风险点构造零长度有效边。

每条边计算：

\[
\theta_i=\operatorname{atan2}(y_{i+1}-y_i,x_{i+1}-x_i),\qquad
h_i=\sqrt{(\Delta x_i)^2+(\Delta y_i)^2}.
\]

用 h、hθ、hθ² 三组前缀和得到区间代价：

\[
E(l,r)=\sum_{i=l}^{r-1}h_i\theta_i^2-
\frac{(\sum_{i=l}^{r-1}h_i\theta_i)^2}{\sum_{i=l}^{r-1}h_i}.
\]

只有可解释的舍入误差负值允许置零。非有限值、零权重区间或明显负代价直接报错。

#### 10.1.2 可选基准算法

**风险等距 `equal_volatility_v1`** 只在用户显式选择时使用。令前沿左端风险为 `sigma_0`、右端风险为 `sigma_J`，四个目标边界为：

\[
\tilde b_k=\sigma_0+\frac{k}{5}(\sigma_J-\sigma_0),\qquad k=1,2,3,4.
\]

再映射到满足顺序、最少边数和最小跨度约束的最近有效前沿节点，`b5=sigma_J`。这里的“最大风险”仅指**有效前沿最高收益右端点的风险**，不是全部可行权重中的最大方差。该方法容易解释，但不会识别“多承担风险却只能换来少量收益”的弯曲区，因此不作为系统默认。

**前沿弧长等分 `equal_arclength_v1`** 使用与默认算法相同的标准化 `(x_i,y_i)` 和边长 `h_i`。令累计弧长：

\[
H_j=\sum_{i=0}^{j-1}h_i,
\]

四个目标位置为 `k*H_J/5, k=1..4`，再选择满足顺序和最小跨度约束的最近有效节点。它同时吸收风险和收益两个方向的变化，但只按“走过的曲线距离”分段，不判断局部方向变化是否形成新的风险收益区域。

两种基准算法均为确定性 O(J) 算法，可以与 `frontier_shape_dp_v2` 共用标准化数组与累计弧长缓冲区。比较算法时只生成不同的切点索引，不复制 `weights[J,N]`。

### 10.2 连续动态规划

\[
D(k,j)=\min_{i<j}\{D(k-1,i)+E(i,j)\},\quad D(0,0)=0.
\]

其余初值无穷大。k=5；默认每档至少 5 条有效边、标准化风险跨度至少 0.05。候选区间 `[i,j)` 的风险跨度为 `x_j-x_i`，回溯得到的切点是节点索引，不是再加一后的边索引。

并列最优按四个切点的字典序选择最早组合。不能简单认为“取当前最小前驱 i”就等价，也不能在每一层累积使用一次 tie 容差，最后超过总目标的允许误差。

具体实现：先计算各起点、剩余段数的后缀最小代价，得到完整最优值；再从左向右选择最早的合法切点，要求“已采用代价 + 当前段代价 + 最优剩余代价”不超过完整最优值加一次全局 tie 容差。选中后递推，最终再次复核总目标。这样将全路径字典序与总容差放在同一个契约中。

前缀和让区间查询 O(1)，总计算仍为 O(5J²)。不构建 J×J 的区间代价矩阵；保存 O(5J) 的后缀 DP 状态及少量切点，空间 O(5J)。

### 10.3 近直线与稀疏曲线

当且仅当当前显式选择的是 `frontier_shape_dp_v2`，且全体有效角度变化小于版本化阈值（上位文档初始值 0.02 弧度），该算法内部采用明确记录的累计弧长 20／40／60／80% 切分作为**近直线退化处理**。这与用户主动选择 `equal_arclength_v1` 是两个不同语义：前者仍记录主算法为 `frontier_shape_dp_v2` 并附 `fallback_reason=near_linear_frontier`，后者直接记录弧长等分算法。

取满足最少边数与最小跨度的四个不同有效节点；若最近点局部选择冲突，使用受约束的有序切点选择，不按独立四舍五入制造重复边界。

DP 无合法解且不满足近直线条件时，返回 `SEGMENTATION_INSUFFICIENT_RESOLUTION`；不能无提示切换等波动宽度或人工阈值。

### 10.4 稳定性复核

同一冻结输入分别求 101 点和 200 点前沿。边界比较使用同一组已核验端点作为标准化尺度，先检查两次端点一致性；不能各自随意缩放后掩盖端点漂移。

\[
\Delta_b=\max_{k=1\ldots4}\frac{|b_k^{101}-b_k^{200}|}{\sigma_{right}-\sigma_{GMV}}.
\]

超过初始复核阈值 0.02 时，输出 `unstable_calibration`。用户可以调整输入、提高来源质量，或由有权限维护者记录复核理由后采用明确标记的版本；自动模式未经确认不得设为默认。该测试只是网格稳定性，不是模型样本外有效性检验。

默认采用 101 点结果，200 点用于验证。人工选择采用更密结果时也要明确记录，不能后台交换发布边界。

### 10.5 分类区间与数值契约

上限 `0 <= b1 < b2 < b3 < b4 < b5`；不得出现倒置或重复上限。自动模式须满足最小分段跨度，b5 为前沿右端风险。人工模式 b1=0 表示 C1 仅包含零风险点，并非数据缺失；其下游可用性须另查零上限支持能力。

```text
C1: [0, b1]
C2: (b1, b2]
C3: (b2, b3]
C4: (b3, b4]
C5: (b4, b5]
大于 b5: above_scale
低于参考 GMV: 保留 C1，并附 below_reference_range
NaN／无可比口径: unavailable，而不是 C1
```

恰好等于边界属于较低档。固定比较容差同时作用于“是否属于某档”和“是否超过授权上限”；只要一个组合被分类为不超过 C3，就不能被同口径的 cap 检查判定超限，反之亦然。对差值在容差内的贴边点记录 `within_boundary_tolerance`，不依赖显示舍入。

不能将上限之外风险钳制到 C5，不能将不合法负波动取绝对值，不能将零方差视为计算失败；零方差可以分类为 C1，但可能无法支持完整前沿分档。

### 10.6 人工阈值

人工模式保存五个严格递增、首项非负的上限、来源和说明；来自自动覆盖时还保存自动值。重复、倒置或负上限拒绝，并给出字段错误。零上限不偷偷改为一个小正数；若目标消费者不支持，应显示“零上限尚不能用于该目标接口”，保留正确的标尺内容。

超过参考最大风险的部分标为 `not_calibrated`。某档在可用前沿内没有有效节点时，代表权重、收益和画像均为空并附原因，不取邻档组合冒充。

手工阈值可以有外部政策依据，但系统不据此认证适当性。当前研究只实现数字授权，不能将人工说明转换成尚未执行的风险保证。

### 10.7 代表组合

按实际分类区间选取有效节点，再取档内累计弧长的中位节点。边界点属于较低一档，高一档的代表选择必须排除该点，避免表内出现代表风险不属于本档的情况。

代表点仅用于解释；不是该档中风险最高、回撤最大或唯一可持有的组合。

## 11. 参考画像：波动、ES 与回撤

### 11.1 基础指标

每档基础展示为参考 CMA 下的代表组合年化预期收益及波动：

\[
\mu(w)=w^\top\mu,\qquad \sigma(w)=\sqrt{w^\top\Sigma w}.
\]

对浮点级微小负方差按已验证容差处理；明显负值作为矩阵或计算错误，而不是开方前全部截零。

### 11.2 历史画像

第一版支持共用真实收益面板上的历史 VaR／ES 与历史 MDD，置信水平默认研究设置为 95%，并在表中显示实际观察频率与样本区间。

参考权重的历史回放需冻结独立的组合再平衡规则：与“类内 Proxy 再平衡”不是同一个层次。可默认按月重设大类代表权重并明确标注。无数据或存在持有期缺失时，相关画像返回 unavailable，不能用剩余资产补齐。

冻结权重来自当前参考研究时，这一历史回放是事后参考组合画像，不声称当时已确定该组合。

每日历史 ES 不乘 sqrt(252) 后称为年度 ES；年度、月度、模拟与压力画像分别拥有自己的指标契约。

### 11.3 经验 ES 的一致实现

损失定义 L=−R，正数越大表示损失越大。设 B 个等权损失样本降序排列为 `L_(1)…L_(B)`，`q=(1-alpha)B`，`k=floor(q)`，`f=q-k`：

\[
ES_\alpha=\frac{\sum_{i=1}^{k} L_{(i)}+fL_{(k+1)}}{q}.
\]

f=0 时不读取下一项；0<q<1 时取最大损失。该分数尾部规则与上位文档的经验 CVaR 优化表示一致。VaR 使用冻结的经验逆分布分位数规则，不能展示与门禁各调用不同插值方法。

尾部样本不足时保留技术计算值与“不足以稳定估计”的状态，并按画像质量策略决定是否展示数值；不把单个样本当作可靠尾部估计。所有收益为正时 ES 可能为负，保留其含义，不把负 ES 直接改成零。

排序使用结果专属损失缓冲区，不能原地排序只读收益面板。

### 11.4 回撤

\[
MDD=\max_t\left(1-\frac{V_t}{\max_{u\le t} V_u}\right).
\]

V 使用剔除外部现金流影响的参考市场净值，包含初始净值作为首个峰值候选。资金支付造成的余额下降不是市场回撤。

仅给定 mu／Sigma，不能得到唯一真实 ES 或 MDD。参数分布、Monte Carlo 与压力画像列为可扩展能力；未实现或缺模型时显示未计算，不自动假设正态、不在本模块新建另一套情景引擎。

### 11.5 下游意义

画像用于理解参考组合。除非下游求解与最终门禁明确消费了相同指标、期限、置信水平和来源，否则它们都不是硬约束。

缺少可选历史 ES 不必否定一个数学上有效的波动标尺；但必须显示未提供画像。低风险锚、CMA 合法性等默认资格的必需证据缺失则不能被当作可选警告跳过。

| `backend/optimizer.py` | 历史准备与共用矩参数前沿的衔接 | 抽取数值入口；非二次风险历史能力保留 |
| `backend/services/strategic_allocation_routes.py` | 注册 risk-scales 子路由 | 扩展，不重复相同 URL |
| `backend/sensitivity/repository.py` | 不可变成果与受控数组 | 复用；所需通用幂等／恢复补齐在此层 |

共享 AssetClass／Proxy 的具体契约进入既有战略范围领域；不要在 `risk_scale_contracts.py` 中复制一份资产／代理定义。扩展需要与投前大类当前消费者成对设计，并有兼容测试。

前端目标拆分：`RiskScaleCenter`、`RiskScaleWorkspace`、`RiskScaleVersionView`；细分组件承担来源选择、分档编辑、前沿、画像与发布摘要。共用 AssetClassProxyEditor 和 CMA 编辑组件从现有领域抽取，不从一个路由页面直接嵌入另一个路由页面。

### 12.2 算子颗粒度审查

| 计算语义 | 类型 | 为什么这样划分 |
|---|---|---|
| 相邻收益、FX 变换、统计矩、PSD 检查 | 共用基础算子 | 可独立替换、预览与测试，不绑定风险中心 |
| 代理持有与再平衡递推 | 状态内核／共用组合步骤 | 权重漂移依赖上一期；I/O、时点选择在外围 |
| 线性约束 QP／LP | 耦合内核 | 权重、活跃集、乘子联立迭代；按残差／预算终止 |
| 前沿目标扫描 | 组合计算计划 | 目标生成、端点、逐点求解、检查可分开追踪 |
| 五段 DP | 耦合内核 | 分段状态依赖前驱最优值；有限网格回溯终止 |
| 分类、cap 比较、画像 | 基础／组合步骤 | 不需要共同拟合，不封成一个不可拆的大黑盒 |

每一项回答 AGENTS.md 的四问：只解决什么问题；中间结果能否使用／替换；是否已有等价算子；继续拆分是否破坏状态或数值语义。上表是本需求设计记录，详细注册沿用统一注册契约，不能把具体实现清单塞进 AGENTS.md。

执行层允许共享一次收益扫描或缓存结果，但用户仍可分别查看风险矩、前沿点、分档边界与画像来源。

### 12.3 能力表

后端返回当前进程真正具备的来源类型、CMA 方法、矩语义、约束、分档方式及画像指标，同时返回不可用原因和 readiness。

不支持的能力在前端显示“尚不可用”，不换成其他模型执行。已有 BL 方法不意味着所有跨币种输入均已支持；固定签名已注册也不意味着 worker 已预热。

## 13. 高性能、内存与运行边界

### 13.1 NJIT 执行原则

全部本项目数值路径包括收益构造、权重漂移、历史统计、年化、矩检查、前沿、DP、分类、ES／回撤均使用已预热的 NJIT 内核。Python 只负责 I/O、参数校验、边界转换、调用编排与结果封装。

显式签名采用稳定 float64／int64、固定 rank、受支持的只读布局；生产禁止新签名编译、object mode 与 Python 回退。Numba 文档区分有签名编译与无签名惰性编译；仅写 `@njit` 或启用磁盘缓存都不能替代进程 readiness。[E1]

请求开始检查当前 PID 的内核清单与编译指纹。每个 API worker 及实际数值 worker 启动时均预热生产计划并冻结编译；重启后重新验证，不沿用父进程“已就绪”的声明。

默认 `fastmath=False`。输入索引范围在边界验证；测试额外启用 boundscheck 覆盖越界，不能为了速度接受不受控裸指针。

### 13.2 数组契约

| 数据 | 运行时契约 | 所有权 |
|---|---|---|
| 原始解码数值／共同收益 | float64，二维；时间升序，稳定资产轴 | 规范化后只读 |
| 日期／轴索引／来源编码 | int64；映射随版本冻结 | 只读 |
| 有效性／状态 | 固定整数编码；缺失与 0 收益分开 | 输入只读，输出独占 |
| mu／Sigma／约束系数 | float64；参数在调用边界确认布局 | 只读 |
| 前沿权重、指标、DP 回溯 | float64／int64，紧凑结果数组 | 当前计算独占，发布后只读 |
| KKT／梯度／排序缓冲区 | float64／int64 | 任务独占，生命周期内复用 |

现有 ArtifactRepository 只支持 float64／int64 的 C 连续 NPY。第一版持久化有效性与状态使用 int64；若日后引入 uint8，应在共用存储扩展并做兼容验证，不能本模块偷偷保存后又无法读取。

只读基础数组 + start/end/index 传入内核。连续区间采用基本切片，非连续共同日期优先传索引数组间接访问；不在每个前沿点、档位或窗口做 `R[mask]`。NumPy 的基本切片与高级索引有不同复制语义，不能由 `copy=False` 推断整条链零拷贝。[E2]

### 13.3 必要复制清单

| 边界 | 为什么可能复制 | 控制措施 |
|---|---|---|
| Parquet／外部格式解码 | 数据不一定已在所需 dtype／布局 | 按所需列和区间读取，一次规范化后复用 |
| 排序、同轴对齐 | 某些输入不能形成连续视图 | 优先索引访问；确需物化时只构建一份规范化面板 |
| 固定签名布局适配 | 非兼容布局不能现场编译 | 已支持 A 布局时直接使用；否则明确的一次最小复制 |
| 求解权重与工作区 | 需要修改迭代状态 | 结果与工作缓冲区独占，不改只读输入 |
| ES 排序 | 原收益不可原地排序 | 只复制该代表组合的损失输出，不复制所有原始资产 |
| 发布 NPY | 需要持久化快照 | 仅显式确认后执行，已有面板引用不重复保存 |

结果数组的分配合法，零拷贝不是“不分配输出”。`np.shares_memory`、写保护、别名与生命周期测试必须落在真实调用路径上。

### 13.4 避免重复计算

CMA 矩每次来源版本只读取／校验一次；矩参数前沿不为每个目标重新计算协方差，也不逐点回放全部历史收益。

五档画像只针对所需代表组合计算；没有打开或请求的模拟／压力画像不执行。修改人工阈值复用同一前沿结果，更新档位归属和必要代表画像。

缓存键包含完整来源与算法契约：数据快照、资产与 Proxy、CMA、约束、日期／口径、数值版本、分档参数、画像规则。不可仅用方案名、截止日或字符串 C3 作键。

预览缓存只在内存中有界保存，受总字节与生命周期控制；未命中可重新计算，不能自动落盘。发布版本直接读取冻结结果，不打开即重算。

仓库读取数组当前会校验文件哈希；一次任务集中读取所需数组并持有其所有者，避免每个网格点重复调用 `arrays()`。不能为了缓存速度跳过损坏检查或让卸载磁盘后的旧输入伪装为新来源。

### 13.5 复杂度与内存量级

主要规模：原始代理成分 P、历史 T、大类 N、前沿点 G。主要计算为代理构造约 O(TP)、共同统计 O(TN²)、G 次小型 QP、分档 O(5G²)；复杂度还受活跃约束与迭代数影响。

数组量级示例，仅是尺寸计算，**不是实测峰值内存**：

| 数组 | 示例维度 | 原始字节／量级 |
|---|---|---|
| 五年日频大类收益 | 2520×30 float64 | 604,800 字节，约 0.58 MiB |
| 参考协方差 | 30×30 float64 | 7,200 字节 |
| 200 点权重 | 200×30 float64 | 48,000 字节 |
| 五段 DP 主要状态 | 5×200 float64 | 8,000 字节，基例与边界单元另计 |

原始成分面板、有效性数组、解码、解释器／JIT／BLAS、文件页缓存均另计，不能用上表声称整个进程只消耗几 MB。

N≤30、G≤200 继承现有上限。新增资源策略必须同时约束 P、T、总输入元素、总字节、总迭代和并发，而不是只限制 N。建议起始策略为 P≤300、T≤10000、输入面板总元素≤3,000,000；这些是待实测调整的资源配置，不是新增金融限制。

预检返回估算工作区和超限维度。超限时让用户明确缩减范围，不静默减少产品、样本或网格点。输出也按总字节约束，遵守现有单数组 256,000,000 字节存储边界。

### 13.6 并发、取消与超时

第一版采用现有服务内的有界同步计算入口；FastAPI 编排不阻塞事件循环，数值调用经受控执行通道运行。不为这一个小型前沿新增 Celery、独立微服务或通用任务平台。

设置数值并发准入与内存预留，容量不足返回带重试指引的 busy 状态。普通列表／只读详情不等待大规模计算槽位。

默认不对 N≤30 的网格盲目启用 prange；先利用可行热启动与缓冲区复用。并行只能在同机、同输入下证实更快且等价后启用，并控制 BLAS／Numba／worker 线程总量。

取消与计算预算在网格点、阶段或固定迭代批次检查。线程中运行的 NJIT 不能通过 HTTP 超时被安全强杀；任务真正结束前不能释放共享输入所有者或内存预留。硬终止需求必须走已预热且受监管的进程执行器，不能在超时后留下无人管理的线程。

若后续接入多进程，传递 mmap／共享内存描述符和范围；不重复 pickle 整个 R。进程退出、失败及超时释放由单一所有者管理。

### 13.7 可验收的性能要求

必须记录冷启动／预热、取数、矩准备、端点、网格、分档、画像、持久化各阶段时间与内存；不能把 JIT 预热排除后又宣传首请求性能。

基础硬门槛：请求新增编译数为 0、Python fallback 为 0、预览持久化写入为 0、只读输入修改为 0、重复请求无无界内存增长。

性能基准至少包括 N=5／10／30、G=101／200、不同 T/P、重复约束、PSD 现金和非连续输入。端点／DP 的新实现没有历史线上基线时，先建立可重复基准；只对同算法同负载的优化要求“不显著退化”。本设计不承诺尚未测量的毫秒级或固定倍数加速。

## 14. API 契约

### 14.1 路径与动作

统一前缀 `/api/strategic-allocation`，沿用上位文档，不再增加另一套 `/api/settings/risk-levels`。

| 方法／路径 | 行为 |
|---|---|
| `GET /risk-scales/capabilities` | 已就绪能力、限制、不可用原因 |
| `GET /risk-scales` | 方案／版本摘要、兼容筛选、游标分页 |
| `GET /risk-scales/defaults` | 当前口径默认引用及当前资格 |
| `POST /risk-scales/compare` | 两个精确版本 → 口径兼容性、输入变化、数值边界差异；不写成果 |
| `POST /risk-scales/drafts` | 显式保存新草稿，不产生发布成果 |
| `GET/PATCH/DELETE /risk-scales/drafts/{draft_id}` | 草稿读取／乐观锁更新／明确删除 |
| `POST /risk-scales/preview` | 完整输入或草稿 revision → 计算结果与哈希，不写正式成果 |
| `POST /risk-scales/confirm` | 重验预览并发布不可变版本 |
| `GET /risk-scales/{id}` | 读取冻结版本，不重新拟合 |
| `POST /risk-scales/{id}/activate` | 更新对应默认引用，不修改版本 |
| `POST /risk-scales/{id}/retire` | 停止新引用的治理动作，历史保持可读 |

固定路径先注册。若默认版本被停用，必须在同一治理操作中换到明确指定且合格的版本，或显式确认清空该默认；不能自动挑另一套。

比较页读取两个版本并比较元数据；数值边界差异通过同一后端比较能力计算，不为方便在前端维护第二套分类函数。资产／Proxy／CMA 的预览与确认复用其共用接口，不再在 risk-scales 下复制模型 API。

### 14.3 响应与确认

预览返回：`request_echo, resolved_refs, data_fingerprints, result, diagnostics, limitations, mathematical_status, publication_eligibility, application_eligibility, execution_audit, preview_hash`。

`preview_hash` 覆盖确定性输入、冻结来源、采用结果、算法与数值策略；排除耗时、请求 ID、PID 等波动字段。NaN／Inf 不作为 JSON 数字输出，采用空值加状态；哈希前不按展示精度舍入。

确认请求必须包含明确 `confirm=true`、同一输入／draft revision、`preview_hash`、需要的警告确认和幂等键。确认期间重新读取并核验引用；来源或采用结果变化返回 409，不自动发布“差不多”的新结果。

允许任务内缓存避免重复昂贵工作，但确认不能仅信任客户端曲线或未经核验的旧缓存。不同运行环境导致重算结果变化时要求新预览，不用模糊哈希消除冲突。

### 14.4 错误与 HTTP 状态

| 状态 | 示例 code | 语义 |
|---|---|---|
| 422 | `RISK_SCALE_BANDS_INVALID`、`CMA_BASIS_MISMATCH` | 字段或业务输入不合法 |
| 409 | `PREVIEW_STALE`、`REVISION_CONFLICT`、`DEFAULT_CHANGED` | 输入／状态已变，需重新核对 |
| 403 | `RISK_SCALE_OPERATION_FORBIDDEN` | 缺少真实服务端权限 |
| 404 | `RISK_SCALE_VERSION_NOT_FOUND` | 指定版本不存在，不替换最新 |
| 503 | `COMPUTE_NOT_READY`、`COMPUTE_BUSY`、`STORAGE_UNAVAILABLE` | 执行或存储暂不可用 |
| 200 的结果状态 | `DEGENERATE_FRONTIER`、`iteration_limit`、`unstable_calibration` | 请求合法但研究未满足发布条件，保留诊断 |

所有错误含 `code, message, field_path, details, suggested_action`。失败不返回伪造数值；数值不收敛不转换成 HTTP 500 未说明异常。

请求模型和前端类型从同一 Pydantic／OpenAPI 契约生成；类型生成变化纳入检查，避免手写两套枚举和边界规则。

## 15. 存储、并发发布与可维护性

### 15.1 复用真实存储能力

RiskScaleVersion 保存为现有 `kind=series`，通过 `artifact_type=risk_scale` 区分。不能直接向当前只接受既定 kind 的 `save()` 传入 `risk_scale`。

元数据与小型五档结果保存在 manifest，前沿权重／状态等数值通过 NPY 存储。已有 ReturnPanelVersion 和 CMA 数组只保留内容寻址引用，不在每个标尺复制一遍原始数据。

新列表需要的 `artifact_type, scheme_id, version_number, base_currency, risk_basis_id` 等字段，应通过共用摘要契约有界扩展；当前 SUMMARY_KEYS 未包含这些内容。已有记录允许缺字段并保持旧消费者行为，不能假设字段早已存在。

### 15.2 预览、草稿和成果写入分开

`GET` 与 `preview` 不创建目录、锁文件、正式 artifact 或模型结果文件。预览不自动保存来源快照；首次使用的数据来源若需冻结，由明确的上游确认动作完成。

“保存草稿”是用户授权的独立写入，只保存定义与引用，不把当前预览当作发布结果。已保存草稿带 revision，修改不能覆盖别人更新。

所有写入经受控数据磁盘 `guard_path`，禁止磁盘离线后回落到项目 data 目录建立另一套数据库。日志、异常和导出不暴露源凭据。

### 15.3 幂等与中断恢复

现有仓库的“目录 rename + index 更新”并非跨文件原子事务。需在共用存储层设计受控的发布幂等记录，不能在风险服务里临时拼第二套文件事务。

建议流程：

1. 校验幂等键与规范化请求哈希；同键不同请求返回冲突。
2. 在短锁内预留成果 ID 与操作记录，计算不持锁；重试复用这条记录。
3. 完成匹配的校验后，按既有受控暂存目录写入数组与 manifest，校验并提升。
4. 在索引锁内登记摘要及完成状态；完成后才对调用者报告发布成功。
5. 中断发生在目录提升后、索引完成前，恢复只检查该操作预留的成果目录、哈希及状态，再完成登记；不重新生成一个随机 ID，不全盘扫目录冒充普通查询。

这要求对现有 `save()` 提供通用幂等／恢复扩展；当前随机 ID 接口不能直接保证上述行为。失败清理只能作用于本操作拥有的暂存路径，不能删除已经被引用的完整成果。

### 15.4 默认切换与退休

默认绑定、修订号和本次治理记录在同一 AtomicJsonStore 文档里原子更新，并带 `expected_revision`。同兼容键的两个并发切换最多一个成功。

先确认版本已完整发布且具备当前资格，再切默认。不能将“发布 + 激活”伪装为跨多个文件的一次不可分割操作；发布成功但激活冲突时，应清楚展示“版本已发布，默认未改变”。

引用资格在服务端按版本、时间、权限、来源有效性计算；默认指针、页面缓存或 journey 中保存的 ID 都不构成资格证明。

### 15.5 版本、复核与停用

后台刷新市场数据只提示“有更新可用于重新校准”，不改当前版本。重新校准、修改人工阈值或改变风险语义均产生新版本。

复核到期默认显示待复核；是否禁止新引用由冻结治理策略决定，必须在设置与目标选择器一致显示。硬失效、退休和数据损坏拒绝新引用，不默认为最新版本。

历史 Mandate 中的原始数值授权不会因默认切换而变化；历史审计仍可读取。当前应用是否需要重新复核另行计算，不把“历史可读”误认为“可以新采用”。

### 15.6 技术债控制

不新增私有 CMA、历史统计、QP、分位数或回撤公式。共享接口只抽取真实调用需要的语义，不预建无人消费的万能插件架构。

新代码不保留 `old/legacy/backup` 算法副本。旧入口若确有兼容契约，只做薄适配并委托唯一执行实现；兼容到期清理路由、导入、类型及失效测试。历史产物通过其契约版本只读，不因代码清理重写历史数值。

已存在的自动分类、历史非二次风险前沿、单 CMA 政策等能力不是本次设计的删除范围。共享改造实施时，对受影响调用明确列回归，不以统一为由缩减用户能力。

## 16. 与投资目标、SAA／TAA 的接入契约

### 16.1 投资目标新增引用

```text
risk_scale_ref: {version_id, content_hash}
risk_authorization_mode: scale_cap | explicit_numeric | reference_pending
authorized_max_level: C1...C5（scale_cap 时必填）
authorized_volatility_cap: float64（后端从版本解析并冻结）
risk_basis_snapshot: {currency, semantics, period, annualization, tolerance}
authorization_source / confirmed_by / confirmed_at
```

用户选择等级后，后端解析 cap，并在保存前核对数值与版本，不接受客户端随意把 C3 的上限改大。

`scale_cap` 与 `explicit_numeric` 是明确模式：已有数值授权按原契约保留；采用标尺时选择其上限，不能同时让一个隐藏的历史 `max_volatility` 默认值覆盖它。用户需更严格的限制时使用显式附加上限，并记录实际 cap 为适用上限的较小值及其来源。

缺少匹配标尺时允许 reference_pending，不偷偷采用现有 MandateRequest 的 0.15 默认值宣称已获得风险授权。对旧字段默认值的迁移必须区分旧请求与新模式，并做契约测试。

当前旧 Mandate 上限字段要求大于 0；零风险数值授权等边界不能用一个 epsilon 悄悄替换。是否支持这类新增授权须显式扩展消费者契约；零风险实际组合的分类仍可正常返回 C1。

### 16.2 一次清楚的使用体验

用户在投资目标选择“人民币多资产参考 v3 / 授权不超过 C3”。页面展示真实 cap 及来源，用户不需要理解 QP 或 DP。

SAA 计算后另行显示“实际估计等级 C2”。这不是冲突，也不需要为“达到 C3”主动增加风险。

上游默认升级到 v4，原目标继续引用 v3。只有用户显式升级并重新确认，才生成新的 MandateVersion；旧政策和 TAA 不被后台改写。

### 16.3 实际资产范围与参考范围

实际 SAA 的大类可以不同于 Universal，因此不强制两个投资宇宙完全相同；但风险比较必须具有兼容币种、期限／年化定义和风险语义。

实际风险用本次真实 CMA 计算，再对照标尺阈值。不能把参考 CMA 协方差硬贴到不同资产轴，也不能认为同一波动等级自动有相同 ES／回撤。

单／多 CMA 后续门禁继承上位设计，本模块只输出完整标尺及授权引用，不承担多 CMA 联合求解。TAA、产品实施仍需用其实际风险契约重新检查。

### 16.4 投前大类复用方式

“引用系统参考资产版本”直接复用只读 AssetClass／Proxy 引用；“基于参考资产调整”建立新的草稿，确认后形成新版本。不能无提示复制全部历史数组，也不能让研究员编辑一份公共对象后改变全系统标尺。

### 17.1 按依赖分步落地

|---|---|---|

A–D 是风险等级中心主体，E 是其成为投资目标基础的最小闭环。没有 E，页面即使能发布，也不能宣布完成了“目标基于标尺”的业务接入。

开发期间只为真实已实现的能力标记 available；未完成接口不能用示例图或静态阈值包装为可用默认。

### 17.2 第一版与延后项

第一版覆盖多方案、指数／产品代理的共用契约、可执行参考 CMA、自动与人工分档、基础历史画像、不可变发布及目标引用。

若环境缺特定市场／币种数据，则来源能力明确不可用，不伪造；不要求因此在本需求扩展所有外部数据接口。尚未实现的 NIW 不阻塞已有方法，但不能标为完成。

先不做新模拟引擎、自动定时重校准、复杂组织默认继承、风险问卷、跨标尺等级自动翻译、GPU、分布式求解或交易联动。需要这些能力时作为独立需求，并复用已有领域服务。
