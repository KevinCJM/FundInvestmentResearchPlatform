# 投前产物的版本与依赖管理

> [投前研究](README.md) · 本页规定投前各模块方案产物的版本、依赖钉住、可用性和列表展示口径。设计日期：2026-09-23。

## 为什么需要统一口径

投前研究是一条链：上游产物被修改或删除后，下游产物仍指向旧版本。此前各模块各自判断"当前版本"，同一件事表现不一致。例如，范围改版后 LTCMA 列表显示"旧版本"但仍可选；目标改版后列表无提示，进入 SAA 才报错；SAA、TAA 和研究包列表完全不显示上游状态。本页用一套规则替代这些分散判断。

## 依赖图

箭头表示"下游钉住上游的某个精确版本"。

| 步骤 | 方案产物 | 直接上游（钉住 id 与内容 hash） | 版本来源 |
| --- | --- | --- | --- |
| 设置 | 风险标尺版本 | 参考输入 | `scheme_id` + `version_number` |
| 01 | 投资目标与约束 | 风险标尺版本 | `supersedes_mandate_id` 链 |
| 02 | 战略范围（Strategy first） | 投资目标与约束 | `supersedes_universe_id` 链 |
| 02 | 产品范围（Product first） | 投资目标与约束、产品池版本 | `supersedes_snapshot_id` 链 |
| 03 | LTCMA | 研究范围（目标经范围推导）、先验 LTCMA、历史情景运行 | `supersedes_cma_id` 链 |
| 04 | SAA 方案 | 投资目标与约束、LTCMA（一个或多个） | 不可修改，每份为 v1 |
| 05 | TAA 决策 | SAA 方案 | 不可修改，每份为 v1 |
| 06–09 | 研究包及验证、定稿 | SAA 方案或 TAA 决策（同时冻结目标、LTCMA、实施映射） | `scheme_id` + `revision` |

历史目标中的 `strategic_universe_id` 是旧版"授权范围"，不属于上面的主链，原有校验保持不变。

## 版本模型

每个产物都带一个 `version`，全部从已保存记录派生，不改写任何冻结字节，也不改变内容 hash：

| 字段 | 含义 |
| --- | --- |
| `lineage_id` | 系列 ID：同一产物所有版本共用，取首个版本的 id；风险标尺、研究包沿用 `scheme_id` |
| `number` | 版本号：v1 起，按修改链递增 |
| `status` | `current` 当前 / `superseded` 已被新版本替代 / `retired` 已删除 |
| `latest_id`、`latest_number` | 同系列当前版本，系列已删除时为空 |

不可修改的产物（SAA 方案、TAA 决策、参考输入、历史情景运行）每份即一个 v1 系列，只有状态没有演进。

## 依赖引用

列表中每个产物用 `upstream` 列出直接上游，每项包含上游类型、id、名称、钉住的版本号、同系列最新版本号和状态：

- `current`：钉住的就是当前版本。
- `superseded`：上游已有新版本，钉住的是旧版。
- `retired`：上游已删除；`missing`：上游无法读取，与已删除同等对待。

## 可用性规则

每个产物另带 `usable`，前后端使用同一结果：

| 状态 | 条件 | 能否查看 | 能否接入新的下游工作 |
| --- | --- | --- | --- |
| `ready` 可用 | 自身为当前版本，直接上游均为当前且上游自身可用 | 能 | 能 |
| `stale` 需更新 | 自身已被替代，或任一上游已有新版本，或上游本身需更新 | 能 | 不能；需基于最新上游修改或重建 |
| `blocked` 已停止引用 | 自身已删除，或任一上游已删除、缺失，或上游本身已停止引用 | 能 | 不能 |

规则要点：

1. **钉住，不跟随。** 上游出新版本时下游不自动改指向，历史结果可复现、可审计。
2. **可用性沿链传递。** 例如目标改版后，范围、LTCMA、SAA、TAA、研究包依次显示"需更新"。
3. **升级即产生下游新版本。** 在下游的"修改"中改选同系列最新上游并保存；不可修改的产物（SAA、TAA）通过新建完成。范围修改允许把绑定目标升级为同一系列的当前版本；换成不同系列的目标仍需复制为新研究。
4. **删除按系列生效。** 删除当前版本后整个系列停止引用，下游自动变为"已停止引用"。旧版本仍保留 `superseded`、原编号与内容 hash；当前版本为空时，其派生可用性为 `blocked`，不能提示升级到不存在的版本。
5. **后端是最终口径。** 列表提前置灰并写明原因；保存、计算接口在后端再次校验，不以前端禁用代替。

### 等价改版例外

战略范围只改说明等非配置内容、`scope_fingerprint` 不变且各大类权重上下限相同时，旧版本与当前版本视为等价：引用旧版本的下游不因此变为"需更新"，列表以中性色提示"已有新版本 vN · 配置相同"。未设置边界与显式 0–100% 等价。收益估计指纹仍不包含配置边界，便于比较估计口径；生命周期另外核对保存的权重边界，不能仅凭指纹放行。此核对也适用于已有记录，不改写历史 hash。目标与 LTCMA 暂无配置指纹，任何修改都视为实质改版。

### 风险标尺例外

风险标尺有自己的默认绑定和有效期治理：同一方案发布新版本不使旧版失效。目标引用的标尺只在已停用或过期时影响可用性，有新版本仅作提示；原有 `application_blockers` 软提示保持不变。

## 列表展示

所有方案列表统一展示：

- 自身版本号 `vN` 及状态徽标；非当前版本注明"当前为 vK"。
- 直接上游名称（可点击进入只读页）、钉住的版本号和状态徽标。
- 不可接入下游的行写明原因，并禁用"选择 / 下一步"。

| 列表 | 展示的上游 |
| --- | --- |
| 01 投资目标与约束 | 自身版本 |
| 02 研究路径与范围 | 投资目标与约束 |
| 03 LTCMA | 按"目标系列 + 范围系列 + 版本"分组，组头展示目标与范围版本 |
| 04 SAA 方案 | 投资目标与约束、研究范围、LTCMA |
| 05 TAA 决策 | SAA 方案 |
| 06–09 研究包 | 来源 SAA 方案或 TAA 决策 |

LTCMA 多选仍要求同一目标、同一路径、同一范围版本；可用性不为 `ready` 的 LTCMA 不能选择。

## 实施状态

2026-09-23 第一期已落地：

- 后端共享派生模块 `backend/strategic_allocation/versioning.py`（`ResearchVersions` 一次扫描战略侧存储，产品范围按需加载），契约类型在 `common_contracts.py`。
- 列表接口返回 `version`、`upstream`、`usable`：目标与战略范围（`/catalog`）、产品范围（`/investable-universe-snapshots`）、LTCMA（`/cma`、`/catalog` 的 assumptions）、SAA 方案（`/policies`）、TAA 基线与决策（`/tactical-allocation/catalog`）、研究包（`/pre-investment/packages`）。
- 后端拦截：LTCMA 进入 SAA 或作为先验时拒绝需更新版本（`CMA_NOT_CURRENT`）；新的 TAA 预览与保存拒绝需更新或已停止引用的 SAA 方案（`TAA_BASELINE_NOT_CURRENT`、`TAA_BASELINE_BLOCKED`）；研究包验证沿用已有的当前性检查，因此随 LTCMA 规则一并收紧。
- 范围修改可把绑定目标升级为同系列当前版本（`checked_scope_mandate(allow_upgrade=True)`）；前端编辑页提供"改用最新版本"。
- 前端共享组件 `frontend/src/components/versioning.tsx`，各列表按上表展示；SAA 选择 LTCMA、TAA 选择 SAA 基线时置灰不可用项。

行为变化：此前已被替代的 LTCMA 版本仍可被精确引用进入 SAA，现在只能查看。

未纳入第一期：风险标尺与参考输入列表的上游展示、产品池版本作为产品范围上游的状态、先验 LTCMA 与历史情景运行在 LTCMA 列表中的上游展示、"一键基于最新上游重建"按钮（当前通过各模块已有的修改与复制入口完成）、原有分散的"当前版本"判断尚未全部改为调用共享模块。
