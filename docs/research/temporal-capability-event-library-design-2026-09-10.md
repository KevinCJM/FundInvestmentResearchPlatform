# 情景时点能力与全球历史事件库：详细设计及验收

## 1. 需求与边界

两个目标：让系统根据实际依赖、参数、执行方式和数据可得性解释“能否实时使用”；把历史事件从单个算法的大段配置提升为可复用、有修订和出处的研究资产。保留已有图谱、接口字段、运行快照和人工事件闭区间语义。不改变指标数学公式，不自动迁移已保存定义，不把审计通过解释为盈利保证或统计因果证明。

这次实现包括：轻量时点推导、显式的真实 NJIT 图谱审计、预览/正式运行报告和发布门禁、事件库维护/筛选/事件包/版本锁定引用、现有人工事件的可重复导入。外部数据库自动下载、实时新闻抓取、重大事件自动定界、事件收益归因不属于本次范围。

## 2. 核对现状

- Regime Graph v2 已有注册表、端口类型、DAG 依赖、prepare 固定签名计划、预览任务、不可变正式运行和发布门禁。
- `causality/probes.py` 已有 P1 尾部扰动、浮点灰区与未知判定、P3 历史长度敏感性。`causality/audit.py` 的算子基线和公式审计主要针对 typed DSL，不能直接把它的 Python 参考执行器放进生产请求。
- `window_consuming` 是调用窗口义务，不等于事后；P3 预热敏感不是未来泄漏。有限探针只能发现反例或形成已覆盖样本证据，不能证明所有输入安全。
- 情景中心在目录、infer、运行和前端重复读取 causal/repaints/supports_realtime，混淆数学因果、时间可得性和事后语义。新逻辑集中为一个时点能力解析器，旧字段只保留为兼容投影。
- 人工事件以 events 数组存入定义，每项包含 id/label/start_date/end_date/color/description；区间可重叠，数值内核使用稀疏边界。保留这条数值链路，不增加第二套事件计算。

## 3. 产品模型

### 3.1 三件不同的事

1. 计算方式：按当时信息计算，或全样本事后研究。用户仍可切换，不由界面悄悄重跑。
2. 能力结论：可按当时信息试算、需满足条件、仅事后、未验证。运行后才能给出“本次审计通过”。
3. 用途许可：研究展示、产品研究、正式回测、TAA。能力结论不替代现有完整发布门禁。

事后结果不是错误。人工标签显示“正确的事后用途”，而不是红色报错。UNKNOWN、样本不足、任务取消、探针未覆盖都不能变成通过。参数、输出、图、执行模式、数据快照任一变化后，不复用旧证据。

### 3.2 前端布局

工作台保留左侧算法库与右侧“算法定义/校验与预览”。在预览运行按钮下放一张紧凑的“时点能力”卡：一句话结论、关键原因、查看证据、定位节点。详细面板才展开计算因果/数据时点/历史重绘/事后语义；注明数值探针覆盖与局限。编辑时只调用纯推导，点击“因果性审计”才启动真实执行探针，避免每次输入窗口都计算多遍。

前端不能自行按算子名字决定实际图谱资格。后端返回每个输出的结论和阻塞路径；诊断旁支不污染不依赖它的主输出，但被选择为运行输出或比较目标的旁支照常受门禁。候选资源的事后提示只用于告知，不伪装为已验证实际图谱。

情景中心增加“全球历史事件库”页签。默认：搜索栏 + 类别/地区/时间/核验状态筛选 + 事件包 + 事件列表。选择一项后展开详情与研究窗口；新建/编辑在局部表单中完成，不要求用户写 JSON。桌面列表和详情并排；768px 以下上下排列，320px 不产生页面水平滚动。表格/文本是可访问的事实载体，不仅靠颜色。

人工事件编辑器提供“从事件库选择”：搜索/选择一个事件或事件包、选择窗口、显示已选数量，点击一次加入。取消不改变原定义；加入为一次可撤销编辑；相同事件版本和窗口不重复加入；超过100个明确阻止，不能静默截断。修改已引用项的窗口或名称时明确转为本地人工副本，不冒充原库版本。

## 4. 统一时点能力解析

以 `output port + node parameters + upstream lineage + run mode` 为输入。注册表声明最小时间语义规则，而不直接声明整个业务算法永远实时或事后：逐点/单向历史窗口、显式对齐、全输入定界、人工事后标签、依执行模式训练的模型、受限公式。

- 单向滚动统计：依赖窗口右端不晚于输出观测，传播上游数据可得日。
- 显式日历重采样：周期完成和数据公布是两种时间；缺完整周期/发布日期不能由采样日期猜成实时可得。
- HMM/Markov/GMM：现有 realtime 初始训练锁定后推断与 retrospective 全样本拟合按实际执行分支分别推导；训练窗口不是独立免审常量。
- 峰谷定位/PS 全局筛选/事后合并：保留已核实的未来依赖契约；普通下游加减/条件/滞后不会洗掉未来依赖。
- 人工历史事件：计算本身只是日期匹配，可不重绘；标签来源仍强制仅事后。不能把“不重绘”等同于“当时已经知道”。
- 通用/指标公式：复用 typed DSL 的类型和现有算子裁决基线，遇到沿时间归约明确要求窗口证据；未知算子/未覆盖契约失败关闭。公式参考审计不在生产请求临时编译。

报告同时返回各输出的祖先集合、原因节点、证据路径、策略版本以及独立的 hindsight/repaint/numerical/data 判断。原有 causal/repaints/realtime_supported 等只由报告投影，不维护平行裁决。

## 5. 真实执行审计

复用现有 prepare 和预览任务取消/过期机制，新增显式 audit_temporal 选项；正式运行在最终门禁前生成相同证据。按实际选定输出祖先执行，使用已经预热的 NJIT 计划。严禁把 audit_expression 的参考 Python evaluator 当作数值生产路径。

共享 `causality` 模块提供时间戳感知的固定签名数值探针，继续使用现有 Verdict、扰动风格与容差：

- P1：锁定原始数据快照，保持日期轴和长度；按 available_at 而非单纯行号扰动未来值。各源分别扰动，防止多源同比例变化互相抵消；保留 NaN/Inf/类别语义。按真实输出日期和可得日比较，禁止把周频/月频结果机械右对齐到日频。
- P2：从同一原始快照截断可得前缀后重算，比较当时应可得输出，检查尾部扩展是否修改既有结果；显式记录轴变化、缺失变化和首个反例。
- P3：对递推算子记录既有预热契约与历史长度敏感性，不与泄漏裁决混合。
- 数据时点：使用已解析快照的发布状态/vintage/PIT 标记，不通过猜测日期填补未知。
- 语义：人工事后标签/全样本定界不能被数值通过反向覆盖。

限制样本、源数、切点和重复运行总量，取消和超预算返回未验证，不静默放行。原始 PortValue 只读共享；仅被扰动的源分配必要副本，原图/缓存不写入；输出及工作缓冲区允许分配。报告记录覆盖数量、引擎版本、定义哈希、模式、数据指纹。日常浏览/查看保存结果不再执行审计。

## 6. 全球事件数据模型

事件事实与市场研究窗口分开。`Event`：稳定ID、中文/英文名称、类别列表、地区列表、描述、事实起止日期（可未知）、日期精度、事件进行状态、核验状态、公开时间（未知保留空）、来源条目、研究窗口列表、是否归档。`Window`：稳定ID、名称、起止日、选界理由。事实结束未知不等于今天结束；进行中事件的研究窗口可以有明确“截至日”。

`EventRevision`：乐观修订号、内容哈希、创建/更新时间、不可变历史。编辑生成新revision，归档阻止新选择但旧引用可读。来源URL只作为元数据和安全http(s)链接，不由后端抓取，不引入SSRF。未核验条目不能自行标成权威；核验需要来源和窗口理由。

`Pack`：按类别或用户选择组织的事件包；加入图谱时解析为确切事件修订+窗口，不保存会漂移的动态查询。

现有41项导入为“已有工作区人工研究窗口”，记录来源定义ID/revision；不能把之前说明中的机构名字当作已经逐条核验的引文。事实日期未知保留空，原起止日迁入研究窗口，原定义和旧运行不改写。重复导入幂等，不覆盖人工维护后的库条目。

## 7. 后端接口与持久化

复用本项目 AtomicJsonStore 和领域错误协议，不增加数据库依赖。事件库使用独立小型元数据存储；实际事件计算仍由 annotation.manual_events 与原NJIT内核负责。

接口放在 `/api/historical-regimes/event-library`：事件列表/详情/历史修订、新建/乐观更新（含归档）、事件包、从已保存人工定义导入、按确切revision与window批量解析。读操作不触发网络请求或自动改写定义。

解析返回原有人工事件结构，加可选 `library_reference={event_id,revision,window_id,content_hash}`。服务端 prepare/save 校验引用与内嵌快照一致；不能仅信前端给出的哈希。历史数值运行消费冻结快照，不依赖库中最新版本。自由手写 events 无需 library_reference，完全兼容。

## 8. 验收清单

- 计算：因果/泄漏/未知、常量或全NaN无证据、分支屏蔽、多源抵消、不同频率/发布日期、模型拟合方式、类型与非有限值、同日数据、冻结输入不污染。
- 模式：人工标签不重绘仍仅事后；闲置节点不拦截无关输出；选中比较分支受限；旧接口兼容字段与统一报告一致；旧快照不被新规则回写。
- 事件：CRUD/修订冲突/归档/历史获取；事实与窗口分开；错误日期/重复ID/超100/非法URL拒绝；批量引用去重；篡改冻结引用拒绝；41项导入幂等且旧定义不变。
- 前端：无JSON操作、清晰未验证与失败反馈、搜索分页/空态/错误重试、取消不丢草稿、过期响应不覆盖、引用编辑脱钩、320/768/1440布局、键盘/文本访问。
- 自检：pytest专项与情景回归、Vitest、TypeScript、生产构建、浏览器验收、Git差异及路由记忆验证。测试只使用离线夹具。
