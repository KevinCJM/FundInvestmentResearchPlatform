# 通用区间计算图滚动执行：详细设计

## 1. 目标与边界

用户以现有算子构成区间标量指标，系统自动分析其完整计算图，合格后可直接生成滚动时序。不再要求每个统计量增加 window 输入重载、rolling_xxx 实现及编译器专用分支。均值、标准差、区间最大回撤、Sharpe、Calmar、分位数和用户组合指标共用同一执行机制。

“区间输入→标量”是必要条件，不是对任意黑盒算法的证明。自动判断基于受控类型、算子区间语义、全部依赖和状态边界；未知语义失败关闭。用户配置不能让未注册代码、外部模型状态或未来信息绕过检查。

只修改指标引擎、指标服务、指标中心及对应测试/文档，不调整当前工作区其他需求。既有指标/快照不原地改写。正式运行不编译，不回退 Python，不修改输入。

## 2. 核心模型：可展开的执行作用域

新增编译器控制结构 `rolling_apply(calculation, window)`，中文为“滚动计算”。calculation 是完整的区间标量子图，不是已经算好的全样本标量，也不是运行期 Python callable。

示例：

```
rolling_apply(mean(returns), 20)
rolling_apply(std(returns, 1), 20)
rolling_apply(-min_value(drawdown_series(adjusted_nav)), 20)
rolling_apply((mean(returns)-risk_free_rate_per_observation)/std(returns,1)*sqrt(periods_per_year), 20)
```

编译器在构建阶段明确标注作用域：子图内部节点每个窗口重新执行。外层不能提前对全样本计算子图后再切片。例如滚动最大回撤必须在每个窗口重新建立峰值，不能对全历史回撤序列求滚动最小值。

日期和年度配置属于执行上下文。规范表达式可显式包含自动绑定的 `observation_dates` 与 `annual_risk_free_rate_decimal`；编辑界面优先呈现计算内容和窗口，自动上下文在高级信息中说明。源公式、规范表达式、计算图与执行记录保持同一语义。

## 3. 职责与 AGENTS.md 四问

- 滚动作用域只解决：按右端时点遍历窗口、绑定区间输入、重置区间上下文并收集一个标量。
- 子图可以独立使用/替换，仍由统一数学算子组成，并可在画布编辑；不能将业务指标写死在滚动执行器。
- 普通单向数据连接无法表达“同一子图在不同输入区间重复执行”的作用域；仅替换 mean/std 等叶子归约不等价于完整区间重算。
- 切片、执行顺序及状态生命周期属于作用域控制语义；拆为全样本先算再滚动会改变最大回撤、分位数条件统计和部分路径指标。它不是不可见业务黑盒。

## 4. 自动能力分析

分析已验证 Typed DAG 的选定根依赖闭包，不扫描无关节点，也不按指标名称判断。

1. 最终是数值标量，不是时序、矩阵、布尔值、日期或结构化状态。
2. 至少依赖一个可绑定时间轴的一维数值输入。
3. 存在区间归约/拟合/区间状态计算；单纯固定常数或单独取首末值不作为区间聚合指标推荐。
4. 输入为可对齐的一条或多条时序，加常量配置/可重建区间上下文。矩阵外部输入、未定义外部标量上下文失败关闭。
5. 每个原语声明 local、resettable 或 history_required 等区间语义。纯数学/统计原语复用注册表声明；回撤扫描和区间内拟合可重置；需要窗口前递归状态的算子不自动开放。
6. 作用域内不允许再次滚动或消费逻辑窗口集合；避免隐式双重时间窗口。今后若支持嵌套，需明确独立契约，而不是放开校验。

返回 supported、原因代码、中文说明、输入序列、聚合节点、状态重置说明、窗口单位及资源估算。运行可用性（是否有真实数据）与结构能力分别判断。

## 5. 区间数据契约

第一版采用完整观察窗口，右对齐并包含当前时点。不补齐不足窗口，不删除缺失行拼成新窗口，不把缺失填零。

- 收益类窗口 W 表示 W 个收益观察。收益和其他同日期序列取 [start,end)；依赖的净值路径需要覆盖起点，取 [start-1,end)，得到 W+1 个净值点。
- 纯净值/价格类窗口 W 表示 W 个观察点；峰值从窗口第一个点初始化。
- 多序列必须由数据层按日期对齐，不能分别删除缺失后仅按数组位置配对。执行前验证长度、日期单调性及一致性；输入数组本身不携带可伪造的跨产品对齐推断。
- observation_count、window_elapsed_days、risk_free_return_window 在每个窗口内重新计算；年化频率及年化无风险利率为定义/参数配置，不用全区间样本数替代局部样本数。
- NaN/Inf 输入使该窗口不可用，邻近其他有效窗口仍可计算。除零、样本不足、无事件等按原标量数值契约保留缺失，不影响其他窗口。
- 输出日期为窗口右端；保留输入数据的知识可得时点和价格基准，滚动不能把未发布信息变成实时信息。

## 6. 编译与执行算法

```
保存/显式校验/启动预热
  → 验证整个区间子图
  → 为子图生成静态调用的 NJIT 区间函数
  → 生成统一的 NJIT 滚动循环
  → 预热可写/只读连续 float64 签名并禁用自动扩展

正式运行
  → 校验参数、读取缓存
  → 一次读取/排序/对齐/边界转换
  → 进入已准备计划
  → 切片视图绑定区间 → 调用区间子图 → 写入预分配时序
```

子图只用已注册的数值内核。编译期间选择调用关系，运行期没有 Python 函数回调、按指标名称分派或新 JIT 签名。新增合格区间指标只改变用户图和生成计划，不修改滚动循环。

通用性不等于所有公式 O(T)。一般复杂度为 sum_t C_f(W_t)，扫描类通常 O(TW)，分位数还涉及排序。既有等价融合内核可以继续服务已有公式；后续优化只是执行计划优化，不是新指标可用性的前置条件。不能声称 Numba 会自动把任意滑窗变成 O(T)。

## 7. 内存与资源预算

- 基础数据用一维 float64 ndarray，日期为稳定数值日序号。无 object/pandas 数值容器。
- 预分配结果，窗口仅用基本切片视图，不构建 T×W 矩阵，不逐窗口复制原始输入。
- 共享子图节点在单窗口内只执行一次。必要中间计算输出及排序工作区由现有内核管理，每次窗口调用结束释放；峰值为输入+输出+单窗口活跃工作区，不累计所有窗口。
- 不承诺现有所有内核都支持 out 参数；无法复用的必要中间输出需在验收中记录，禁止伪称零分配。
- 非连续/dtype 不匹配只在输入边界进行一次必要规范化，并记录；只读和可写布局都须预热。
- 在执行前按输出点数、W、节点成本及中间形状估算并限制计算/内存预算，超额明确拒绝，不能失控长算。
- 测试 np.shares_memory、只读输入不变、非连续输入、W=1、超长窗口、错配/非法日期、参数变更计划复用；基准记录稳态耗时、峰值内存和必要输出分配。

## 8. 前端布局与流程

保留“定义与公式 / 校验与预览”，不新建研究中心，不强迫用户理解 window 中间类型。

### 标量指标

基本信息下展示一行能力说明：“支持滚动计算 · 每个窗口独立重算”，右侧“生成滚动时序指标”。不支持时展示简短原因，未知/未验证不能当支持。来源范围包含用户自己保存的指标。

### 时序创建

“滚动计算”卡片只保留三个主操作：①选择区间指标（可搜索）②窗口观察数③生成滚动公式。下方一句动态说明：“对最近 W 个…逐日计算『指标名』，窗口不足或缺失时留空”。来源版本、窗口起点重置、日期/无风险配置等放在可展开详情。

生成的是普通可编辑时序定义；完整子图真实保留，画布能看到“区间计算内容→滚动计算”及窗口参数，而不是把聚合结果当已算好的常量。点击/展开可以修改子图，修改后明确解除来源绑定，不修改原标量定义。

窗口作为已有参数体系的候选输入；作者可选择“允许计算时调整”，默认值必须存在。其他页面默认计算，临时覆盖不改变指标版本。未开放参数仍不能通过 API 越权覆盖。

移动端顺序单列、桌面按来源/窗口/操作排布。未选来源或窗口为空/非整数/越界时禁用生成并明确指出原因。

## 9. 服务、版本与缓存

沿用 derive-rolling-series、rolling-scalar-draft、validate、graph/resolve、evaluate-series 和保存接口。新滚动转换协议与旧1/2版区分，旧协议只做有实际调用的兼容适配，不保留第二份新数值算法。原内置定义、历史 revision 和其数学口径不变。

新定义记录完整生成表达式、来源 id/revision/hash、转换协议、执行作用域版本、缺失/边界语义。计划身份包含编译器作用域版本及子图；结果缓存继续包含来源/定义版本、有效参数、日期范围、数据代际和目标。窗口参数仅改变运行值，不生成新函数签名。

## 10. Excel、因果审计与验收

Excel 必须针对同一窗口执行同一完整标量子图，不得把全历史回撤当窗口回撤。复用标量公式导出机制，并限制窗口展开后的单元格预算；超额返回明确限制，不导出错误或伪造 Excel 自定义函数。

因果审计识别作用域边界：子图中的归约仅消费当前窗口，不能对其全样本片段单独审计后误判整个滚动结果。必须测试未来扰动不改变已有输出、改变窗口外峰值不改变窗口最大回撤、参数/日期变化不命中错误缓存。

专项测试包括：普通统计、分位数/CVaR、MDD、Sharpe、Calmar、自定义组合、多输入相关系数；逐窗口独立参考；错误/缺失隔离；默认及覆盖参数；已准备计划缺失时失败；画布往返和真实浏览器流程；Excel、历史版本回归、前端构建、i18n 和路由检查。

技术依据：NumPy 官方 copies/views 文档明确基本切片是视图，高级索引会复制；Numba 官方 supported Python features 支持已编译函数静态调用及受限异常处理。最终性能/签名/内存结论以本项目实际测试为准，而非仅依据装饰器。

## 11. 实现收口与验收入口

最终作用域实现版本为 `interval-rolling-1.3`，新派生协议为 `3.0.0`。代码入口为 `backend/cal_indicators/rolling_scope.py`、`backend/causality/rolling_scope.py` 和 `backend/custom_indicators/excel_rolling_scope.py`；现有编译器/服务负责调用，不建立第二套独立数值指标实现。

自审核后补充两个实现约束：①校验在分配之前，作用域在实际父 NJIT 调用中内联，避免异常跨帧遗留数组引用；②流式 Excel 必须在上下文行首次写入时输出公式，不能写零占位后回写已刷新行。动态长度多输入在进入固定内核前检查实际长度。

内存估算包含结果数组、有效性前缀和单窗口中间量，不把编译器/进程RSS误报为计算内存；工作量是估算门禁而非硬实时保证。完整测试命令、533项后端/108项前端/8项浏览器结果、性能测量及范围外未通过项见 `docs/rolling_interval_graph_acceptance.md`。
