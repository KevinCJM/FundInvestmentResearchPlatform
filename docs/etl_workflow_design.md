# 数据下载与 ETL 任务编排

## 计算图编辑器（2026-09-06 更新，替代下文早期顺序表单）

ETL 默认使用从历史情景识别抽取的公共计算图画布；不再逐步铺开全部配置表单。节点库按后端 `graph_schemas` 生成，下载、映射、取值、快照和数据集任务都使用同一组件。节点参数通过按需打开的检查器编辑，保留通用接口参数和任务目录。

数据边来自 `inputs`，控制边来自 `after`。实线传递数据，虚线仅控制先后；拖动位置不会改变任务顺序。新 `graph_version=1` 定义可乱序存放节点，后端用 `backend/computation_graph` 编译稳定拓扑顺序后再交给现有执行器（不是并行执行）。后端继续检查数据类型、数量、表关系与快照必需输入。

旧保存流程不需要批量迁移，画布适配层将原顺序显示为必要的控制依赖。明确保存时写入新图版本及 `canvas` 位置/视口，既有 Tushare 31 节点流程可直接打开。删除节点同步清理相关引用；子图复制重写内部 ID；撤销、重做、移动端连接表单和只读门禁共用公共实现。

保存的图含界面布局；实际运行冻结原模板与编译后的业务定义，`canvas` 不进入计算参数。全量/增量仍是每次运行选项，历史候选、权限、限流、失败恢复和未发布边界不变。公用模块与回归依据见 `docs/computation_graph_design.md`。

## 最新补充：通用前端与全数据任务

编排器不按供应商或流程 ID 选择组件。运行表单由 `parameters` 渲染，普通接口表单由 `request_fields` 渲染；缺少请求合同则保留通用 JSON 参数入口，不再从输出字段推测产品代码。用户可以直接在表单里新增运行参数。

新增 `task` 数据集节点：由 `/api/data-sources/etl/tasks` 返回任务目录、可选来源、参数、前置能力和输出说明。同一种编辑器支持任意已登记任务。任务可增删、调序、设置输入及参数绑定，模板只是保存的普通定义。

Tushare 全数据同步定义包含 30 个已支持采集/派生动作及独立指标快照，共 31 节点、覆盖当前 40 个已配置接口。只需开始日期、截止日期及本次模式，不需要单个 ETF 或基金代码。原 17 步指定产品流程保留。基于已有采集器进行全市场产品遍历及分片，不把 100000 行限制的单接口试算器改成无界全表扫描。

批量节点输出独立兼容工作区和逐批标准映射候选；它不冒充完成多源融合或正式发布。增量基线仅来自同流程范围、配置及实现的成功私有结果；失败恢复核验文件校验和。所有本轮细节以 `docs/etl_generic_full_data_design.md` 为准，下述早期阶段边界保留作历史说明。

## 1. 需求与现状

用户的工作入口是“数据下载与更新”，而不是接口配置页。应能先选择 Tushare、AKShare 或自建来源，再选择该来源支持的数据、产品/日期范围及增量或全量。多个来源的数据可以放进同一条流程；用户决定执行顺序和快照计算位置。

当前 DataManagement 只挂载旧 Tushare 面板，单接口下载藏在配置中心。sync_jobs 把下载、映射、取值合并为一个自动动作，无法控制计算顺序。本次保留旧下载能力但放进“原 Tushare 全市场任务”折叠区，默认入口改为多源下载和 ETL。

## 2. 用户操作

### 快速下载

1. 选择数据源；展示已保存的接口，按标准业务表分类，支持名称/接口/字段搜索。
2. 勾选需要的数据。禁用项说明未启用、映射未完成等原因；配置入口直接定位到该来源/接口。
3. 为每项填写实际产品代码/日期/必要参数，选择全量或增量。默认参数可见，不用猜测下载范围。
4. 确认执行清单。快速下载自动生成“下载 → 映射 → 多源取值”步骤；用户可转入 ETL 编辑器调整，或直接运行。

### ETL 编排

同一页面第二个工作区提供流程列表、新建/保存/另存流程、步骤添加、删除、上移/下移和依赖选择。采用顺序步骤编辑器而不是第一版就引入自由画布：顺序容易理解、手机可操作、可清晰验证。步骤可以跨数据源，快照可以放在任意依赖完成的位置，也可以有多个快照。

运行前展示计划校验；执行时展示每步等待、运行、成功、无数据、失败、已取消、被阻断、耗时、行数和错误。失败后保留已成功结果，“继续未完成步骤”不重跑成功下载。需要重新抓数据则明确“新运行”。取消在安全边界生效，不声称瞬时终止已发出的网络请求。

## 3. 步骤合同

| 类型 | 输入 | 输出与规则 |
|---|---|---|
| download | 来源、接口、固定修订、参数绑定；默认跟随运行模式 | 有界分页、共享限流的 Raw 制品；此步不映射、不计算快照 |
| map | 一个前置 download 步骤 | 使用该运行冻结的字段映射生成标准候选；不重新联网 |
| resolve | 一个或多个前置 map 步骤、标准表 | 按冻结的多源规则合并指定映射输出；可显式包含运行开始时锁定的历史候选，不读运行中新增的无关批次 |
| snapshot | 一个或多个前置 resolve 步骤 | 在独立目录基于指定合并结果计算指标分析快照；不修改活跃研究数据 |

顺序就是执行顺序；inputs 是数据依赖，必须引用前面的合法类型，禁止前向引用、循环、重复 ID、孤立引用。快照要求已合并 `master.instrument` 与 `market.nav_daily`，可额外引用原始行情与交易日历；不允许拿尚未映射的下载结果计算，也不允许悄悄读旧活跃价格。

快照复用现有 instrument_analytics 构建器及 NJIT 内核。适配层仅把本次 Canonical 输入投影到私有兼容目录；以内部 instrument_id 作为该目录唯一标识，按主表类型区分 ETF/场外份额。单位净值不填入 adjusted_nav，缺少复权数据的指标保持不可用；不把 AKShare 行情伪装成净值。配置指标及其版本在启动时冻结到私有工作区。快照生成的文件、输入校验和和计算配置一并记录。

## 4. 全量、增量与数据边界

### 4.1 流程定义与运行选项分离（2026-09-06）

同一条流程支持全量和增量，不为两种模式复制流程。`POST /runs` 的 `options.mode` 为本次全量/增量选择，默认 incremental。下载步骤 `mode=inherit` 跟随本次运行；产品信息、日历等可明确配置 `full` 每次刷新。历史已保存步骤的显式模式仍保留，不静默迁移历史定义。

流程可声明具名 `parameters`，下载步骤的 `parameter_bindings` 把参数 ID 绑定至接口字段。运行的 `options.parameters` 提供产品代码和日期。必填参数未填时可以保存流程，但启动校验拒绝；不将缺失代码解释为全市场请求。绑定仅为受控值替换，不执行模板语言或 Python。

运行保存原始 `template_definition`、具体绑定后的 `definition`、`options`；冻结每个下载的实际模式、请求日期和断点键。同一 request_id 更改模式/参数会冲突，恢复仍使用原范围，不重新读取已变化断点。快照按完整指定输入重建，不把增量下载误解为只计算新增行。

### 4.2 Tushare 基金同步流程

流程名：**Tushare ETF 与公募基金数据同步**。按用户请求通过普通流程保存 API 创建，可编辑和删除，不在初始化时自动复活或覆盖。

包含 17 个步骤：SSE 日历下载/映射/取值；ETF 与场外基金信息分别下载/映射后统一取值；ETF 与场外基金净值分别下载/映射后合并；ETF 行情下载/映射/取值；最后指标快照。运行必填一只 ETF 代码、一只场外基金代码及截止日，历史起点默认 2010-01-01。范围是指定产品，不是全市场。

基础信息与日历固定全量刷新；净值和行情跟随运行模式。主数据只使用本次记录，避免混用不同采集日的主数据版本；净值、行情的 `history_scope=matching_inputs` 仅纳入同接口、同产品和同非日期口径的历史候选。默认 `history_scope=table` 保留旧流程整表历史行为。

`GET /templates/tushare-funds` 仅生成基于已保存接口修订的流程草稿，不写流程、不触发网络；使用既有 PUT /workflows/{id} 保存。

### 4.3 取数与发布边界

“全量”是重新请求用户选定接口/产品/区间，不是删除整个数据仓库，也不宣称自动下载全市场。“增量”复用相同来源/接口修订、非日期参数的成功断点并回查 3 天；无断点时从指定起点开始。映射未成功不推进断点。旧 Tushare 模块级全市场下载仍由原下载器执行。

历史候选复用可单独关闭。合并只接受冻结历史批次和显式引用的本次映射批次，按请求日期范围筛选。全量重新取得的重叠记录按同来源修订规则取新值，未返回行不会被假定为供应商明确删除。显式删除/撤回协议不在本轮实现。

正式研究读取迁移和自动发布继续保持原阶段边界。本页面明确显示“候选未发布”，不把下载成功、取值通过、快照完成等同于替换正式数据。定时触发可后续复用流程 ID，不在本轮引入调度器。

## 5. 后端结构

`backend/data_sources/etl_models.py`：严格流程、步骤、依赖与参数模型。
`etl_store.py`：SQLite 流程修订、运行与节点状态；运行 ID 幂等；制品哈希。
`acquisition.py`：有界下载与增量辅助，供单接口和 ETL 共用，禁止再复制一套供应商逻辑。
`etl_service.py`：校验、冻结、后台顺序执行、取消、恢复、状态读取。
`etl_snapshot.py`：显式 Canonical 输入到现有快照计算的隔离边界。

持久化在现有 data_sources.sqlite3，新表 etl_workflow、etl_workflow_revision、etl_run。Raw/映射/取值/快照制品放在 data/etl_runs/<run_id>/ 下；映射记录仍接入现有候选批次目录和结果 API。以上均为内部控制结构，不增加外部导入表。

## 6. 一致性与安全

运行启动持有全局刷新锁直到结束，防止旧下载器、单接口下载、配置修改与 ETL 相互穿插。运行冻结流程版本、来源/接口修订、取值规则、历史候选清单和指标配置；不持久化明文凭据。网络使用现有 SSRF 防护、目的地址绑定、共享配额、有界重试和 SDK 隔离。禁止用户脚本/SQL/任意文件路径。

步骤制品先写临时文件再原子切换。恢复前核验所有已成功步骤的制品哈希；源配置已变化则拒绝继续并要求新运行，不能以新规则静默重跑。跨进程读取运行状态；服务退出后标记 interrupted，不能永久显示运行中。重复请求 request_id 不启动第二个任务。失败默认阻断后续步骤，避免快照使用半成品；允许空数据是显式选项，默认失败关闭。

最长流程运行时间有上限，每次网络调用及分页之间检查取消与剩余时间。快照在受控子进程运行，取消/超时终止该私有计算而不触碰正式文件。

## 7. API

位于 `/api/data-sources/etl`：
- GET /workflows；PUT /workflows/{id}；DELETE /workflows/{id}（expected_revision）
- POST /validate（返回错误、步骤摘要、快照依赖）
- POST /runs（definition 或 workflow_id+revision，request_id，confirm=true，options.mode、options.parameters）
- GET /runs；GET /runs/{id}
- POST /runs/{id}/cancel；POST /runs/{id}/resume（confirm=true）

只读环境仍可查看/校验，运行、保存、恢复与取消遵循环境写入开关及同源请求检查。

## 8. 验收

离线覆盖多源选择、只显示来源支持数据、全量/增量及参数落到真实 adapter、步骤顺序、坏依赖/循环、CAS、重复请求、运行锁、停止后续、成功步骤不重跑、取消、服务重启恢复、制品篡改、映射失败不前进断点、冻结规则、仅指定输入参与取值、真实快照读本次合并输入、不得覆盖 active、只读和跨站请求。前端覆盖快速下载、跨来源流程保存、排序、输入选择、验证和失败恢复；三种视口浏览器测试以及生产构建。真实网络 smoke 最多一次 Tushare 请求、仅临时目录；离线测试不联网、不写正式市场数据。
