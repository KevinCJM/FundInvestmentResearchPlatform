# SAA → TAA → 产品配置：连续研究体验优化

日期：2026-09-11。对应体验审计 J02、J03、J07、J12–J15、J25。此记录只覆盖 SAA 和产品配置页面；产品池、大类、TAA 工作台和数据质量修复由同一需求的其他部分负责。

## 用户看到的流程

1. 从大类保存页面进入 SAA，URL 携带 `alloc` 和 `universe`，自动加载这份大类方案。更换方案立即加载对应研究，不能用旧方案的输入误算新方案。
2. 首屏选择“填写长期权重”或“比较收益与风险”，确认研究区间及资金边界。类内产品清单、指标口径、随机采样参数和完整前沿图默认折叠。
3. 不确定长期比例时，比较较低风险、较高收益风险比、较高收益三个真实候选。表格同时列权重、收益、风险，可一键采用，再编辑选择理由和长期权重。
4. 验证历史表现后进入 TAA。清楚说明继承的是权重、产品映射、单项/联合边界；TAA 的日期、费用、调仓规则和 SAA 对照需要按本次研究重新计算。
5. 保存 TAA 后交接产品配置。页面显示每类预算、已分配金额比例及是否匹配，只允许类内手工调整。预算不匹配时前置阻止运行，后端仍验证来源、风险和有效期。

## 具体变更

| 问题 | 行为 |
| --- | --- |
| 回到 SAA 又变成其他方案 | 真实上下文和 `?alloc=…&universe=…`；按范围和方案分别保留输入草稿 |
| PIT 重载或离开页面后草稿丢失 | 保存日期、目标、约束、策略和调仓输入；刷新/返回恢复，结果和调仓计算缓存不持久化 |
| 算过后改参数仍看到旧结果 | SAA 前沿和回测结果根据输入变化失效；产品配置编辑后清除旧结果，运行中的迟到结果也不能覆盖新输入 |
| 开场全是算法设置 | 目标、日期、权重优先；高级计算与产品明细按需展开 |
| 权重口径混乱 | 单类/联合范围及目标收益风险输入为百分比，服务请求仍使用原小数契约；明确类内权重与全组合权重 |
| 有图却难采用 | 三类候选表直接采用真实返回的权重；沿用当前后端计算，不在前端另行优化 |
| 改成自定义后权重变 100/0 | 保留正在编辑的权重，只解锁输入；说明随等权/自定义方法变化 |
| 编译信息干扰研究 | 去掉正向结果的 NJIT 来源提示，执行证明校验保留，不允许客户端等权计算回退 |
| 日期看似一致实际不同 | 新研究的回测开始日对齐构建开始日，并不早于共同数据起点；明确回测结束仍跟随当前可用数据 |
| 产品预算到最后才失败 | 复用数值校验服务按类检查合计与预算；展示具体哪一类需要调整 |
| 产品配置步骤仅装饰 | 步骤可点击定位对应操作区域；TAA 交接使用 `universe + decision` 区分草稿 |
| 错误弹窗消失 | SAA 计算错误保留为页面提示；原执行校验和服务端质量错误仍明确展示 |

## 计算与时点边界

- 没有引入新的数值算法或额外求解器。百分数/小数转换属于输入展示边界；等权、有效前沿、策略权重及类预算合计沿用后端契约与执行检查。
- 恢复的固定权重是研究输入，不是当前数据已验证的结论。风险预算与目标求解策略只保留方法和预算，计算权重恢复为待计算；不保存前沿、回测结果或临时调仓缓存。
- SAA 回测 API 目前只接受起点，终点由当前数据口径决定。本次没有发送一个后端不支持的 `end_date` 来制造日期已对齐的假象。
- SAA/TAA 历史结果的调仓、成本和时点并不天然一致，交接说明明确要求在 TAA 内重新比较。
- 产品配置仍提交 `allocation_source`，没有跳过服务端预算、研究版本、有效期或风险门禁。客户端预算合计通过统一数值校验服务计算。
- 本部分没有修正国债代理净值，不对疑似异常收益作可投资结论；数据质量门禁由后端专项处理。
