## 1. 范围、兼容与架构决定

改动限定投前01–04及它们直接依赖的数据/计算/产品交接链。保留现有三种目标、人工CMA、四种政策候选、历史有效前沿、手动/自动分类、Momentum/Manual/Regime与日频回测。增加的方法必须显式选择，不能改变旧请求默认算法。不可变历史不迁移、不重写，回滚通过Git。原有AGENTS.md工作区修改不属于本任务。

采用现有模块化单体，不创建第二个投研后端。边界：

`React工作区 → services/*.ts → existing FastAPI routers → domain service → fixed-signature kernels / immutable repository`。

已有ArtifactRepository负责新战略定义/映射/CMA的不可变保存；TacticalAllocationRepository仍是SAA baseline及TAA决策唯一来源。输入契约分模块，避免继续向页面或service单文件堆全部逻辑。共用权重约束、风险矩、时点校验及应用门禁；新增数学不得被前端重复实现。

## 2. 01目标：机构语境与真实边界

### 2.1 数据契约

在MandateRequest增加可选的`institutional_context`，旧请求缺省为空，不制造新审批要求：

- `investor_type`：personal/family_office/asset_manager/corporate_treasury；只改变提示和适用字段，不自动替用户提高风险限额。
- `purpose`：资金用途说明。
- `cash_reserve_weight`：明确的组合内现金用途下限，0–1；与原`min_liquid_weight`区别显示。
- `balance_sheet`：可选同研究日、同本位币快照，区分可投资资产、组合外资产、已确认负债与未缴承诺。不存在的数值保持null/未提供，不补零。计算结果显示“研究快照”，不冒充法定账簿。
- `review_items`：税务/监管/币种与对冲/杠杆/特殊流动性等待核验事项，保留状态、理由、证据与核验时点。记录“研究员已核对”不等于独立审批；未核验事项参与应用资格判断，不能被下游删除或改写为通过。

现金流仍复用FundingPlan/FundingFlow，不并行保存两套同一支付计划。未缴承诺不当作资产，也不自动等价当前负债；压力催缴假设必须显式输入，不能把预期分配当作确定可用资金。

### 2.2 计算与门禁

经济资产负债表的简单汇总采用独立固定签名NJIT；它是诊断而非完整随机ALM。资金目标、成功概率和所需本金继续调用`planning.py / goal_kernels.py`。

现金用途下限形成保留前缀的政策分组，仅匹配CMA中明确的`role=liquidity`且`liquidity=liquid`资产。普通权益ETF虽然可以交易，但不能满足该现金角色。没有满足条件的资产时返回明确错误；实际产品同日可用性仍需实施核验。原流动性分组约束保持原含义。

SAA候选、政策确认、TAA前瞻检查和最终产品桥接共同消费冻结后的边界。人工核验未完成可以保存研究，不可被宣称为可应用；实际应用再次检查时点、到期和证据状态。

### 2.3 前端

沿用“资金与成功标准 → 风险与限制 → 量化诊断 → 核对与确认”。首屏增加资金用途选择；机构细节采用渐进展开，不展示十几项空表单。现金储备与可交易资产比例分开解释。明确显示“已计算 / 未建模 / 待人工核对”，保存按钮仍要求确认。完成后提供“下一步：确定投资范围”，保留原直接进入SAA入口为次要操作。

## 3. 02：战略机会集与实施映射

### 3.1 新不可变对象

`StrategicUniverseVersion`：name/as_of/currency/assets/source；每个资产含稳定id、展示名、经济角色、流动性及定义理由。产品列表不构成这个对象的存在条件。

`ImplementationMappingVersion`：明确引用strategic_universe_id、产品域快照和已有大类配置，逐个战略资产指定实际代理大类；保存源配置、NAV/产品域血缘和映射哈希。映射通过选择真实对象形成，不能按同名猜测。未覆盖资产可以保留，但必须在预览与保存结果列出。

对应接口位于现有`/api/strategic-allocation`路由下：

- `POST /universes/preview`：验证战略范围，不写文件。
- `POST /universes/confirm`：重算并核对preview_hash后保存。
- `GET /universes/{id}`：读取不可变战略范围。
- `POST /implementation-maps/preview`：核对范围、产品域、实际代理及缺口。
- `POST /implementation-maps/confirm`：确认后冻结映射。
- `GET /implementation-maps/{id}`：读取冻结映射。
- 现有catalog扩展独立范围与映射目录；旧字段不移除。

类和方法名可在实现时依据现有命名约定收敛；如接口命名调整必须在本设计中同步，不得前后端各自维护不同契约。

### 3.2 SAA与TAA来源适配

CMA增加可选的战略来源引用。旧`alloc_name`路径继续原样工作；战略先行模式必须明确以不可变范围ID取资产轴，不能把一个虚构alloc_name传给文件读取器。

`_source`的业务读取分离为单一来源解析器：既有产品大类 → 真实快照；独立范围 → 战略资产快照及可选冻结映射。只有后者允许缺产品/缺NAV的纯前瞻研究；返回明确`implementation_status`。CMA完全由用户提供时，政策研究不依赖虚构的历史NAV。

完整映射后TAA可通过受控适配读取真实代理收益，并显式重排至战略轴。优先传索引；必须物化的重排只允许在数据边界一次复制，记录原因。产品映射、class budget及源哈希随baseline冻结。缺任何所需代理时阻止TAA，不把该资产删掉或将剩余权重重新归一化。

### 3.3 页面与旅程

02页面区分“需要的战略资产”和“现有可买产品”，提供“先做战略研究”和原产品池路径。独立范围创建使用清楚的增删行和字段校验；真实代理从既有大类方案选择。覆盖结果逐类显示“已映射/缺少产品/范围不一致”，并给回产品池或大类构建的动作。

旅程增加mandateId、strategicUniverseId、implementationMappingId。产品域变动不删除独立战略定义；但使依赖旧产品映射的基线/交接失效。改变Mandate或战略轴应使未确认下游结果失效。历史保存对象始终按ID只读打开。

## 4. 03：长期假设与政策模型

### 4.1 三层分离

1. 资产范围和研究时点。
2. 预期与风险生成方法，形成不可变CMA。
3. 在同一Mandate约束下比较政策，人工确认选用。

旧人工CMA是默认兼容方法；BL和情景模型显式选择，保留原始输入以及实际被消费的`effective_returns`和`effective_covariance`。缺少新输出的旧CMA只按其原人工口径读取，不为旧历史生成虚构后验。

### 4.2 Black–Litterman

输入：同币种同年化口径的资产收益协方差Sigma、明确市场权重w_m、市场风险厌恶delta、无风险收益r_f、tau、绝对/相对观点和观点标准差。市场权重必须完整、非负、合计1；不提供真实/人工确认的先验权重时不自动称等权为市场组合。

先验为超额收益：`pi = delta * Sigma * w_m`。

将绝对总收益观点转换为超额收益，relative观点保持两资产收益差。`P`中绝对行取一个资产，relative行取+1/-1。`Omega=diag(view_std**2)`严格为正，日期与依据随观点保存。标准差不是胜率；不把“80%信心”直接当作80%收益实现概率。

用线性方程求解而非显式求逆：

`mu_excess = pi + tau*Sigma*P.T * solve(P*tau*Sigma*P.T+Omega, q-P*pi)`。

`mu_total = mu_excess + r_f`。

保留后验均值不确定性矩阵，但默认的资产风险仍为明确选择的Sigma；不得悄悄把均值不确定性协方差当作资产收益协方差。零观点等于先验，弱观点趋近先验，相对观点影响有关联资产。输出真实进入现有候选搜索、资金诊断及TAA政策风险检查。

### 4.3 情景CMA

只有显式给出概率p_s且合计1才允许概率混合。每个情景完整覆盖相同资产轴并声明其收益/风险口径。共用风险矩阵必须是显式假设，不隐式补全缺项。

`mu = sum_s p_s*mu_s`。

`Sigma = sum_s p_s*(Sigma_s+(mu_s-mu)*(mu_s-mu).T)`。

组间均值方差项不能遗漏。概率未知的shock继续属于压力比较，不进入概率CMA。结果标明是用户假设的矩匹配，不冒充机构多期校准模型或尾部分布预测。

### 4.4 政策比较

保留minimum-risk、nominal-utility、robust-utility、maximum-return。已有箱式均值不确定性惩罚继续使用，不另建“Robust MVO”重复功能。

新增风险预算比较，使用相同可行候选集及`RC_i=w_i*(Sigma*w)_i/(w.T*Sigma*w)`，最小化RC与显式目标预算的偏差；预算非负且合计1。标明“有限候选中较接近目标”，不是保证精确风险平价。协方差允许负贡献的情形必须如实保留，不能取绝对值伪装成正风险占比。资金目标门禁适用于所有候选。

候选生成/约束修复只有一个内核；新增评分不复制权重搜索循环或所有原始数据。旧API省略新字段时保留四候选与原随机序列。情景对照用于诊断，不用事后挑选的情景暗改目标。

### 4.5 前端

“长期假设”提供清晰的方法选择：“直接填写”“市场基准＋观点”“多情景假设”。先显示必填输入，tau、种子等放高级设置。BL观点逐条编辑，明确绝对/相对及单位；情景概率可见合计与错误原因。政策卡先展示目标达成、风险与主要权重，再展开方法、风险贡献与血缘。未完成输入/过期/来源变化时不给可点击的应用按钮。

## 5. 04：TAA信号、决策和执行

### 5.1 兼容契约与时钟

旧请求缺少decision_policy时保持`daily_target`。新界面建立研究时显式选用新的调仓策略，不重解释旧草稿或保存版本。

新策略分开：数据观察日、信号可得日、决策频率（日/周/月/季）、执行机会、执行滞后、最小持有期及偏离阈值。日期计划根据当前/既往日期生成，不能用未来月末数据决定今天是否交易。阈值用组合权重百分点而非收益率。

复用唯一TAA持仓推进内核：非交易期按收益漂移，只有符合执行规则的日期更新持仓并计算双边换手与费用；决策更新目标不等于当日成交。兼容入口仅生成daily masks并委托当前内核，不留下新旧两套数值实现。

训练和Holdout独立初始化；共同日期缺口不得冒充交易所真实执行日历。输出决策/执行时间和不交易原因；当前真实持仓未提供时不声称已执行或已达到偏离阈值。

### 5.2 信号组合

原三个模式保持。新增composite：组合多个动量窗口，或用户提供有来源的已研究标准化信号。外部信号按value/carry/macro/risk_sentiment等标注，并提供资产、观察日、可得日、过期规则、单位与依据。系统不把NAV均线改名成这些信号，也不自动下载未授权数据。

所有非零权重信号必须满足当时可得、资产轴完整和未过期；缺失状态不同于中性0。组合系数须明确且合计1，不因为某条信号缺失而偷偷给其他信号增权。默认不完整则回到无有效战术信号/SAA并记录原因。组合中心化后形成零和tilt，统一进入现有边界缩放、分组约束、前瞻主动风险与换手门禁。

大面板优先传只读数组/索引；导入只在输入边界做一次解析。快照保存来源、原始信号与实际使用日期；未来数据扰动不得改变过去持仓。

### 5.3 全链一致

单次回测、候选比较、Walk-forward与下游应用共用同一策略参数。训练只用成熟收益选强度；Holdout只报告，不因验证失败自动改选。固定假设比较仍显式。情景压测区分“当前目标固定冲击”和“实际规则路径回放”，不可混称策略已在该历史环境部署。

下游产品桥接再次检查冻结政策、范围/映射、日期、预期风险和必要人工核验。任何未覆盖非零预算不得消失。研究版本保存不意味着当前可应用。

### 5.4 前端

依旧“观点与规则 / 回测与选优 / 情景模拟 / 版本与审计”。首屏依次呈现所用SAA、观点来源和何时调整；复杂信号与时钟配置采用可展开区域。当前结果展示“维持 / 等待执行 / 形成调整建议 / 不可交接”，并解释原因。历史日频模式清楚标为原研究口径，用户可复制为新研究再换时钟。

## 6. 数值、内存及算子颗粒度

普通数学优先用既有`typed_numba_kernels`、`optimizer.repair_weights_kernel`及SAA/TAA矩/绩效内核。新领域模块可以新增经济余额汇总、BL后验、多情景矩、信号可得性/融合、日程掩码和持仓推进等独立计算职责。

颗粒度四问：

- 余额汇总只解释同币种时点快照；输出可单独预览，不能捆绑目标优化。
- BL是一个联合线性后验求解，属于耦合内核；先验/观点准备和约束优化在外部单独处理。
- 情景矩是一次分布矩聚合，与政策候选可独立替换；不和BL串成不可解释黑箱。
- 信号检查、融合、决策时钟与收益推进分开；收益推进有不可分离的财富/持仓递推状态，因此保留耦合内核，外围预览仍可追溯。

全部固定dtype/signature，允许只读任意stride输入，disable_compile，按PID检查已预热。不可变共享输入不得原地修改。结果、小矩阵解算和工作缓冲可分配；zero-copy不等于不分配输出。验收用shares_memory、非连续视图、readonly输入和重复调用无污染验证，不能仅凭copy=False宣称零拷贝。

## 7. 错误、时点和持久化

新路由沿用现有PIT包装与异常格式；不能绕过平台未知知识截止门禁。范围、币种、资产轴、概率、矩阵、参数、可得日和哈希必须在边界明确失败。preview不mkdir、不锁文件、不写缓存研究产物；confirm重算一致才保存。旧不可变记录允许只读浏览；不能因为今天的时点不同覆盖历史结果。

禁用按钮必须在DOM显示原因。请求使用abort/generation保护，研究日期或输入变化立即使未保存结果失效。点击保存期间修改输入不能让晚返回结果成为当前版本。

## 9. 最终实现细化与审核收敛

以下细化以实际实现及回归为依据；不改变原请求默认合同。

1. **01机构核验**：五类核验主题完整保留；已核验与不适用都要求日期、理由、证据和有效期。现金角色下限独立于普通流动性下限。经济汇总与现金权重为独立固定签名内核，不把金额诊断包装成完整ALM。
2. **02范围与映射**：新接口由 `backend/strategic_allocation/routes.py` 经原服务路由注册；`sources.py` 是来源解析与冻结验证边界。`alloc_name=null` 明确表示独立战略来源，不能传虚构文件名。部分映射可保存，但不能进入TAA/应用；补齐时生成新映射、新CMA与新政策，不回写旧对象。
3. **旅程导航**：`allocationJourney.ts` 持有目标/范围/映射引用，`StageLayout` 根据实际来源区分产品路径与战略先行路径。无产品也可进入SAA；映射是可返回补充的步骤，不作为纯前瞻研究前置条件。导航可达不代表门禁通过，最终资格由后端核验。
4. **CMA单一消费边界**：`cma_application.py` 统一产生/读取 `effective_assumptions`、`effective_returns`、`effective_covariance` 和 `model_result`。原定义与有效结果、模型哈希、只读数组共同冻结；政策求解、资金诊断、TAA风险均使用真实有效值。模型结果缺失不能补算旧记录。BL后验均值协方差采用等价Joseph形式减轻消减误差，不给资产风险添加未声明的均值风险。
5. **风险预算**：新增评分进入同一个候选搜索。零方差时预算候选返回不可用、空权重与null指标，不伪造结果；前端将其分离到不可用候选说明，禁止采纳。原四候选的随机顺序与输出经Git基线对照保持一致。
6. **TAA时钟与费用**：日/周/月/季基于共同观察期生成周期首点，不依赖未来月末；新模式执行滞后至少1观察期。`cost_basis` 独立指定 `half_turnover` 或 `gross_traded_weight`，改变频率不能改变费率分母。成熟决策不会被尚未成熟的新决策反复推迟；实际交易前/期末预算越界进入可行性判断。
7. **当前应用**：需要研究日实际持仓及日期；当前交接另要求持仓是今天的快照。新时钟门禁接入共享 `portfolio_bridge`，不能经直接产品组合入口绕过。政策或映射到期分别返回具体原因；历史候选与保存版本不因此被改写。
8. **兼容与性能**：旧日频入口为唯一递推内核的薄适配，直接分配原输出宽度，不复制完整路径。新增 `tilt_rows_status_kernel` 在单一编译扫描内复用向量合同，避免Python逐行调度；只读/strided输入及单签名均有测试。
