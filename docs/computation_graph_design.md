# 公用计算图与 ETL 画布

## 目标与边界

从历史情景识别的实际 RegimeGraphCanvas 和 v2_contracts 抽取，不另写一套外观相似的画布。公共能力同时包含前端交互和后端图结构；业务算法仍由各自模块执行。历史情景的 API、节点注册表、端口类型、推断诊断、运行顺序、发布门禁和数值结果保持不变。ETL 不借用历史情景的状态模型，也不新增供应商特例。

## 公共层

- `frontend/src/components/computation-graph/`：通用节点/端口/边合同、受控 React Flow 画布、移动端列表、选择、多选、拖动、复制粘贴、缩放、平移、小地图、历史撤销重做。业务标签、端口颜色、帮助、检查器和连线校验通过参数注入。位置仅在拖动结束提交，不让 pointer move 污染撤销历史。
- `backend/computation_graph/`：端口引用合同、有界布局合同、稳定拓扑排序、未知引用/重复 ID/环检测。属于参数校验与编排，无业务数学，无网络、凭据、文件写入或任意代码执行。供历史情景和 ETL 直接调用，不建立不必要的独立服务。
- 历史情景保留原组件导出、DOM 测试标识、文案、颜色、输入检查及 mobile fallback；原父页面负责业务编辑和模型执行。原拓扑诊断由薄适配器保持 code/path/message/顺序。

## ETL 图合同

`steps` 仍是步骤与配置的唯一真相，不另存一份可能不一致的 edges。实线边来自 `inputs`（传递数据），虚线边来自新增 `after`（只控制先后、不提供数据）。连接端口生成这两类引用。布局以独立 `canvas` 字段保存节点位置和视口，明确不作为下载、映射、取值或快照参数。

旧流程没有 canvas/after 时无需迁移数据库，自动布局，使用原步骤顺序。新增 `graph_version=1` 的图流程按 inputs+after 做稳定拓扑排序；同层节点以 steps 顺序破平局。旧列表定义仍保留“依赖只能向前”的校验语义，防止悄悄改变历史执行契约。图流程可以任意添加顺序的节点，保存/运行时后端编译到原有顺序执行器。连线表达依赖，不承诺并行运行。

全量/增量依然由本次运行选择。运行冻结逻辑图及其编译后计划；画布位置不进入业务执行指纹或改变实际调用参数。失败恢复仍核验冻结代码/接口/制品，不重新执行成功节点。

## ETL 节点扩展

- 下载：输出原始批次；可用完成端口控制其他下载的开始。
- 映射：只接受一个下载的原始批次。
- 取值：接受多个映射批次，配置目标标准业务表和多源规则。
- 指标快照：接受已取值标准表；产品、净值、币种与复权等原有门禁不变。
- 数据集任务：复用已有任务目录，可接一个前置工作区；Tushare 全数据 31 节点也是普通任务配置，不出现流程专用组件。

全部节点提供完成/等待控制端口。前端阻止自环、循环、重复连接和错误类型；后端最终校验数据输入数量、表合同、接口版本、权限及快照完整性。删除节点一并清理引用和位置；复制所选子图重写内部引用，保留外部上游引用，新增 ID。改动均支持撤销重做。

## 界面

ETL 编排默认是大画布。顶部提供节点库、撤销/重做、自动布局、连接说明、元数据和保存/校验/运行；选中节点后才打开可收起检查器。默认节点卡显示名称、类型、执行序号、配置就绪状态。连接也可在检查器用表单完成，手机不用精确拖动端口。现有模式、日期等运行表单复用，运行模式不改流程修订。保留可折叠的执行顺序说明，明确拖位置不改运行顺序。

## 验收

先建立历史情景的抽取前测试基线，再跑抽取后回归；覆盖节点位置提交、复制、多选、端口标识、Undo/Redo、图序列化和原后端诊断。ETL 覆盖旧定义兼容、乱序 DAG 编译、数据/控制边、环/非法端口/未知节点、布局持久化与不污染计算参数、删除/复制、只读、保存重开及既有任务执行。真实浏览器检查 320/768/1440 视口及 Tushare 31 节点。测试离线，不触发下载、发布或覆盖活跃行情。

React Flow API 依据：https://reactflow.dev/api-reference/react-flow 。复用项目已安装依赖，不升级依赖。
