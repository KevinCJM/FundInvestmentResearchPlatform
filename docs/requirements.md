# 资产配置投研与组合管理平台需求说明

本文区分“当前已实现能力”和“目标平台需求”。完整产品架构见 [前端功能蓝图](frontend-investment-research-blueprint.md)，领域词义见 [CONTEXT.md](../CONTEXT.md)。

## 1. 产品目标

面向个人、企业和家族办公室等资产所有者，建设内部资产配置研究与真实组合管理平台：

- 持续研究 ETF、场外公募基金等底层产品并维护版本化产品池。
- 按资产主体的目标、期限、流动性、税务和风险约束开展 SAA、TAA 与产品配置研究。
- 管理资产主体、银行/券商/销售账户和内部真实组合。
- 将外部交易事实匹配、分摊并 Booking 为可追溯的持仓、投资账和绩效数据。
- 对真实组合开展 TWR、MWR/XIRR、收益归因、风险分析和研究反馈。

平台不面向外部客户销售，不建设基金设立募集、持有人份额、管理费收费、法定基金会计、监管报送或交易下单。

## 2. 目标用户

| 角色 | 主要诉求 |
| --- | --- |
| 个人资产所有者 | 以目标和风险为中心查看账户、组合、现金流与绩效 |
| 企业资金与投资团队 | 管理自有资金的安全性、流动性、收益性、投资核算及总账衔接 |
| 家族办公室 | 管理多个个人和持有实体，跨银行聚合并按所有权关系穿透汇总 |
| 量化研究员 | 产品研究、指标、产品池、配置模型、回测、情景和归因 |
| 组合责任人 | 维护目标版本、真实持仓、偏离、再平衡测算和复盘 |
| 投资运营 / 核算人员 | 数据导入、匹配、分摊、Booking、对账、关账和例外处理 |
| 系统管理员 | 数据、权限、审计、研究口径、指标、模型、场景、规则和系统参数 |

## 4. 目标业务需求

### 4.1 产品研究

- 基金市场概览、产品详情、产品对比和产品/外部基金经理研究。
- 持仓披露、穿透分析和带置信度的风格代理。
- 指标、评价方案、准入规则、产品池和版本生命周期。
- 产品与信号回测；历史数据必须使用 PIT 快照并保留退出产品。
- 业务页面选择已发布的研究口径与参数模板；研究任务启动时冻结引用版本，不在产品研究内重复维护公共参数。

### 4.2 投前研究

- 选择资产主体或目标模板，记录收益、风险、期限、流动性、税务和可投资范围。
- SAA：长期大类目标、上下限、有效前沿、固定权重候选和再平衡政策。
- TAA：相对 SAA 的动态大类偏离、状态算法、触发与恢复规则。
- 产品配置与择时：类内产品选择、权重、轮换、容量、成本和相关性约束。
- 目标组合合成、风险检查、样本外/滚动/压力/成本检验和版本冻结。

### 4.3 资产主体与组合

- 个人、企业、家族持有实体及其所有权/控制关系。
- 外部银行、券商和基金销售账户及账户归属。
- 内部真实组合、账户—组合多对多关系、目标版本、责任人和有效期。
- 组合是管理维度；只有独立法律或会计主体才启用独立法定账。

### 4.4 投中记录与实施测算

- 根据目标与实际偏离测算交易需求，不连接真实交易通道。
- 导入外部账户流水、成交、确认与交收文件。
- 匹配订单/成交/资金，按守恒规则分摊到同一资产主体的多个组合。
- 现金、交收、持仓和再平衡记录；异常进入待认领或例外队列。

### 4.5 投资运营与组合核算

- 原始事实、匹配、分摊、Booking、凭证和报表全链路追溯。
- IBOR 持仓现金、资产主体投资账、组合管理子账和 PBOR。
- 复式记账、科目与政策版本、试算平衡、现金/持仓/估值对账和期间关账。
- 企业主体支持公司总账科目映射和凭证导出；个人/家族主体提供投资辅助账和汇总报表。
- 表内/表外按资产主体判断；组合层使用纳入组合、组合外、待分配和备查分类。

### 4.6 投后与反馈

- 已核对的实际组合数据、TWR、MWR/XIRR、基准与目标偏离。
- 收益归因、风险归因、费用、汇率、现金流和交易时点分析。
- 持仓、产品、外部基金经理、风格漂移、流动性和情景压力监控。
- 研究假设复盘、产品池更新、模型比较、版本发布和内部报告归档。

### 4.7 设置与治理

- 数据源、数据质量、PIT 快照、研究口径与参数模板、指标与模型、情景算法和统一回测。
- 研究口径与参数模板统一维护基准、无风险利率、数据处理和计算口径，供产品、SAA、TAA、组合回测及投后分析按版本引用。
- 产品与账户映射、交易日历、币种、汇率、科目、会计政策和报表模板。
- 工作空间、角色、主体/组合级权限、职责分离、审计日志、备份和敏感数据保护。

## 5. 关键数据模型

```text
工作空间
  └─ 资产主体
       ├─ 所有权关系
       ├─ 外部账户
       ├─ 真实组合
       │    ├─ 目标配置版本
       │    ├─ 账户关系
       │    └─ 内部责任人
       └─ Booking
            ├─ 外部事实与分摊版本
            ├─ IBOR / ABOR
            └─ PBOR / 绩效与归因
```

## 6. 非功能需求

- **正确性**：原始事实不可静默覆盖；分摊守恒；凭证借贷平衡；主体与组合汇总可勾稽。
- **可追溯**：数据、模型、产品池、目标配置、分摊、凭证、估值和绩效均有版本和来源。
- **安全**：账户号、身份、所有权和家庭数据按高敏感信息管理；最小权限、加密、审计和导出水印。
- **可靠性**：重复导入幂等；缺失数据和对账差异不得静默通过；关账可控重开。
- **可复现**：研究回测绑定 PIT 数据、指标、规则、成本、基准和算法版本。
- **性能**：现有常用研究 API 在常规数据量下目标响应 1–2 秒；大规模回测与批处理应异步展示进度。
- **可维护性**：前后端模块化、测试覆盖关键领域规则，不在页面中硬编码会计和交易政策。

## 7. 交付优先级

| 阶段 | 重点 |
| --- | --- |
| P0 口径纠偏 | 统一资产主体语言，移除基金募集、管理费收入、管理人公司账和对外展示语义 |
| P1 主数据 | 资产主体、所有权结构、外部账户、真实组合及关系 |
| P2 运营事实 | 文件导入、匹配、待认领、组合分摊、Booking 和 IBOR |
| P3 投资核算 | 主体投资账、组合管理子账、对账、关账、企业总账映射 |
| P4 绩效研究 | PBOR、TWR、MWR/XIRR、归因、风险与内部报告 |
| P5 扩展 | 自动数据连接、低频估值资产、税务批次和现金流情景 |

## 8. 技术与数据约束

- Python 3.12，FastAPI + Pydantic；Node.js >= 18，React + TypeScript + Vite。
- 当前研究数据继续使用 `data/*.parquet` 和版本化 JSON；敏感 Token 不得提交或回传。
- 新增真实账户与交易数据后，不得继续依赖无身份隔离的实例级共享文件作为正式存储。
- 静态演示页面不得调用后端、持久化或模拟真实成功提交；已有真实页面不显示静态提示。
- 投中页面不得出现下单、委托提交和撤单入口。

## 9. 当前主要风险

1. 现有静态框架仍有公募基金管理人、基金会计和对外展示语义，需要按蓝图逐页纠偏。
2. 尚无资产主体、账户、组合和权限的正式后端数据模型。
3. 静态 Booking 页面不是会计引擎，不能作为核算正确性证明。
4. 当前工作区指标和评价方案为实例级共享，无法满足多主体敏感数据隔离。
5. 真实交易导入、对账、估值、会计政策和绩效现金流均待正式接口与测试。
