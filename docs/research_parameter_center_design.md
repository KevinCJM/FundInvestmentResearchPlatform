# 研究参数中心与运行口径分离

## 1. 需求结论与边界

指标定义回答“如何计算”，运行口径回答“使用什么基准、利率和年化约定”，数据快照回答“使用哪个时点的数据”。三者独立版本化，运行时组装；不能用修改公式来切换基准，也不能把修改默认值当成重写历史结果。

当前设置下的 research-parameters 与 system-parameters 都是演示页。本次统一使用“系统参数 → 研究计算口径”作为真实管理入口，research-parameters 跳转到同一入口，不建立两个相互冲突的默认值存储。系统运行环境、账户凭据不混入业务口径。

指标编辑器仅展示 benchmark_nav、benchmark_returns、risk_free_rate_per_observation 等类型化变量。指标中的窗口长度、ddof 等算法常量仍属于指标版本；基准成分、年化无风险利率属于运行参数。此前固定沪深300内置指标已从指标中心移除；本参数中心接入完成后的新指标应使用通用基准变量，不重新引入固定指数特例。

## 2. 面向人的操作

设置页两块：
1. 基准库：名称、单指数/加权指数、指数搜索、权重百分比、收益口径、币种、再平衡规则、启用状态。默认仅从本地真实指数目录选择；不隐式下载、不以价格指数冒充全收益指数。保存校验权重恰为100%，不偷偷归一化。
2. 默认计算口径：默认基准、无风险年利率（%）、年化观察数。保存前显示“只影响后续运行；已保存研究不变”。零利率明确标为假设，不宣称市场事实。

业务页使用共享“本次计算口径”组件，默认折叠为一行：基准名称 · 无风险利率 · 年化观察数。展开后选择基准/利率方案，可跳转设置维护。变更后清除旧结果或明确要求重新计算；不能只换标题不重算。产品对比、同一评价方案统一口径；不允许无提示地比较不同口径的Alpha、Sharpe。

指标中心的“校验与预览”也提供运行口径，但公式编辑区域不选具体指数。结果与导出显示实际冻结口径，不从最新设置反向补标题。

## 3. 数据模型与版本

- BenchmarkDefinition：id、revision、name、enabled、currency、return_basis、rebalance、components[{index_code,weight}]。
- AssumptionDefinition：id、revision、name、enabled、annual_risk_free_rate_percent、periods_per_year；首版以固定年化有效利率表达，不冒充可交易利率曲线。
- Library：revision、默认基准/利率方案引用、不可变历史版本。更新必须携带期望revision；冲突409。停用代替物理删除，旧版本继续可回放。
- CalculationContextRequest：benchmark_id/revision、assumption_id/revision。服务器解析默认值并冻结为完整快照、规范化hash；不能信任客户端上传的“已冻结参数值”。
- 运行结果：指标id/revision/output_id + calculation_context + 市场数据指纹 + 实际窗口。评价方案和预计算配置保存锁定参数引用，不跟随当前默认值漂移。

缓存中必须包含口径hash；编译计划身份不包含基准代码和具体利率值。切换基准、利率只换固定dtype入参数组，不产生新的JIT签名。

## 4. 后端实现

独立 research_parameters 模块：严格请求模型、原子版本库、解析器、指数数据适配、固定签名NJIT数值内核。复用已有AtomicJsonStore的文件锁和原子替换，不引入额外数据库。

接口：GET /api/research-parameters；GET /indices?q=；POST/PUT /benchmarks；POST/PUT /assumptions；PUT /defaults。既有指标预览、时序、导出、组合指标、评价方案和快照请求新增 calculation_context。

请求入口建立不可变、请求局部的计算上下文，嵌套调用继承；退出时恢复，线程间不共享可变配置。仅I/O与调度层读取该上下文，NJIT和worker只接收显式float64数组及数值参数，不能从计算内核访问Python对象。旧无参数历史方案走旧口径，不能自动套最新默认值。

通用基准提供器向指标供给归一化净值或收益序列。固定基准兼容变量只用于旧版本，不在新变量目录推荐。数据缺失、币种混用、日期区间不一致返回不可用原因，不填零、不替换基准。

## 5. 金融口径

首版加权基准明确为“每日恢复目标权重”：r_b,t = Σ w_i r_i,t；V_b,t = V_b,t-1 (1+r_b,t)，起点为1。不是原始指数点位加权。首版只支持同币种、统一收益口径的指数；跨币种须先实现FX数据映射，不伪装已支持。月度再平衡和买入持有不使用每日固定权重公式冒充。

固定年化无风险利率转换：r_f,obs=(1+r_f,annual)^(1/P)-1；自然日窗口使用365日有效年利率折算。P可由方案设置，必须为正整数。按真实日期对齐基准与产品，避免把多日收益当作单日收益。Alpha年化约定、残差波动率自由度继续由指标定义负责。

复合基准需要明确再平衡频率是实际方法差异，而不是展示差异。参考：MSCI Dynamic Planner官方介绍明确其复合指数按月再平衡（https://www.msci.com/indexes/index-series/multi-asset-indexes-dynamic-planner）；本系统首版选择每日规则并明确标注，不宣称复刻该指数。

## 6. 全投研流程接入

数据下载/ETL → 指数目录与真实价格数据 → 设置基准库/利率方案 → 指标公式声明参数 → 产品研究/详情/对比预览 → 评价方案锁定口径 → 产品池继承研究证据 → 投前SAA/TAA/产品配置按研究版本消费 → 组合回测快照 → 投后指标与归因 → 结果归档与复盘。

本次优先打通已有公共指标执行链及其真实页面。已有因子、SAA/TAA、会计/真实组合的独立计算引擎不得通过修改全局默认值悄悄改变已保存模型或实际业绩基准；应在各自新建研究任务时显式采用同一参数引用，并保留既有模型/法定核算边界。仍属演示的流程节点不宣称已具有真实运算。

## 7. 验收矩阵

版本冲突/停用/旧版本回放；权重重复、负值、非100%、NaN/Inf、未知指数；币种/收益口径；利率-100%边界；基准NAV与收益一致；复合加权参考一致；对齐/缺失/未来日期；切换基准与利率引发数值变化而非新JIT；线程隔离；缓存不串用；默认修改不改变锁定方案；单值/多值/时序/Excel/快照联动；中英文、键盘、移动端；保留现有工作区其他改动。

本文件记录设计，不代表所有验收已通过。实际完成范围和命令结果另记验收文档。
