# 风险模型与情景模拟闭环：产品及架构详细设计

日期：2026-09-10。目标项目：FundInvestmentResearchPlatform-frontend-framework。
本文件区分目标设计、当前交付能力和验收证据；测试结论另见同目录验收文档，不以设计替代实现。

## 1. 用户目标与边界

研究员在风险模型中心研究产品敏感度，在情景算法中心研究宏观传导和发布市场冲击；业务使用者在产品、SAA、TAA、组合与投后研究页面选择已发布成果。打开业务页面不得自动回归、校准或重新下载数据。

统一保留「情景算法中心 → 情景模拟与压测」，支持从宏观事件、宏观变量、市场风险因子开始。三者是分析入口，不是三个互不兼容的损益引擎。

### 核心对象及所有权

| 对象 | 所有者 | 用户可改 | 不可手改 |
|---|---|---|---|
| 标准变量/因子契约 | 共享数据目录 | 选择变量；明确导入自有序列 | 标准代码、单位、含义 |
| 产品风险模型方案 | 风险模型中心 | 对象、因子、窗口、频率、验证区间 | 回归系数 |
| 敏感度计算预览 | 风险模型中心 | 调整参数并重新计算 | 预览系数；未确认发布前不落盘 |
| 现金流估值研究 | 风险模型中心 | 原始现金流、基准收益率、计息约定 | 计算出的久期、凸度、价格 |
| 宏观传导方案 | 情景中心的传导研究 | 输入/输出变量、滞后、样本和验证参数 | 拟合出的传导强度 |
| 情景冲击路径 | 情景中心 | 三类入口、外生冲击、期限、模型引用 | 已发布路径及血缘 |
| 产品/组合压测结果 | 统一应用服务 | 选择已发布成果及研究对象 | 临时结果；当前版本不自动落盘 |

「设置」是导航分组，不意味着这些模块是简单系统参数；它们是公共研究设施。因子研究中心继续负责特征预测有效性和因子收益构建，不将特征分数冒充可定价风险因子。

## 2. 对现状的核实

当前 ScenarioAlgorithmCenter.tsx 有模板、路径、资产×因子手工矩阵、结果、比较和发布。scenario_stress/engine.py 与 numba_kernels.py 已提供历史重演、因子路径、随机模拟、状态条件抽样及单期反向压力。已有版本锁、缺失门禁和固定签名计算能力应复用。

需要解决的缺口：

- 没有独立的产品敏感度研究及发布流程；新业务应用不能依赖示例 Beta。
- 情景定义与组合权重耦合，不能方便地把同一市场冲击应用于不同对象。
- 缺少事件到宏观、宏观到市场的已校准模型及独立成果。
- 缺少可供业务页面直接读取的暴露和情景制品目录。
- 原确定性结果的 sum_of_period_contributions 是单期贡献之和，不等于复利终值贡献。新闭环必须使用期初财富链接并与终值损益对账，不能改名冒充等价。
- 原降级模式重新归一覆盖资产权重；新正式产品/组合应用不沿用该行为，缺失暴露阻断，不把未知风险变成无风险。

本次保留旧实验的真实路由和有测试覆盖的计算契约，作为「高级计算实验」入口；默认应用切换到已发布成果。历史实验不是新成果的自动迁移来源，尤其不能把手工系数自动认证为已训练暴露。

## 3. 量化解释与纠偏

### 3.1 三段链不是一种公认命名的因果识别方法

可采用分层工程结构：事件及外生驱动 → 宏观变量 → 市场风险因子 → 产品定价/敏感度 → 组合。实际市场有预期、同时反应和反馈；不能宣称所有冲击必须按此顺序发生。

普通回归、VAR 相关性、样本外 R²，以及项目已有的时点因果性审计，都不能单独证明经济因果。初始传导模型明确标为「条件统计传导」，不冒充 SVAR、结构性因果识别或经济预测。没有识别方案和可得数据，不内置虚构的经济敏感度。

事件名只是叙事模板。用户选择模板并给出量化的原始驱动，引用接受这些驱动的已发布事件→宏观模型；不得由「能源危机」直接查表生成 GDP 或股市跌幅。模板不规定通胀必然导致加息、黄金必然上涨等结论。

### 3.2 初始可执行模型

- 产品：多因子 OLS，使用现有共享的固定签名 attribution_kernel 求解；训练集标准化，输出还原到各因子的原始单位。产品模型使用同期风险暴露而非未来收益预测。
- 宏观：可配置有限滞后的多变量线性条件传导，联合回归求解复用同一内核。输入输出以各自定义的变动量为准；冲击投影剔除截距，表示相对无冲击基线的影响。普通统计模型不是经济因果证明。
- 债券：基于用户提供并冻结的确定现金流、基准到期收益率和复利频率计算价格、修正久期与凸度；单期冲击使用原始现金流重新估值。它不是从基金名称推断久期。现金流法不支持含权债、违约回收或未经建模的多期持有收益。
- 不宣称已具备 BVAR/SVAR、完整 Barra 协方差、衍生品全估值、流动性反馈、自动交易或行业校准参数。这些不是按钮名称，而应是后续独立且有数据和验收的能力。

### 3.3 变量语义

共享变量目录固定 ID、版本、市场、币种、角色、原始频率、原始数据来源、变换和输出单位。一个底层变量可承担多个角色，不因位于不同画布区域而复制成两个不同序列。

价格变量转换为单期简单收益；利率水平（百分数输入）转换为 bp 变动；宏观同比增速转换为百分点变动；PMI 等指数转换为点数变动。不把增长率下降 2 个百分点写成 GDP 水平下降 2%。

风险模型及情景的因子契约、频率、市场、币种必须相容；相同中文名字不是匹配依据。用户导入序列创建独立且不可变的变量身份，不覆盖标准变量，也不伪称官方数据。

### 3.4 时间与验证

- 日期轴先形成明确的完整研究频率网格，再变换和构造滞后；缺月保留缺月，不压缩成相邻月。
- 不把低频 GDP 前填成日频；季度模型和月度模型不得隐式混用。期末尚未结束的月/季不作为完整训练观察。日历覆盖检查只要求覆盖实际使用的最后完整周期，覆盖证据包含已知休市日；不因本月尚未同步完而阻断上月已完整的数据，也不把未完整覆盖的月份当成完成。
- 训练截止和验证起点明确分开；标准化只用训练数据，验证区间不参与系数估计。
- 样本量、有限值、变异性、数值退化、样本外表现和源数据时点证据分别展示。通过 R² 门槛不等于模型已证明因果。
- 数据截至日期、可得日期、运行时间、发布时间、生效时间、到期时间分开保存；历史消费同时检查发布时间和可得性，不允许今天发布的模型被当作过去已经可用。
- 新数据到达只提示重新研究；不得重写已发布结果。持仓或策略变化产生新应用快照。

## 4. 前端页面设计

### 4.1 设置 → 风险模型中心

桌面：窄左栏为成果/方案列表，主区域约占 75%。移动端上下排列。白色背景、短说明、一个主按钮；不用满屏技术卡片。

顶部：标题「风险模型中心」，说明「先研究产品怕什么，发布后供产品和组合使用」。右上仅保留「新建研究」。

一级标签：「研究方案」「已发布成果」「数据与因子」。

研究页三步：
1. **选对象和数据**：搜索 ETF/基金，显示已选对象；勾选风险因子，直接显示单位、可用状态和缺失原因；选择区间与频率。
2. **计算与验证**：主按钮「计算敏感度」。结果先显示「可发布/暂不可发布」及原因，再显示 Beta 表和训练/验证样本数、样本外表现。系数只读。模型、滞后及门槛等放入「高级参数」。**此阶段只在当前页面内存中保留结果，不写方案、系数或冻结数组到磁盘。** 修改定义立即标记结果过期，发布按钮失效；迟到请求不得覆盖新草稿。
3. **发布成果**：用户明确点击确认发布后，后端按同一定义重新计算并核对预览哈希；一致才原子写入运行、冻结数组和发布记录。显示「发布后业务页面直接读取本地结果」。未点击确认发布、关闭页面或放弃预览均不产生研究成果文件。

现金流研究使用独立表单：产品标识、现金流表、基准收益率和复利频率 → 计算价格/久期/凸度 → 发布。明确提示仅适用于该现金流假设，不适用于未知底层的债券基金。

已发布页：名称、模型方法、对象数、数据截止、生效及到期状态。点开显示因子暴露、输入摘要、验证结果、来源和发布版本；支持停用但不删除历史计算证据。

数据与因子：内置标准变量只读；提供自有 CSV 时序导入，需声明日期、数值含义、单位和频率；缺少发布时间时披露为导入时才可知，不伪造历史 PIT。

### 4.2 情景算法中心 → 情景模拟与压测

保留历史情景识别原页面及工作流。模拟区域提供「情景库」「新建情景」「宏观传导研究」「高级计算实验」，默认情景库/新建情景，不默认加载带演示数字的 Beta 表。

新建情景三步：
1. **从哪里开始？** 三个大选择项，各用一句示例说明：宏观事件（能源价格冲击）、宏观变量（通胀同比变化）、市场风险因子（股市下跌/利率上升）。
2. **设置变化**：事件入口先选已发布事件→宏观模型，再选相容的宏观→市场模型；宏观入口只选后者；市场入口直接选因子。没有相容成果，显示缺少哪一段并给「去研究传导模型」，不留一个空下拉框让用户猜。路径表只显示当前入口需要填写的列，单位常驻。默认显示「每期变动」，累积路径不得无提示按单期重复施加。
3. **预览并发布**：显示每段输入输出的只读路径表、引用版本及适用范围；强调「假设影响，不是预测，不附情景发生概率」。预览只存在于当前页面，不写磁盘；用户点击「确认发布情景」后，后端重新编译并核对预览哈希，一致才持久化情景路径和发布记录。

宏观传导研究复用研究工作台，按「事件驱动→宏观」「宏观→市场」分组。它不在产品研究页面出现。参数表可编辑，敏感性/滞后响应只读；经济因果未经识别时明确标注。

### 4.3 产品研究

新增/复用「风险与压测」独立区域，与「历史情景识别」「历史收益模拟」区分。打开后先读取已发布暴露：

- 有成果：暴露表、数据截止、模型版本、适用频率和有效性。
- 无成果：「这只产品尚无已发布风险模型」，按钮「到风险模型中心研究」，带入产品身份；不能自动训练。
- 陈旧、停用、不匹配：分别显示原因；不把缺失显示为 Beta=0。

下半区仅有：选择已发布情景 → 检查相容性 →「计算情景影响」。结果展示损益、路径最大回撤（仅有多期路径时）、产品/因子贡献以及估算限制；详细血缘折叠。**产品/组合压测结果是临时计算，不自动保存**；底层已发布敏感度和情景直接读取，不再次训练。

### 4.4 组合研究、SAA、TAA、投后

复用同一个 PublishedRiskPanel/应用工作区，不复制风险计算。

- 产品组合与持仓诊断：带入不可变运行 ID，由后端读取资产及期末持仓权重；不接受前端伪造的「已锁定组合」描述。
- SAA：支持使用已有组合研究快照或明确的代理产品映射；大类标签不能自动猜成某个基金。应用不会修改 SAA 权重。
- TAA：勾选「对比另一个已保存组合」，选择另一份不可变组合快照；两个请求锁定相同情景、暴露成果、研究日期、本金与持有规则。结果并列展示持仓日期和损益，但都只保留在当前页面；任一失败时不展示不完整对比。不将风险情景当作自动调仓指令。SAA、组合构建与持仓诊断复用同一能力。
- 投后：只在有真实持仓快照时称为实际组合；目前原型页面提供进入真实研究组合压测的入口，不假装已连上交易或会计持仓。
- 缺失任何非零权重资产的暴露都阻断。不自动删掉该资产并归一剩余权重。

页面间跳转只传对象 ID/组合运行 ID/模型发布 ID/情景发布 ID；来源和完整定义由后端解析。新压测结果不生成可跳转的持久化 impact ID。旧版本历史 impact ID 仅保留只读兼容入口。

## 5. 后端结构与接口

新增共享 sensitivity 包：类型契约、变量目录、受控数据适配、不可变制品存储、特征预处理及模型编排。数值回归复用既有因子研究 NJIT 内核；现金流定价和跨期贡献属于独立金融语义，提供固定签名 NJIT。

新增风险模型路由：目录、无副作用预览、确认发布、停用、已发布暴露查询。宏观传导使用同一校准实现，但按领域隔离发布目录；未发布草稿不保存。

scenario_stress 新增已发布情景服务：三入口编译、模型相容检查、无副作用预览、确认发布路径、统一临时应用，以及旧版历史应用的只读兼容。保留现有 engine 的真正历史/概率/反向计算用途，不复制同一数值算法。

建议路径：
- `/api/risk-models/catalog`、`/variables`、`/previews`、`/releases`、`/releases/{id}/retire`
- `/api/risk-models/runs/{id}`：只读取已经确认发布时形成的冻结运行。
- `/api/scenario-transmission/...`：相同的预览/发布操作，领域限定为两段宏观传导。
- `/api/published-scenarios/previews`、`/releases`、`/impacts`；`/impacts` 只返回临时计算，旧 `/impacts/{id}` 仅兼容历史落盘结果。

所有写接口使用严格契约，拒绝额外 beta/coef 字段；服务层再次校验，不能绕过前端直接写系数。错误用中文业务说明和结构化错误码。调用预算、行数、资产数、因子数、路径长度均有限制。

## 6. 持久化及磁盘

统一从已有逻辑 DATA_ROOT 进入，并使用现有 StorageManager/guard_path；不能把市场活跃快照目录当成研究成果根目录，也不能新增私有源码旁路径。现有整数据区磁盘迁移自然携带这些子目录。

```
DATA_ROOT/
  model_variables/                 # 独立可追溯的自有时序
  risk_models/                    # 仅确认发布后形成的产品运行及发布成果
  scenario_stress/
    transmission_models/          # 仅确认发布后形成的宏观传导运行及发布成果
    published/                    # 仅确认发布后形成的市场冲击路径
    impacts/                      # 仅旧版本兼容读取；当前版本不再写入
```

**持久化原则：只有用户确认发布才保存。** 模型计算、现金流计算、宏观传导计算和情景预览都只返回带 SHA256 预览哈希的临时结果，不创建研究文件；确认发布时重新计算/编译并校验哈希，一致后才把运行、冻结数组、情景路径和发布记录写成不可变制品。产品/组合压测结果当前也不自动保存。发布/停用是追加治理记录。数组用固定 dtype、明确形状的文件；清单保存 SHA256，读取核验，禁止 pickle 和任意路径。先写临时目录、fsync、原子提升，再写索引；并发写入持锁。磁盘未挂载时读写都失败，绝不回落至本地同名目录。

业务页面只读取已发布小清单和冻结成果；训练预览才加载行情。只有确认发布时冻结输入供复现。必要转换：源数据到标准日期/float64、一次频率网格、一次特征矩阵；运行内复用。显式导入自有时序属于数据导入操作，仍需要持久化，不属于“未发布研究结果”。

## 7. 损益及相容性

统计暴露：每期产品解释收益为 beta × 同口径因子变动，不把回归截距或残差当成情景冲击的确定结果。显示为「模型解释的情景影响」，不声称覆盖全部风险。

单期组合收益 = 初始权重 × 各产品收益之和；金额损益 = 初始组合市值 × 组合收益。多期默认买入持有，产品权重随净值漂移；固定权重模式必须明确表示每期再平衡及成本假设。

跨期贡献使用期初资产财富加权，各资产贡献之和必须等于组合终值收益；不能简单相加单期百分比。不对确定性冲击提供 VaR、ES、发生概率。逐点分位数也不能冒充一条真实随机路径。

现金流法暂限单次估值冲击：存储初始现金流及利率，用相同定价器计算冲击后价格；基准收益率与 shock 的 bp 转换只有一个来源，利差/曲线范围必须声明。当前仅接受「债券到期收益率平行变动」语义的因子；即使单位都是 bp，也不能直接把 Shibor、政策利率或信用利差当作相同的到期收益率冲击。负收益率在复利底数为正时允许，含权/违约/多期估值不冒充支持。

## 8. 算子粒度审查

- 日期网格/频率变换：只解决序列对齐和变换，结果可独立预览；不是新业务黑盒。
- 标准化和滞后特征：可独立测试，与校准内核分离；训练均值/尺度冻结。
- 回归：系数联合求解属于耦合内核，复用既有实现；不把每个 Beta 作为独立重复回归。
- 宏观投影：消费已训练参数和输入路径；不再次求解，不与产品聚合混为一体。
- 现金流价格/久期/凸度：共享同一现金流折现求导语义，多输出可保留。
- 产品冲击映射：复用既有 factor_to_asset_kernel；资产贡献/组合财富演进另行计算。
- 发布、存储、类型验证、页面展示是编排/I/O，不伪装成数值算子。

保留兼容入口原因：历史/概率/反向实验具有不同且仍真实调用的计算契约；不是用于回滚的旧代码副本。新发布链不绕过其历史限制。
