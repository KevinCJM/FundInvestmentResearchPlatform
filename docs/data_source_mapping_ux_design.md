# 数据源与接口映射：操作体验优化

## 定位与投研链路

代码依据：`frontend/src/app/processRegistry.ts`、`DataSourceCenter.tsx`、`backend/data_sources/service.py`、`mapping.py`。

业务主线：产品研究 → 产品评价与产品池 → 投前目标、SAA/TAA、产品配置与验证 → 投中执行研究 → 投后管理 → 反馈迭代。组合中心与基金会计是并行的事实支撑；不少投中、会计、投后节点仍标记为 prototype，不能把流程入口当成全部已经实现。

数据支撑线：连接数据源 → 定义接口及字段对应 → 样本验证 → 下载与候选结果 → 去重、身份核验、取值规则及快照发布 → 指标、因子、情景和配置研究。本页负责接入配置与验证，不代表完成下载，更不代表正式研究数据已经发布。

## 现状问题

- 来源、接口、标准表、身份解析、下载和发布同时出现，用户不知道从哪一步开始。
- 已有接口和新建接口使用近似相同的技术表单，普通使用者被迫阅读底层配置。
- 标准字段长表缺少搜索、必填缺项提示和清楚的字段流向。
- 启用、配置校验、凭据保存、真实连通、下载完成与发布的含义容易混淆。
- JSON 草稿无效时，父配置仍是旧值，必须避免继续以旧配置采样；切换步骤不能丢失尚未解析的输入。
- 修改目标表会重置字段和身份映射，必须事前确认。

## 用户路径

### 使用已有数据

选择来源 → 按基金净值、日行情等业务名称搜索 → 查看接口及目标数据 → 检查字段 → 离线预览或明确确认的单次真实采样 → 保存后进入下载工作区。

来源已经配置好时不引导重复新建。页面显示“映射待完善”“接口已停用”等具体状态；凭据已保存只表示具备配置，不表示真实连接成功。

### 接入新数据

新建来源并保存 → 独立保存凭据 → 新建接口 → 填写返回字段 → 对应系统字段 → 验证并保存 → 下载。接口参数保留类型，不把数字、布尔或嵌套对象默默转成字符串。

### 修复问题

筛选待完善接口或从失败候选批次定位接口 → 查看必填缺项和后端错误 → 修复 → 重新验证。不会自动替换已有研究数据。

## 页面与交互

- 首页：用途说明、紧凑连接状态、业务接口清单、状态与数据分类筛选、排序和下一步操作。
- 已有接口编辑：数据与接口、字段对应、验证与使用三个主要步骤。下载限额、分页等为独立高级设置，不夹在日常主路径中。
- 每步保留同一份草稿；隐藏而非销毁输入组件，非法 JSON 草稿也不丢失。
- 字段区：来源字段 → 系统字段 → 转换方式；支持搜索、必填和未配置筛选。缺少同名字段时不擅自选择第一个来源字段。
- 必填身份字段单独提示。系统批次、哈希、修订和采集时间仍由后端生成，不让用户重复配置。
- 保存与验证有明确反馈；修改配置后旧验证结果失效。后台返回的 valid/ready 仍是权威，前端缺项数量不是可执行判定。
- 删除映射、替换目标表和放弃未保存修改必须确认。
- 保存、校验、预览、采样及凭据请求期间禁止重复执行和切换当前配置，防止迟到响应覆盖其他接口。已有后台下载仍使用原任务机制。只读模式保留字段搜索、筛选和离线验证，仅禁止配置修改、保存、凭据变更和真实采样。

## 后端边界

复用 `/api/data-sources/catalog`、`/config/source`、`/config/interface`、`/credentials/{id}`、`/validate`、`/preview`、`/interfaces/{id}/sample`。

保存继续携带 expected_revision，冲突保留草稿。验证和离线预览不进行网络下载、不生成候选批次。真实采样继续显式确认并使用已保存版本；权限、凭据绑定、共享限流、超时、分页和快照发布仍由现有后端负责。

本次不改变外部供应商 API、下载器、数值计算、数据格式、权限判断或正式数据，不执行真实外网采样。

## 验收重点

- 用户进入页面后能看到已有业务数据及下一步，不必先新建来源。
- 按名称、分类、状态查找接口；无结果时有清空筛选入口。
- 三步切换、非法草稿保留、错误字段定位、只读行为均有测试。
- 必填缺项可见，切换目标表不会无提示地清空配置，不自动错配第一列。
- 保存携带修订号；修改后不得使用旧验证结论或对旧保存版本误采样。
- 离线预览、空样本、样本成功与下载、发布状态严格区分。
- 前端回归、构建、离线后端测试及浏览器交互检查；未执行项目须如实记录。

## 实施与验证结果

本次仅修改数据接入前端及相关测试，复用后端接口和原任务执行。新增 `ParameterEditor` 是参数键值表的唯一实现，保留文本前导零、数字、布尔、空值及嵌套对象。金额和大整数固定值以文本传给后端转换，避免 JavaScript 数字精度损失。没有创建旧版组件副本。

已验证：前端 6 个测试文件共 56 项通过（页面 26、参数表 4、数据模型 7、下载工作区 10、多源规则 5、接口同步 4）；后端数据源、AKShare 适配、ETL 快照/工作流、多源解析、路由与同步 146 项通过。Playwright 使用隔离的后端真实目录定义及离线 API 拦截，在 320、768、1440 三种宽度下共 3 项通过，无页面脚本异常、无整页横向溢出。生产构建和本次已跟踪文件的 `git diff --check` 通过。

保留事项：全量 TypeScript 检查在指标、产品研究等其他模块报告类型错误，本次修改文件未出现在错误列表；未扩改这些文件。构建仍提示浏览器兼容数据较旧和现有大包警告。没有执行真实供应商采样，也没有修改正式配置、凭据或已发布研究数据。

路由检查：本次 9 个源码和测试文件均由现有 `frontend_data_source_center` 模块覆盖；本说明是新增未跟踪文档，覆盖检查提示未登记。未更改共享路由文件或暂存用户工作区；在后续将本说明纳入版本管理时，再登记稳定文档路径。原有 `InterfaceEditor` 的请求参数表单定义能力及工作区其他未提交改动均保留。
