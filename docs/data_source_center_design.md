# 数据源与接口映射中心

## 统一下载与编排入口（2026-09-06）

来源中心继续负责接口、凭据、字段映射和取值规则配置。日常下载统一进入 `/settings/data-sources?source=<source_id>`，该页可以选择来源支持的数据、产品/日期及增量/全量，并保存用户定义的 ETL 顺序。来源概览不再仅为 Tushare 提供下载跳转。

ETL 复用本中心的协议适配器、限流、映射与取值引擎，将自动串联动作拆为独立步骤；执行数据依赖、运行修订、取消和失败恢复均有持久化记录。正式研究消费迁移仍未执行，候选、快照完成与发布必须分开。详细设计见 `docs/etl_workflow_design.md`。

## 本阶段边界

基于 `backend/data_model` 标准字段合同，提供可持久化、带修订号的数据源、接口、字段映射和下载约束配置。Tushare 的 40 个预置 API 配置接入现有 `T01_get_data.py` 调用边界；保留既有日期/代码分片、断点、模块选择和业务文件，不改变旧研究读取口径。

本阶段包含配置中心、真实单次采样、Tushare 候选映射双写、HTTP/Tushare/AKShare 的独立接口全量/增量下载，以及多源优先级与异常处理；**不包含定时调度或正式 Canonical 版本发布及研究消费者迁移**。配置存在、字段可映射、样本验证通过、候选已生成与正式发布是不同状态，不能混用。

## 信息架构

设置优先展示“数据同步与任务”，数据同步、来源映射和数据质量共享导航。日常 Tushare 更新不要求逐个编辑接口；来源中心默认展示连接、检查映射、同步/采样三步引导。需要修改时再打开来源或接口编辑器。移动端用紧凑接口选择器，桌面使用可筛选列表；返回协议、共享限制和高级参数按需展开。

标准表只读，系统字段不能直接映射。定义校验、样本转换、候选批次和正式发布分别说明，不合并成一个“成功”。失败候选可以定位到对应接口修复。HTTP、Tushare 和 AKShare 均可从接口详情启动受控后台下载；定时调度尚未开放。多源结果仍为未发布候选，不能误称已用于正式研究。详细用户流程见 `docs/data_sync_user_flow.md`。

### 外部业务数据与内部对照的边界

外部导入目录回答“系统需要或可以接收哪些业务数据”，不列出所有技术上能够写入的表。产品、机构、行情、净值、持仓，以及基金经理任职、指数成分、产品分类和基准等真实业务关系仍为外部导入对象。

`master.organization_identifier`、`master.person_identifier`、`master.instrument_identifier`、`portfolio.external_account_identifier` 仅保留为系统内部代码对照定义，`source_mappable=False`。用户在导入配置中设置来源字段和身份解析，业务记录使用解析后的内部 ID；不需要单独导入这四张对照表。数据字典只在高级内部视图展示它们，接口映射目标列表不提供它们，后端校验、预览与直接映射也拒绝将其作为导入目标。

此次只修正导入范围和展示语义，不改变表 ID、字段物理结构或已有业务映射的 `1.2.0` 合同版本。外部导入目录由 42 张调整为 38 张；总定义仍为 114 张。这些数量表示定义范围，不代表已接入数据或已完成正式发布。

## 组件

- `backend/data_sources/models.py`：严格配置模型，拒绝未知属性与无界下载。
- `store.py`：SQLite 原子配置、乐观锁、不可变修订、脱敏凭据引用。
- `presets.py`：Tushare 接口与映射默认值；缺失来源字段明确保留未映射，不编造金融值。
- `mapping.py`：响应解析、受控字段转换、标准字段校验与预览；无 eval/任意 Python。
- `runtime.py`：冻结配置、跨进程共享限流、受控 HTTP 请求；Tushare 兼容适配。
- `services/data_source_routes.py`：配置、校验、接口采样与既有下载衔接。
- 前端所有目录和字段均由后端提供，不再维护第二份标准表。

## 配置合同

来源级：名称、类型、基础 URL、启用状态、凭据是否已配置、共享配额。
接口级：唯一 ID、来源 ID、版本、方法、路径/API 名、默认参数、响应格式（records/columns/CSV）、数据路径、字段数组路径、原始字段定义、分页策略、日期参数、下载限制和多目标映射。
映射级：标准表版本、来源字段→目标字段、常量、缩放、日期/时间转换、枚举转换；身份绑定与审计生成不等同于外部字段直写。
约束级：请求/分钟、行数/分钟、单次行数、最小间隔、并发、连接/读取超时、重试次数、退避和最大页数。所有请求共享来源配额，接口配额为附加约束，不能各线程重复发放。

## 安全和一致性

不接受任意 Python、SQL、文件路径或任意 SDK 方法。HTTP 禁止私网/回环/链路本地目标，禁用重定向，限制响应大小；凭据独立私有存储，API 永不回显。修改使用 expected_revision，冲突返回 409；运行使用冻结配置，不在一次任务中热切换映射。单位变化、未知枚举、无效日期和非有限数值必须报错。PIT 日期缺失不能替代为观测日期。

## Tushare 约束依据

项目内当前没有接口 JSON，使用已安装 tushare-fetcher 的接口目录和现有脚本声明核对。官方文档核对入口：
- https://tushare.pro/document/2?doc_id=127
- https://tushare.pro/document/1?doc_id=108
- https://tushare.pro/document/1?doc_id=130

积分不是独立权限证明；新增接口默认禁用，用户确认权限后启用。内置接口保留现有执行范围，限制取配置与原运行边界的更严格值。现有标准化函数继续负责兼容文件；映射预览使用真实接口原始响应，避免发行规模、成交额重复换算。

## 使用说明

1. 设置 → 数据源与接口映射，选择 Tushare、AKShare 或新建来源。已有配置均为普通可编辑记录；不会被后续初始化覆盖。
2. 选择接口，编辑默认参数、响应格式、来源字段、标准映射和下载限制，保存生成新修订；收到 409 时保留草稿并重新加载，不覆盖他人的修订。
3. 粘贴样本可离线验证；真实采样要求先保存、明确确认，最多一次请求，不写正式数据。
4. 所有来源均可在接口详情“下载与更新此接口”中指定范围，增量模式沿用同配置同产品断点。Tushare 原全市场流程保留旧入口；协议和分页可编辑，下载器按保存值执行，不兼容设置明确报错，不静默还原。
5. 下载后查看标准候选及多源结果；需要人员或基金产品人工身份对照的映射会明确提示。系统 ID、批次、哈希无需手填，系统维护字段有独立底色和文字标签。
6. 打开“多源取值规则”，调整来源顺序、表级覆盖、缺失/异常替代、冲突处理、必需字段和容差。保存后可对已下载候选执行取值，不会再次请求数据源。详情可查看替代原因、冲突字段、选中来源和批次。
