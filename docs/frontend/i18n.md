# 语言与业务术语

本页负责系统翻译、可编辑业务术语、动态语言和修订；视觉规则见[前端设计准则](README.md)。

## 矩阵与运行契约
- 设置页保留系统只读表、业务可编辑表、业务修订历史。前两表统一为代码首列、语言横列，不再以中文标题和“默认／自定义”作为三个主要列。
- 全部分类显示完整键，如 `axes.asset`；筛选某命名空间时显示其内部代码，如 `asset`。底层始终按完整键加语言代码定位，翻译文本永远不是主键。单元格详情提供完整键和默认译文。
- 第一列和表头冻结。支持双击、Enter/F2 编辑，方向键定位，Shift 扩展区域，TSV 矩形复制粘贴；逐格或整块编辑只形成草稿，显式批量保存才发布。单次最多 1000 个变更，粘贴越界或存在非法单元格时整块拒绝。
- 表头“＋ 添加语言”和“管理语言列”接入动态注册表，最多 24 种语言；允许规范化后的语言—文字—地区代码子集，如 `ja-JP`、`zh-Hant-TW`，不支持扩展或私用标签。内置中文和英文配置受保护；新增语言可以改显示名、排序、启停，不能删除已登记的语言代码，停用保留译文。
- 语言回退只指向内置中文或英文，禁止跨语言继承用户的自定义术语。新语言的系统表显示“未提供系统语言包”；业务单元格没有实际译文时标记“未翻译”，另行提示运行时回退文本，不把回退文本计作翻译完成。
- 新增 `GET /api/i18n/matrix` 和 `PUT /api/i18n/languages`；原有 catalog、bundle、编辑、导入、历史接口保留。语言列表和默认语言共享 preferences 修订；业务译文有独立修订。写入统一按 preferences → business 顺序加锁。旧版语言偏好按原值兼容迁移。
- 新语言运行时会进入页面和顶部语言选择器；本地语言列表缓存支持已登记语言重载。语言切换只影响展示，不修改公式、用户备注或计算定义指纹。当前没有新增数值内核。
- 本次修复了窄屏固定列遮住译文、未提交编辑丢失、重置自定义语言时缺少回退预览、以及顶部仍固定双语言选项的问题。历史验证范围见[工程纪要](../verification/engineering.md)。

## 服务与持久化约束

- 设置页明确分为“系统翻译（内置只读）”“业务翻译（可自定义）”“修改历史”，不能靠前端禁用按钮保护系统词条。
- 系统目录 `locales/system.json` 与 `locales/navigation.json` 只随代码发布，不提供运行时修改接口；业务默认目录 `locales/business.json` 与领域注册表关联，运行时只写独立 `i18n_business_overrides.json`。工作区默认语言单独写 `i18n_preferences.json`。
- 翻译引擎使用 i18next / react-i18next，固定 system / business 命名空间，不允许跨命名空间回退；浏览器偏好与工作区默认语言分开。
- 普通编辑、导入、恢复历史全部经过同一后端白名单、占位符、长度、文本安全及乐观锁验证。系统词条无法通过伪造请求改写。
- 导入先验证并查看差异，再以绑定内容和版本的确认摘要应用；导出只含业务覆盖。恢复历史创建新修订，不倒退修订号。
- 全站可接入统一 t/term/Intl 边界；菜单全部接入，业务标签以稳定注册标识关联。未迁移的旧页面和缺失译文明确统计，不通过 DOM 替换或翻译输入值伪造覆盖率。

## 数据与安全
### 稳定键

- `navigation.settings`
- `indicator.graph.actions.validate`
- `indicator.graph.nodeKinds.constant`
- `domain.variables.returns.label`
- `domain.variables.returns.description`
- `domain.operators.rolling_mean.label`
- `domain.operators.rolling_mean.parameters.window.label`
- `domain.valueTypes.scalar.numeric`
- `domain.axes.time`
- `errors.GRAPH_CYCLE.message`

不能用当前中文原文作主键，也不能因为两个地方都是“输入”就合并成同一个领域术语。字面相同不代表业务含义相同。

### 默认词条

维护在版本控制中的 `locales/system.json`、`locales/navigation.json` 和 `locales/business.json`；不使用早期规划的每语言子目录布局。词条注册描述包含 key、模块、适用对象、默认语言、占位符、是否允许术语覆盖、字数上限和使用位置。注册表负责绑定 key；翻译目录负责各语言的文字，避免前后端各自维护完整默认文案。

### 工作区覆盖

独立持久化：`schema_version`、`revision`、`default_locale`、`overrides[locale][key]`、变更时间、历史版本。沿用项目的原子写入和独立乐观锁，避免两个人同时改术语造成覆盖。

同一目标语言内先取工作区覆盖，再取系统默认；不存在时按显式 fallback 语言规则回退。某语言的自定义中文不能覆盖另一个语言的默认英文。无法解析的 key 提供可定位的中文兜底及诊断，不能在业务页面直接裸露原始代码标识。

首次不加入“个人术语覆盖”，避免同事在同一套研究结果里看到不一致术语；将来确有需求，再在个人语言偏好之外单独设计。

## 当前边界

系统文本只随代码发布，用户不能通过普通编辑、导入或恢复请求改写。业务覆盖与用户自由文本分开；语言切换不改公式、备注、计算 ID 或定义指纹。

矩阵为当前交互，不再维护早期单语言表格方案。显式批量保存前只有草稿；revision 冲突保留本地编辑。动态语言停用保留译文，不删除语言身份或伪造系统语言包。

历史验收覆盖系统只读、动态语言、矩形粘贴原子拒绝、恢复新修订、窄屏固定列和运行时切换。剩余未迁移页面及缺译应按真实覆盖统计，见[工程纪要](../verification/engineering.md)。
