# 数据下载与 ETL 编排

本页负责执行图、全量／增量、失败隔离、状态与恢复。接口及映射见[数据源中心](README.md)，数据目录迁移见[存储契约](storage.md)，Tushare 接口／文件／schema 见[下载契约](tushare-download.md)。

## 用户操作

选择来源和数据集，填写范围或分析自动增量计划，校验后明确启动。快速下载生成可审阅流程；需要控制依赖时进入公共计算图。节点表单由后端合同生成，不根据供应商名称分叉页面。

流程列表、保存修订、运行记录、取消和“继续未完成步骤”分别操作。运行卡片优先显示当前节点、阶段、进度及可执行恢复动作；分页安全上限不冒充真实总页数，累计响应行数不冒充新增记录数。

## 执行图与兼容
当前 `graph_version=1` 的输入与执行依赖具有不同失败语义：

- `inputs` 实线：真正使用上游数据；上游失败或阻断时，本节点标记“依赖阻断”，列出缺失的上游。
- `after` 虚线：仅等待上游结束，失败、阻断也允许继续；不继承上游工作区。节点仍按稳定拓扑逐个执行，节点内部并发不变。
- 取消、流程总超时、实现/配置/制品被修改、存储离线/空间不足和控制库安全故障停止整个流程。普通接口失败只阻断数据后代。
- 所有可执行节点结束后，只要有失败或阻断，整次运行仍为失败，给出失败/阻断摘要，不发布半成品。恢复只重跑未完成步骤，已成功独立分支先验哈希后复用。

检查器每条连接可切换“必须依赖其数据”与“仅执行顺序”。服务端仍检查必需输入，不能借此绕过日历、产品目录或质量校验。“按数据需求重新梳理依赖”调用 `POST /api/data-sources/etl/dependencies/plan`，依据任务注册表的 requires/provides 重建当前草稿，保留原执行先后，支持撤销和过期响应保护，不自动保存或下载。

新全数据模板已使用真实依赖：指数覆盖快照需要所选行情分支，不依赖指数成分权重；宏观采集与成分权重不存在数据依赖。快照实际依赖的数据失败仍阻断。旧定义/旧运行不原地改变；没有图版本的旧运行保持冻结的 fail-fast 合同，可复制到编辑器后显式梳理并保存新版本，不能暗改旧任务的连线以绕过恢复校验。
ETL 默认使用从历史情景识别抽取的公共计算图画布；不再逐步铺开全部配置表单。节点库按后端 `graph_schemas` 生成，下载、映射、取值、快照和数据集任务都使用同一组件。节点参数通过按需打开的检查器编辑，保留通用接口参数和任务目录。

数据边来自 `inputs`，控制边来自 `after`。实线传递数据，虚线仅控制先后；拖动位置不会改变任务顺序。新 `graph_version=1` 定义可乱序存放节点，后端用 `backend/computation_graph` 编译稳定拓扑顺序后再交给现有执行器（不是并行执行）。后端继续检查数据类型、数量、表关系与快照必需输入。

旧保存流程不需要批量迁移，画布适配层将原顺序显示为必要的控制依赖。明确保存时写入新图版本及 `canvas` 位置/视口，既有 Tushare 31 节点流程可直接打开。删除节点同步清理相关引用；子图复制重写内部 ID；撤销、重做、移动端连接表单和只读门禁共用公共实现。

保存的图含界面布局；实际运行冻结原模板与编译后的业务定义，`canvas` 不进入计算参数。全量/增量仍是每次运行选项，历史候选、权限、限流、失败恢复和未发布边界不变。公用模块与回归依据见 `docs/indicators/computation-graph.md`。

## 最新补充：通用前端与全数据任务

编排器不按供应商或流程 ID 选择组件。运行表单由 `parameters` 渲染，普通接口表单由 `request_fields` 渲染；缺少请求合同则保留通用 JSON 参数入口，不再从输出字段推测产品代码。用户可以直接在表单里新增运行参数。

新增 `task` 数据集节点：由 `/api/data-sources/etl/tasks` 返回任务目录、可选来源、参数、前置能力和输出说明。同一种编辑器支持任意已登记任务。任务可增删、调序、设置输入及参数绑定，模板只是保存的普通定义。

Tushare 全数据同步定义包含 30 个已支持采集/派生动作及独立指标快照，共 31 节点、覆盖当前 40 个已配置接口。只需开始日期、截止日期及本次模式，不需要单个 ETF 或基金代码。原 17 步指定产品流程保留。基于已有采集器进行全市场产品遍历及分片，不把 100000 行限制的单接口试算器改成无界全表扫描。

## 步骤与运行身份

download 生成受控 Raw 制品；map 消费单个下载结果；resolve 消费明确候选并冻结取值规则；snapshot 只消费完整合法输入；task 调用已登记数据集能力。节点可以在定义中乱序存储，由稳定拓扑编译执行；禁止循环和孤立引用。不得保留已过时的“必须只引用列表前序节点”规则。

快照要求产品主数据与合法净值，不把单位净值填成 adjusted_nav，也不偷偷读取旧活跃价格。布局 canvas 不参与计算身份。
### 流程定义与运行选项分离（2026-09-06）

同一条流程支持全量和增量，不为两种模式复制流程。`POST /runs` 的 `options.mode` 为本次全量/增量选择，默认 incremental。下载步骤 `mode=inherit` 跟随本次运行；产品信息、日历等可明确配置 `full` 每次刷新。历史已保存步骤的显式模式仍保留，不静默迁移历史定义。

流程可声明具名 `parameters`，下载步骤的 `parameter_bindings` 把参数 ID 绑定至接口字段。运行的 `options.parameters` 提供产品代码和日期。必填参数未填时可以保存流程，但启动校验拒绝；不将缺失代码解释为全市场请求。绑定仅为受控值替换，不执行模板语言或 Python。

运行保存原始 `template_definition`、具体绑定后的 `definition`、`options`；冻结每个下载的实际模式、请求日期和断点键。同一 request_id 更改模式/参数会冲突，恢复仍使用原范围，不重新读取已变化断点。快照按完整指定输入重建，不把增量下载误解为只计算新增行。

### Tushare 基金同步流程

流程名：**Tushare ETF 与公募基金数据同步**。按用户请求通过普通流程保存 API 创建，可编辑和删除，不在初始化时自动复活或覆盖。

包含 17 个步骤：SSE 日历下载/映射/取值；ETF 与场外基金信息分别下载/映射后统一取值；ETF 与场外基金净值分别下载/映射后合并；ETF 行情下载/映射/取值；最后指标快照。运行必填一只 ETF 代码、一只场外基金代码及截止日，历史起点默认 2010-01-01。范围是指定产品，不是全市场。

基础信息与日历固定全量刷新；净值和行情跟随运行模式。主数据只使用本次记录，避免混用不同采集日的主数据版本；净值、行情的 `history_scope=matching_inputs` 仅纳入同接口、同产品和同非日期口径的历史候选。默认 `history_scope=table` 保留旧流程整表历史行为。

`GET /templates/tushare-funds` 仅生成基于已保存接口修订的流程草稿，不写流程、不触发网络；使用既有 PUT /workflows/{id} 保存。

### 取数与发布边界

“全量”是重新请求用户选定接口/产品/区间，不是删除整个数据仓库，也不宣称自动下载全市场。“增量”复用相同来源/接口修订、非日期参数的成功断点并回查 3 天；无断点时从指定起点开始。映射未成功不推进断点。旧 Tushare 模块级全市场下载仍由原下载器执行。

历史候选复用可单独关闭。合并只接受冻结历史批次和显式引用的本次映射批次，按请求日期范围筛选。全量重新取得的重叠记录按同来源修订规则取新值，未返回行不会被假定为供应商明确删除。显式删除/撤回协议不在本轮实现。

正式研究读取迁移和自动发布继续保持原阶段边界。ETL候选页面明确显示“候选未发布”，不把下载成功、取值通过、快照完成等同于替换正式数据。定时触发可后续复用流程 ID，不在本轮引入调度器。
## 一致性与安全

运行启动持有全局刷新锁直到结束，防止旧下载器、单接口下载、配置修改与 ETL 相互穿插。运行冻结流程版本、来源/接口修订、取值规则、历史候选清单和指标配置；不持久化明文凭据。网络使用现有 SSRF 防护、目的地址绑定、共享配额、有界重试和 SDK 隔离。禁止用户脚本/SQL/任意文件路径。

步骤制品先写临时文件再原子切换。恢复前核验所有已成功步骤的制品哈希；源配置已变化则拒绝继续并要求新运行，不能以新规则静默重跑。跨进程读取运行状态；API退出后健康worker继续运行；核验worker确已退出且锁可接管时才标记 interrupted，不能永久显示运行中。重复请求 request_id 不启动第二个任务。旧无图版本运行失败阻断后续，新图按本文顶部的数据依赖隔离；两者均禁止快照使用缺失的必需输入。允许空数据是显式选项，默认失败关闭。

最长流程运行时间有上限，每次网络调用及分页之间检查取消与剩余时间。快照在受控子进程运行，取消/超时终止该私有计算而不触碰正式文件。

## API

位于 `/api/data-sources/etl`：
- GET /workflows；PUT /workflows/{id}；DELETE /workflows/{id}（expected_revision）
- POST /validate（返回错误、步骤摘要、快照依赖）
- POST /runs（definition 或 workflow_id+revision，request_id，confirm=true，options.mode、options.parameters）
- GET /runs；GET /runs/{id}
- POST /runs/{id}/cancel；POST /runs/{id}/resume（confirm=true）

只读环境仍可查看/校验，运行、保存、恢复与取消遵循环境写入开关及同源请求检查。

## 独立执行与恢复

ETL worker 与 API 生命周期分离；重启 API 不应杀死健康下载。状态读取核对 PID、出生标识、工作目录与持锁者；SQLite 事务只包围短写入，不在网络请求或长期文件校验期间持写锁。

取消和恢复使用正式接口。跨代码版本恢复保持原日期、auto_plan、输入基线与来源配置；只有已验证兼容的检查点可迁移。自动图允许复用非连续成功分支，但真实 inputs 必须全部满足；旧单链合同保留连续前缀限制。每个未完成工作区分别验证，不能只迁移首个失败节点。

## 需求与边界

“自动”指用户触发后自动推断取数范围，不是定时任务。保留手动增量和全量模式；新增 `options.mode=auto_incremental`。用户只选数据集，先看只读计划，再确认下载，不填写日期。

原数据集 ETL 只识别同流程且整次成功的私有基线。没有该基线时，即使选择增量也可能初始化全部历史。自动模式默认使用当前活跃快照；用户可显式选择完成下载补足缺失表，没有基线绝不降级全量，不修改既有运行及其冻结参数。

## 用户流程

1. 设置 → 数据下载 → **自动增量（无需日期）**。
2. 选择数据集，服务端目录的 `requires/provides` 自动展开目录、日历等前置步骤。
3. **分析快照并预览区间**：只读 Parquet 元数据和交易日历，不访问供应商、不创建下载任务。
4. 展示快照名称、各数据集已有最新日、回查开始日、请求截止、更新策略及阻断原因。
5. **确认计划并开始自动增量**：携带计划 ID；锁内复查快照和来源配置，变化则要求重新预览。
6. 运行记录保留已确认的日期与基线。用户更改选择或启动失败后，旧预览失效。

ETL 编排器也提供自动模式：隐藏日期型运行参数，必须先“分析自动增量区间”。自动模式使用服务端数据集合同，不执行节点上原先写死的全量策略或旧日期。单接口下载/映射流程继续使用原手动模式；不把一个接口配置推测为完整市场数据集。

## 区间规则

| 数据类型 | 自动行为 |
| --- | --- |
| ETF / 场外基金净值、ETF 行情与份额 | 各自读取真实文件最新日期，含该日向前回查 5 个 SSE 交易日；截止上海时区昨日 |
| ETF / 场外基金净值、ETF 行情中的无历史代码 | 在全市场逐日更新前，单独按代码补齐；取已有快照历史起点与产品生命周期起点的较晚者，不重拉已有代码历史 |
| 指数行情与估值、基金复权、宏观利率 | 使用登记的文件/日期列推断；多文件分组采用最早的所需回查起点，传给已有分片采集器 |
| 持仓披露、分红 | 优先读取与基线 Parquet 绑定的公告日查询覆盖；补未查询日期，已查询且仍新鲜的日期复用。修订复核独立配置，不套用 5 个交易日 |
| 日历 | 先补至昨日，已经覆盖则复用；没有可用 SSE 日历时阻断 |
| 目录、经理、基准、增长通胀/货币/发布日历 | 按原有采集器刷新；宏观旧 vintage 保留。不宣称这些接口都是增量接口或常数时间 |
| 本地派生/指标快照 | 使用前置完整候选数据重建，原 NJIT 计算链不变 |
| 指数成分与权重 | 暂不开放自动区间合同，界面明确标示手动更新，禁止猜测日期 |

昨日只是请求上界，不是“数据已经披露”的断言。净值实际请求仍遵循现有交易日批次与空响应确认策略；迟报及修订通过重叠窗口重取。无历史代码已确认无数据仍记录采集器检查点，不用零填补。

**不承诺修复全部历史缺口**：现有代码在最近 5 个交易日之前的稀疏缺失，以及更早的修订，不由最新日期推断出来，仍需数据质量诊断和手动补历史。对于从快照中读出的最早待补范围超过一年的情况，失败关闭，要求分段手动补齐。空文件、未知日期、未来净值、失效 manifest、无基线都不能静默初始化。

## 后端实现

- `auto_incremental.py` 管理数据集范围合同与只读 planner。日期优先读取 Parquet row-group statistics；缺统计时只分批投影日期列，不读取完整净值矩阵。
- 扩展现有 `POST /api/data-sources/etl/validate` 返回 `auto_plan`；`POST /runs` 要求 `auto_plan_id`。旧 API 参数保持兼容。
- 计划 ID 包含执行图、日期策略、基线文件 size/mtime、来源/接口配置修订。启动采用现有全局下载锁，再验证计划；复制前后检查文件身份。
- 只复制所需时序基线和日历，宏观相关任务额外保留小型 vintage 文件。使用现有 macOS Copy-on-Write 或安全复制，不使用可写硬链接；私有清单存 checksum，后续恢复沿用冻结制品。
- 工作进程接收固定 `auto_step`；新模式没有 `has_baseline` 或已确认步骤时拒绝执行。已有代码走逐日/分页增量；无历史代码补齐后仍使用最初冻结的日期窗口，不能被新写入数据的 latest 截断。
- 原有 16 线程池、来源/API 双层共享配额、请求超时、重试、分页与行数上限不提升、不绕过。沿用已配置接口，不引入新供应商权限。
- 新增逻辑只涉及元数据读取、日期调度、文件复制和结果封装，不新增金融数学内核、不改变 NJIT 数值计算或启动预热。

## 数据发布与重复运行

自动下载结果仍是私有兼容数据和映射候选，**不会自动激活或覆盖正式快照**。最新日期只依赖实际返回的数据，不能提前推进到请求截止日。研究基线默认不变；用户可明确选择已完成任务作为采集基线，不把未发布的候选当作正式研究数据。

## 查询覆盖与事件增量优化（2026-09-10）

- `event_coverage.py` 是唯一事件覆盖规划实现，记录最新数据日之外的公告日查询覆盖、复核时间、基金身份集合、来源配置哈希和结果 Parquet 校验和。每个数据集只增加一个 `*.coverage.meta.json`，经现有清单/CoW 传递，不引入数据库迁移或为每个空基金生成长期覆盖文件。
- 只有完整分片及最终合并均通过后，才能提交覆盖；已独立复核的空响应可以推进查询覆盖，但绝不生成虚构数据行。缺失、损坏、来源变化、未完成 SPLIT 均不是可跳过的凭据。预览只读小型清单；启动/执行核验实际数据 checksum。必要代价为流式哈希读取，不解码完整金融矩阵，不新增金融数值计算或 NJIT 回退。
- 默认 `event_update_purpose=update`、复核间隔 7 天、近期窗口 90 个自然日；可改为主动 `recheck`。默认只更新未查询日期以及到期的已覆盖近期日期；同一截止/范围/有效覆盖重复运行不请求供应商。旧数据无覆盖证据时从最新公告日重查，不编造历史覆盖，也不自动回退完整历史。
- `auto_baseline_scope=acquisition` 必须配合明确选择成功任务，允许用较新的候选数据及其覆盖作为本次私有采集基线；旧客户端保持 `missing_only` 兼容语义。候选不得比活跃表更旧，不能借用只有覆盖却没有对应数据的记录。活跃研究文件和 manifest 永不改写。
- 持仓增量按全市场 `ann_date + offset/limit` 顺序分页，校验日期、页长和业务键；原始行数决定游标与末页，不能用去重后行数提前结束。跨页键重叠或同页数值冲突时，取得末页后按原 offset 完整复读全部页面，逐页全字段、原始顺序和 SHA-256 均一致才合并完全相同记录；无重复或冲突时不增加整轮复核。稳定数值冲突按本文上方隔离合同留档，不能当作质量通过；整页无新键、复核变化、未知末页、权限错误仍失败关闭。两轮读取及空页复核共享原请求预算、限流、超时与取消，不扩张逐基金遍历。全历史按基金/公告区间二分的现有合同保留，转型前历史不按当前成立日删除。
- 第一个空页只由调用方复核，后续空末页由分页器复核，修复空基金/日被复核两层而产生 4 次请求的问题；正常空查询固定 2 次成功请求，不取消独立复核。共享配额、连接/读取超时、有界重试及取消契约不变。
- 有覆盖时新增持仓基金身份单独按原历史起点补齐，再合并本次市场日期；分红不猜测未核定的单基金区间接口，目录变化时复核已有公告日。执行中暴露该变化；超出冻结范围或不支持的部分工作区迁移仍失败关闭，保留证据，不能强行按成功复用。
- 自动增量跨代码版本恢复沿用原 `auto_plan` 和 `task_baseline`，不按恢复当天重算日期。任务合同不变时，可复用非连续的成功节点，但它们的必需 `inputs` 上游必须全部成功；`after` 只约束顺序。逐一校验所有已经执行但未完成的工作区，分别迁移检查点，不只处理第一个失败节点；从未执行的节点在上游完成后才解析输入。共用正式执行的多输入清单解析。原文件/行数/校验和、分片和空复核均校验后导入新任务，SPLIT 仅审计而非完成；旧运行不改写。旧非自动单链合同仍要求成功前缀连续。
- 前端提供更新目的和修订间隔，区分最新公告日、已查询至、最近复核、本次新增/复核/复用天数和分页成本参考。运行页区分日期进度、分页位置、逐基金进度；分页安全上限不是总页数。累计接收不冒充新增/修订行数，未逐键比较的行数明确不作推断。

验收覆盖：相同截止零重复请求、截止增加一天只查询新日、覆盖空洞、到期与主动复核、损坏或不同来源拒绝复用、空查询 2 次、全市场跨页无逐基金扩张、旧图冻结基线/日期的跨版本恢复及旧记录不可变。时间策略和计数属于 I/O/编排元数据，不新增数值算子。

## 2026-09-11 持仓数值冲突隔离

- 目标：完整采集与质量放行分离。供应商稳定返回不同数值不等于网络故障，不盲目重试同一完整日期；也不按最后值/最大值/求和捏造答案。
- 批次边界：同一完整采集响应集合内同键多值才作为待核验冲突；前后两批各自唯一且有效的新值不同属于供应商修订，继续由唯一的 `append_incremental_rows` 按业务键 Update 私有候选，保留新采集时间，不能误报冲突或覆盖旧快照。分页复读中的内容漂移不能直接局部 Update，需重新取得完整一致的一批，避免混合页造成漏行。
- 分页发生键重叠或同页冲突时，必须先取得原始末页，再按相同 offset 完整复读并校验内容/顺序哈希。只有稳定且完整的响应才进入隔离处理；分页缺失、重放、漂移、超时及预算问题仍停止。
- 冲突的全部原始变体独立保存，候选表保留唯一业务键占位，四个数值字段为缺失，`availability_status=source_conflict`。不影响其他记录，不将旧基线的值冒充本轮确定值。
- 冲突检查点附带哈希、行数、身份及记录时间；恢复必须同时验证原始变体和空值占位。最终 Parquet 与冲突证据通过质量清单绑定，已下载不代表已经解决数值冲突。
- 前端摘要和步骤显示“采集完成 · 数据待核验”，披露冲突数量、原始证据和不可发布状态。含冲突结果禁止作为自动增量基线、下游计算输入或活跃研究快照；独立节点继续执行。
