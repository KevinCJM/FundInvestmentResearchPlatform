# AI 助手对话界面优化设计

日期：2026-09-20。状态：**已实施；首轮验收见第 10 节，紧凑改版见第 11 节，独立新对话见第 12 节**。第 11 节及设计准则15.6覆盖前文中已经调整的常驻模型行、文字按钮和输入区域规格。

交互样稿：[打开 UI 原型](ai-assistant-conversation-ui-prototype-2026-09-20.html)。原型使用明确标记的示例状态，不连接模型、不写入指标库。

## 1. 设计结论

保留小牛悬浮入口，将助手做成**可展开阅读的研究对话窗**：对话占据主要空间，处理过程轻量展示，指标草稿和试算入口附属于产生它们的回复。沿用品牌蓝、系统中文字体、现有 React/Tailwind 和 Markdown/KaTeX，不引入 UI 框架。

本次交付设计、交互样稿及业务页面实现。助手称谓统一为“AI 助手”；“指标”只出现在当前业务的上下文及成果中。通用外观不代表其他中心已经接入工具。

## 2. 实施前界面的核实结果

依据：本轮通过 CodeGraph 读取当前代码；Chrome 中打开 `http://127.0.0.1:5177/settings/indicators-models` 并展开助手；查看上一轮 320px、1440px 浏览器截图。历史截图是补充证据，不等于本轮重新完成全部验收。

| 当前事实 | 对用户的影响 | 本次设计 |
| --- | --- | --- |
| 浮窗宽 420px，AI 消息还有右边距、边框和内边距 | 长公式和表格可读区域偏窄 | 默认宽 480px；AI 正文平铺；提供展开阅读 |
| 打开后下方仍保留 64/80px 小牛和“收起对话” | 同时存在两个关闭入口，挤占高度 | 打开时小牛进入标题栏，底部入口隐藏；关闭后恢复 |
| 公式是深色长代码块，多个通道连在同一块里 | 很难先了解指标名称、输出及参数 | 成果先展示名称、类型、通道、参数，完整公式按需展开 |
| 用户、AI、状态都是类似的边框卡片 | 阅读节奏被多层边框打断 | 用户浅蓝气泡；AI 无外框；成果才有独立边框 |
| 工具阶段大多显示“正在处理…” | 无法判断检索、校验、试算的区别 | 真实阶段摘要；可展开有限操作记录 |
| 填入、保存反馈使用全局 `notice` | 看历史消息时可能分不清操作对象 | 成功/失败反馈紧随被操作的成果 |
| `meta` 有模型名，但标题只显示固定副标题 | 用户不易确认本次对话配置 | 显示配置模型；不把“已配置”解释为连通性检测通过 |
| 已有乐观消息、停止、上下文整理、断线恢复、按轮成果归属 | 核心机制已经具备 | 继续复用，不重新建设聊天引擎 |

当前代码已支持 Markdown/LaTeX、安全渲染、校验后展示草稿、多通道公式、历史成果归属。这些不列为“尚未实现”的缺陷。

## 4. 容器、入口和响应式

### 4.1 布局规格

| 环境 | 提议尺寸与行为 |
| --- | --- |
| 桌面 ≥1024px | 右下角；默认宽 480px，展开宽 720px；距右/底 20px；高度 `min(760px, 100dvh - 104px)`，为顶部导航留空间 |
| 平板 640–1023px | 宽 `min(480px, 100vw - 40px)`；同样保持右侧浮窗，不提供展开按钮 |
| 手机 <640px | 左右/底至少 12px；宽 `100vw - 24px`；高度上限 `100dvh - 88px`；保持非模态浮窗，关闭后回到工作台 |
| 短视口或软键盘打开 | 标题与输入优先可达；收起副信息；输入最多占可见高度 25%，消息区承担剩余滚动；无固定最小面板高度撑出屏幕 |

以上尺寸已用于业务页面；[设计准则 15.6](../frontend/README.md#156-ai-助手悬浮入口与对话窗) 已统一更新尺寸、小牛位置及输入区滚动例外。上下文详情随消息滚动，避免短视口展开后挤掉输入区。

继续使用 body Portal 和现有浮层常量 70。**保持非模态**：背景工作台可点击、无遮罩、不设置 `inert`。展开只改变同一实例尺寸，不重建会话、改变草稿或重置滚动。

### 4.2 小牛入口

- 关闭：沿用 welcome WebP，手机 64px、桌面 80px，附“AI 助手”文本按钮；图像加载失败仍可操作。
- 打开：同一只小牛放在标题栏左侧，32px；外部入口隐藏，空间让给对话。此位置属于品牌入口，不进入消息、风险提示或计算数值。
- 保留始终可见的“× 关闭”，Esc 收起，关闭不会停止任务；输入、历史和滚动位置保留。关闭后焦点回到重新出现的小牛按钮。
- 不做弹跳、自动摇晃、呼吸光、假在线绿点。后台状态若有真实更新，可在入口文字显示“正在处理”或“有新回复”；关闭期间没有订阅/轮询证据时不显示这些断言。

## 5. 区域设计

### 5.1 标题栏与上下文

第一行：小牛 + **AI 助手**，右侧“展开/收起宽度”和“× 关闭”。标题 18px/600，控件至少 40px 高。手机只显示关闭，避免挤占标题。

第二行显示 `配置模型：{meta.model}`，最长两行；完整值可通过可聚焦详情查看，不能只依赖 hover。仅有配置模型时，不声称这是旧消息或在途请求所用的模型。思考等级不在缺少字段时猜测；本期不新增模型切换器，继续由 LLM API 配置管理唯一使用项。

标题下用一条可折叠“本次上下文”摘要，默认显示“指标定义 · 未选产品也可讨论”或已选对象数量。展开后显示页面、产品、周期、已知的有效截止日。`view_state=unknown` 显示“时点口径未确认”；继承设置但缺少有效值时显示“随页面口径”，不得凭 `as_of=null` 写成“不受历史时点限制”。

上下文变化时，以一条中性提示标记后续消息的新条件。历史试算仍显示各自冻结条件。此区域只说明已经携带的信息，不增加产品必选门槛。

### 5.2 消息与排版

| 元素 | 样式及行为 |
| --- | --- |
| 用户消息 | 右对齐，浅 `accent-50`，文字 `accent-900`，最大宽 90%；手机可至 96%；保留原始换行 |
| AI 回复 | 左对齐、占满内容宽度，不套外层卡片；“AI”用 12px 辅助标识，正文 14px/24px |
| 段落、标题 | 段间 12px；消息标题 16px/600；消息组间 24px；不把普通回答做成大标题 |
| Markdown | 复用现有安全渲染；列表、表格、引用按现有协议；不新增原始 HTML 或远程图片自动请求 |
| 数学公式 | 原有 KaTeX；只在公式区域横向滚动；失败显示原文和局部提示，其他正文正常显示 |
| 代码/DSL | 默认可换行，12px 等宽；复制拿原始内容，排版换行不改变定义；可切换原始行查看 |
| 消息动作 | 完成后的 AI 回复提供“复制回复”；复制失败有内联提示；不新增无后端语义的点赞、分享或分支按钮 |

流式传输边界：当前已有阶段事件，不等于已经有逐 token 正文流。收到完整正文就直接渲染；不靠定时器逐字播放制造“正在生成”。

### 5.3 运行状态

用户点击发送后立即看到原文，下面出现本轮的一行状态；状态属于本轮，不能在历史卡片下面常驻。输入保持可写。

| 实际状态 | 展示文案 | 操作 |
| --- | --- | --- |
| sending / queued | 正在发送… / 等待开始… | 防重复发送；保留消息 |
| thinking | 思考中… | 停止 |
| tool + 已知名称 | 正在查找产品 / 核对数据 / 校验定义 / 试算结果 | 停止；可展开操作记录 |
| tool + 未知名称 | 正在处理… | 不从模型文字猜工具动作 |
| compacting | 正在整理上下文，稍后继续… | 停止；不是红色错误 |
| waiting_retry | 连接暂时不稳定，正在重试… | 停止；不让用户同时重复发送 |
| recovery | 暂时没有新进展，正在换一种方法 | 停止 |
| stopping | 正在停止，进度会保留 | 防重复停止；等待真实终态 |
| completed | 移除等待行；已有公开步骤可收起为“查看处理记录” | 继续输入 |
| cancelled | 已停止，进度已保留 | 继续讨论 |
| paused | 原因 + 当前保留进度 | 继续分析；修订需求后发送 |
| failed / interrupted | 本轮失败原因或服务中断说明 | 重试原消息 / 从进度继续，按现有语义显示 |
| disconnected | 连接已断开，正在恢复进度… | 重新连接；不能推断后台已停止 |

过程展开只显示公开工具名、执行状态和有依据的耗时，不显示原始输入输出、内部推理、密钥或上下文全文。无可靠总步骤数时不显示百分比。当前事件可表示操作阶段，但尚不具备所有开始/完成记录之间稳定的一一关联，不能用数组下标拼接成看似精确的执行树。

### 5.4 指标草稿成果

卡片放在所属 AI 回复末尾，外框一层，内部靠分隔线和留白分组。默认结构：

1. **具体指标名** + “定义校验通过”，下面是“时序 · 2 个输出 · 未保存草稿”。校验通过不等于已经有真实产品结果。
2. 通道列表：输出名称、结果类型；参数摘要从 `parameter_schema` 读取标签、默认值和约束。缺失说明不让前端编造经济解释。
3. “查看完整公式（2 个输出）”：原生折叠区，按通道分别显示完整 DSL。标量读 `expression`，时序读全部 `series_outputs`；名称缺失用 ID；不以空顶层公式替代多通道内容。
4. “填入编辑器”（次操作）、“确认保存指标”（主操作）。手动点击保存仍走现有 confirmation/hash/revision 流程。
5. 操作后在此卡片下显示“已填入编辑器，尚未保存”或服务确认的保存版本。下一轮对话不复制此反馈。

只有 `valid===true && !stale` 可展示可操作成果；设计中、失败、失效的中间定义继续隐藏。历史有效草稿保留“填入编辑器”，注明“历史草稿，填入后需重新校验”；直接保存继续要求当前 run、hash 和 revision 一致。

本期以精确 DSL 为公式真相。若已有与该定义绑定的服务端 `display_latex`，可作为附加阅读模式；缺少它时不让前端或模型推测数学排版，也不增加一次自动 LLM 调用。多个独立标量输出若后续在助手契约开放，应按真实结果结构逐项展示，不能假定顶层公式是全部定义。

### 5.5 试算成果与工作台联动

试算入口与草稿处在同一轮回复内的独立区段：显示产品名称/代码、周期、有效历史截止日和“查看试算结果”。已经加载完整句柄时，补充后端返回的实际参数及可计算/不可计算状态；仅有 reference 时不要伪称“全部可计算”。

点击后：按钮显示“正在读取…” → 校验对应 `preview_id` → 把同一快照产品、周期、截止日、实际参数同步到工作台 → 收起助手 → 切换“校验与预览”，滚动并将焦点定位到结果标题。

读取失败、过期、上下文冲突时保持对话打开，错误就近显示在这张试算卡，不清空用户输入，也不展示另一轮结果。重新试算必须由用户触发。工作台仍用既有图表和可访问结果表；浮窗内不重复实现第二套计算图表。

### 5.6 输入区、滚动与空态

- 输入 label 改为“发送消息”，placeholder“描述问题，或继续补充你的想法…”。两行起，自动增高至 6 行/约 144px，再允许输入框自身滚动；这属于明确的输入控件例外。
- 保持 Enter 换行；桌面 Ctrl/⌘ + Enter 发送。中文输入法 `isComposing` 期间不得发送。键盘规则可见，手机不显示无用快捷键提示。
- 空闲时“发送”；运行中无输入时只突出“停止”，有输入时同时显示“停止”和“停止并发送”。队列继续单条串行，展示待发送原文与“取消待发送”；不能启动重叠计算。
- 4000 字上限保持；接近上限（3600 起）显示计数。保存保护简写为“保存需确认”，不加长篇免责声明。
- 在消息区底部附近（沿用 48px 阈值）跟随新消息；用户上翻后不抢滚动。输入区上方用局部小按钮“↓ 查看新消息”，避免整条横幅挤压消息。
- 加载更早消息前后保留首个可见消息锚点和相对位置；不让列表头部插入将用户推向别处。
- 首次空态：“想一起研究什么？”+ 一句说明。当前指标页可提供“设计一个指标”“解释当前公式”“找产品试算”三个示例；点击只填入输入框，用户再发送。没有有效草稿时，试算示例提示先定义指标，不呈现成功样例。

## 6. 颜色、尺寸与可访问性

沿用 [项目设计准则](../frontend/README.md) 和 `tailwind.config.js`：`accent-600/700` 主操作，`slate-900/700/600` 文本，白色内容表面，`slate-50` 局部分组，`emerald/amber/rose` 只用于真实状态。

面板和成果 12px 圆角、控件 8px、徽章胶囊；面板 `shadow-xl`，成果不重复加阴影。标题区/消息区 16px 内边距，输入区 12px。正文与占位符至少 4.5:1，控件至少 40px 高，图标按钮有可访问名称，文字不使用透明度弱化。

非模态对话 `aria-modal=false`，保持工作台键盘可达。打开默认聚焦标题或关闭按钮，手机不自动唤起软键盘。关闭回到入口；查看试算结果将焦点交给工作台标题，优先于关闭回入口的通用规则。二者通过明确关闭原因区分。

消息 log 使用礼貌播报；运行状态单独 `role=status`，错误 `role=alert`，不重复播报整个历史或每秒耗时。折叠区使用原生语义。仅使用 ≤200ms 的 CSS opacity/transform，减少动态效果时关闭；不动画尺寸，不滚动自动追赶正在阅读的用户。
