# 情景识别作为枚举时序指标：统一配置与计算分析

本轮仅分析当前代码与改造方向，没有修改业务代码或运行中的方案。

## 需求的准确含义

情景识别是带有限值域约束的时序计算。数据、变量、常量、算子、依赖图、公式、参数及计算日期轴可以使用与自定义时序指标相同的模型。牛市、熊市、震荡市只是某个枚举输出的业务含义。

“内置／自定义”表示定义来源；“标量／时序”表示结果形状；“数值／布尔／枚举”表示值类型；“实时／事后”表示信息使用方式。这四个维度应分别描述，不必因此建立四套配置系统。普通标量指标和情景在结果形状上不同，但可以使用同一编辑和计算基础；自定义数值时序指标与情景的联系最直接。

上一版拆分了峰谷职责，并给情景增加三种编辑入口，但依然维护独立的资源目录、声明式公式、定义和执行编排。它解决了算子混杂问题，没有达到本次要求的配置模型一致。

## 建议采用的统一模型

### 一份计算定义，三种编辑视图

画布、构建向导、高级公式共同编辑一个规范计算图。公式是它的文本表达，向导是它的参数表单，画布是它的节点与连接表达。任何视图切换都不得重新猜测或丢弃共享节点、端口、常量、输出和版本。

以现有时序指标的表达式和作者服务作为兼容基准，增加具名中间结果／端口选择能力。旧表达式原样有效；新图可以表达峰谷节点的事件、价格及区间节点的起止边界。不要简单把多输出节点复制成几个独立计算，造成峰谷被重复计算或边界来源不一致。

保存的语义定义、编辑布局、运行数据绑定、运行结果分别管理。配置阶段定义变量含义、类型和所需输入；产品／指数的实际数据是否齐全在绑定或试算时核验，避免要求用户先选产品才能搭建逻辑。

### 输出合同扩展，而非改成另一种算法

建议输出属性分别描述：时间轴、值类型、值域、缺失规则、业务用途和展示设置。市场情景的主通道声明为枚举时序，并声明稳定的枚举 ID 与编码；编码不是有大小和距离意义的收益数值。

- 未分类使用有效性掩码或明确缺失值，不使用“震荡”兜底。
- 不允许对牛熊编码直接求均值或线性插值；比较、状态映射、持续期和转移统计由明确算子负责。
- 名称与颜色可以在输出配置中按默认值展示；它们不参与数值分类。
- 输出不局限三态：美林时钟可声明四个状态。正向／中性／负向是某些算子的要求，不应是通用枚举定义的硬编码。
- 主通道可为市场状态，其他通道为滤波线、区间收益或概率。概率仍是数值输出，并与对应枚举 ID 对齐；模型内部组件编号也需要显式映射。

最终配置页面与时序指标一致，仅在输出值类型选择“枚举”后，出现枚举项设置。情景入口可以预设这一选项并提供市场模板，不需要再维护独立的向导或公式语法。

### 算子共用与执行方式

变量、常量、指标引用和算子遵循统一登记规范。普通数学、滤波、峰谷、区间统计、分类和状态确认分别是可组合算子。目录根据输入类型、上下文和实时约束过滤，不能只因来自另一业务中心就不可使用。

参数分清固定常量和时变输入：左／右窗口通常是固定整数，上下阈值可由常量或另一条数值时序提供，由算子合同明确允许范围。连接的是标量常量时，由类型系统按既有规则广播，不必让用户额外配置一个“常量的时间轴”。

统一编排不意味着强行将所有算法塞进同一个融合内核。有状态滤波、分类状态机、事后峰谷可作为固定签名 NJIT 节点；需要拟合的模型仍保留训练范围、模型版本和隔离执行阶段。它们采用同一种配置交互，但使用适合各自合同的执行节点。

### 时间语义保持独立

枚举输出不决定实时或事后。实时均线分类与事后峰谷定界可以拥有完全相同的输出值域。

算子声明回看、前视、确认延迟、可得时间和是否修订历史；编译器沿依赖传播，实时运行拒绝任何不符合约束的上游，包括被引用的指标、模型及统计。改变展示组件不能改变这些约束。

完整区间统计可以回填到所属历史区间，但其实际可得日不得倒填为区间起点；事后结果不得输出当时可交易的假生效日。这些都是通用时序计算应能承载的元数据，不是另起一套配置体系的理由。

## 峰谷例子

统一画布中的计算链仍然是：

`价格变量 → 峰谷定位 → 相邻峰谷区间 → 区间涨跌幅 → 阈值判断 → 市场状态输出`

四个窗口是峰谷算子的常量输入；上下分类门槛是判断算子的输入。峰谷不计算波动率，波动率不偷偷改变边界，阈值分类不合并区间。需要振幅、波动率、效率或信号合并时，明确添加对应算子。

同一份定义放在指标中心，可以显示状态时序表及可选数值通道；放在情景中心，显示背景色带、市场区间和状态统计。展示组件只消费输出，不重新识别峰谷或根据固定天数推算牛熊区间。

## 不影响指标中心的实施边界

不影响现有指标，应以旧定义、公式语义、结果、窗口规则及页面操作保持兼容为验收标准。完全统一所需的枚举、多端口和时间元数据需要扩展通用能力；要求所有指标相关基础代码永久零修改，会限制真正统一的程度。

建议按以下顺序实施，每一步分别可验收：

1. 先固定统一定义与兼容协议，把旧指标和旧情景转换到明确版本的适配入口，保存的历史记录不改写。
2. 以时序指标页面为基准提取公共构建组件；两边使用同一资源库、节点编辑、向导、公式往返和输出设置，情景页提供枚举默认配置。
3. 将独立峰谷链等情景算子接入公共登记及计划编排。暂未适配的模型明确保留旧运行器及版本，不宣称已经统一。
4. 枚举输出由情景渲染器消费，保留研究实验、冻结结果及发布记录等业务能力。历史结果不重算、不自动迁移。
5. 新通路通过结果对照后成为默认入口，再停止新增情景独立编辑协议。

真正统一的验收包括：同一公式在两个入口得到相同计算图和输出；三种编辑方式无损往返；增加或修改公共算子不需要维护两套参数逻辑；调整颜色不改变数值计算指纹；枚举缺失不变成震荡；实时限制无法通过指标引用绕过；旧指标结果与旧情景结果分别通过对照回归。

本轮结论是架构可行性与改造建议，不表示以上通用能力已经完成实现。
