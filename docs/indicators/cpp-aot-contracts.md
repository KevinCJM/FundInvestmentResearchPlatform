# C++ AOT 接入契约

## 范围

本次补齐 CalMetricsEngine 与平台的接入契约：逐指标错误隔离、单产品标量批次的数据与参数绑定，以及前后端执行门禁。`CppIndicatorBatchPlan` 是显式接入 API；没有切换既有服务路由、删除 NJIT 内核或停用启动预热，因此本次不能作为“后端已消除 NJIT 启动耗时”的证据。

## 错误与数据

- 原生图默认 `error_policy="raise"`，保持直接调用的异常行为；平台适配器明确选用 `isolate`。
- 隔离结果的 `values` 与 `statuses` 同形，列顺序等于定义顺序。数值错误写入 NaN，仅沿真实依赖传播；共享错误影响依赖它的根，其他根继续运行。状态为 int16：0 成功、1 样本不足、2 已识别标量除零、3 已识别标量定义域、4 数值结果不可用（含算子内部样本不足/数值参数错误）；索引/区间投影沿用平台的 7/9/10 状态。输入形状、入口参数校验、内存预算、worker 故障等结构性错误仍使请求失败。
- `[start,end)` 以原始 NAV 时间轴计数。N 条 NAV 在区间内部生成 N−1 条 `nav[t]/nav[t-1]-1`，不读取前一区间数据，不以等价代数改写改变舍入顺序。`interval_tail` 仅是编译器内部的借用视图，不新增业务算子或画布节点。
- 图入口要求对齐、连续、float64 的 NumPy 输入和 int64 区间索引；允许只读输入。非连续输入失败关闭，由调用方在边界显式规范化一次，不在节点内复制。日期采用与 NAV 对齐的日序号。金融价格有效性、数据源、PIT 与因果性仍由平台现有上下文负责。
- 每个指标拥有独立的参数槽和无风险利率槽。开放参数值走原生标量输入，不进入图指纹；数值改变不重新生成机器码。未开放参数不得在调用时覆盖。
- 历史 typed DSL 2.0–2.4 使用平台现有版本化解析与降级规则；LaTeX 先做既有规范化。DSL/算子注册表/数据/变量/上下文版本进入原生来源契约与图指纹，不同版本的计算节点不做跨版本 CSE。原定义不原地修改；版本不匹配拒绝执行。V1 DSL、组合矩阵和时序指标服务不由此适配器切换。

## 所有权

`scheduler.execute()` 返回独立输出。`prepared.run()` / `run_audit()` 复用同一输出缓冲区，生命周期明确为 `borrowed_until_next_run`。需要缓存、快照或跨请求保留时调用 `run_snapshot()`；它直接写入独立只读输出，状态数组也独立，scheduler 关闭后仍有效。调用期间输入必须保持不变。

## 执行门禁

后端 `validate_execution_audit` 与前端 `assertNativeNumericalExecution` 接受固定签名 NJIT 或正式 `cpp_aot` 凭据。C++ 必须声明 `cpp-aot-execution-1`、真实包版本与源码/工具链构建 SHA256、原生计划指纹、算子/IR 版本、dtype、CPU 预算、所有权及 AOT 标志；Python 回退、算子回调、worker 回调、请求期机器码编译必须均为 0。后端声明冲突或字段缺失时失败关闭。凭据是内部可追溯执行信息，不是密码学远程认证。产品比较和等权接口保留既有 NJIT 严格要求：`backend`、`execution_backend` 均声明固定签名 NJIT 且 `njit_required=true`；支持 AOT 不放宽旧路径的缺字段检查。

调用方在服务资源初始化时持有唯一 scheduler；不为每个指标、请求创建 Python 池。安装缺失或原生加载失败必须阻止该路径就绪，不能退回 Python。既有 NJIT 路径继续执行原有 readiness 与预热门禁。

## 验收

原生回归使用真实构建并安装的 wheel，覆盖单线程、线程、进程共享内存、独立 DAG 分支、状态、版本和快照；平台集成测试位于 `backend/tests/test_cpp_aot_contracts.py`。前端单测覆盖双后端与非法凭据；浏览器测试 `frontend/e2e/cpp-aot-execution.spec.ts` 覆盖 320/768/1440 宽度下的接受、拒绝、展开凭据、溢出与文字对比度。浏览器响应为明确的合成契约夹具，不能替代真实后端数学测试或生产迁移验收。

完整命令与本次结果见 [验收记录](../verification/cpp-aot-contracts.md)。
