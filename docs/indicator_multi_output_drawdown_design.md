# 指标中心：命名多输出算子与最大回撤分析

## 本次范围

市场归因从指标目录及隐藏读取/计算入口移除；本地持久化配置扫描未发现其固定 ID 或专用变量引用，不能仅以潜在兼容需求为由保留实现。用户自建指标、数据快照和正常的模型版本不删除。本次不开发因子研究中心的市场模型，不顺带接入尚未完成的研究参数中心。

指标中心保留指标库、构建、校验预览；不承载因子样本外实验和归因工作流。用户仍只选择标量或时序。单结果体验不变；多结果算子只配置一次输入，自动列出可选结果，结果只负责名称、格式、评分方向和下游连接。

## 核心设计

增加内部 record 类型，包含静态命名的数值标量端口。record 不是资产向量，不能直接参与算术、归约或评分；必须选择具名端口。DSL 使用 `drawdown_analysis(adjusted_nav).max_drawdown` 表示取同一次分析的字段，不是重新计算最大回撤的公式。

一个计算图只保留同一输入、同一版本的一个 drawdown_analysis 节点，NJIT 对它仅生成一次内核调用，返回固定 tuple；各端口是零拷贝的标量取值。画布连线显式记录 node_id + port_id，公式往返保留共享节点。现有多个独立公式的指标组继续兼容。

最大回撤分析采用独立内置 ID；既有最大回撤单值 ID 被默认快照真实引用，继续由当前 typed NJIT 引擎计算，其返回类型和数值口径有测试保护。这是当前 API/数据引用契约，不是保留另一套历史执行引擎。市场归因的注册、专用变量、专用取数分支和数值实现已经清除；空文件的物理删除状态见验收记录。

## 最大回撤金融口径

输入为严格有限、正值、日期升序的净值序列。单遍扫描，常数辅助空间，四个标量结果：

1. 最大回撤幅度：max(1 - 当前净值/历史峰值)，以正百分比展示。
2. 最大回撤下跌期数：该次峰值到谷底的观察间隔数。
3. 最大回撤恢复期数：该次谷底到首次回到原峰值的观察间隔数；截至窗口末尚未恢复返回 null 并明确说明，不能当作0。
4. 最长水下期数：所有回撤段中峰值到恢复日或观察截止日的最大间隔数，包含尚未恢复段的已观察长度；不等于最大回撤那一段的持续时间。

期数按净值观察间隔计量，不冒充自然日或交易日。无回撤时四项均为0；同深度选择最早出现的谷底，下降前重复峰值选择最近一次；回到峰值即视为恢复。NaN/Inf、非正净值、空输入失败关闭；不跳过缺失点后伪造连续经历。日期暂作为来源窗口信息，不编码成可评分数字。

参考资料：VectorBT 官方 drawdowns 文档区分 recovered 与 active，分别提供 decline_duration、recovery_duration 和 duration；本实现明确包含 active，并保留自身期数约定。https://vectorbt.dev/api/generic/drawdowns/

## 用户操作

新建标量 → 从“多结果计算”选择最大回撤分析 → 选择一次净值输入 → 自动出现四项结果 → 校验预览 → 保存。已载入此类指标时先显示共享输入；结果名称/格式集中编辑，不要求逐项编写计算公式。高级用户可在画布从任一输出端口连接后续运算。

错误定位到计算步骤或结果；删除结果不删除仍被其他输出引用的计算；未应用画布不能被表单覆盖。新文案通过系统i18n，业务算子及结果名通过业务翻译，键盘可操作，窄屏不横向溢出。

## 执行审计与导出

编译计划记录 `multi_output_call_sites`，测试检查同一图仅一个原生分析节点、生成源码仅一次调用、执行时不增加 NJIT 签名。有效计算的可选统计量缺失与整个计算失败使用不同状态；非法净值不能被解释成“尚未恢复”。

同一产品、同一窗口的原生多结果共用一张 Excel 计算表，汇总按不同单元格引用同一段计算。恢复期数不可用时保留空值与原因，不填零。工作簿使用 Excel 原生公式并设置自动重算；本次测试检查公式、引用、共享结构和平台缓存值，没有在桌面 Excel 中执行独立重算。

最终命令与范围见 `docs/indicator_native_outputs_acceptance.md`。性能脚本只测数值内核，不代表含取数、校验、编译的接口耗时。
