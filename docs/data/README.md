本页是数据接入主题入口。操作顺序为：配置来源与接口 → 校验映射 → 受控采样／下载 → 标准候选 → 多源取值与质量检查。执行及恢复见[ETL](etl.md)，供应商动作与文件合同见[Tushare 下载](tushare-download.md)。

配置存在、样本通过、候选生成、质量通过与正式发布是不同状态。当前多源候选层不能冒充所有正式研究消费者都已经迁移。
## 信息架构

设置优先展示“数据同步与任务”，数据同步、来源映射和数据质量共享导航。日常 Tushare 更新不要求逐个编辑接口；来源中心默认展示连接、检查映射、同步/采样三步引导。需要修改时再打开来源或接口编辑器。移动端用紧凑接口选择器，桌面使用可筛选列表；返回协议、共享限制和高级参数按需展开。

标准表只读，系统字段不能直接映射。定义校验、样本转换、候选批次和正式发布分别说明，不合并成一个“成功”。失败候选可以定位到对应接口修复。HTTP、Tushare 和 AKShare 均可从接口详情启动受控后台下载；定时调度尚未开放。多源结果仍为未发布候选，不能误称已用于正式研究。详细用户流程见 `docs/data/README.md`。

### 外部业务数据与内部对照的边界

外部导入目录回答“系统需要或可以接收哪些业务数据”，不列出所有技术上能够写入的表。产品、机构、行情、净值、持仓，以及基金经理任职、指数成分、产品分类和基准等真实业务关系仍为外部导入对象。

`master.organization_identifier`、`master.person_identifier`、`master.instrument_identifier`、`portfolio.external_account_identifier` 仅保留为系统内部代码对照定义，`source_mappable=False`。用户在导入配置中设置来源字段和身份解析，业务记录使用解析后的内部 ID；不需要单独导入这四张对照表。数据字典只在高级内部视图展示它们，接口映射目标列表不提供它们，后端校验、预览与直接映射也拒绝将其作为导入目标。

此次只修正导入范围和展示语义，不改变表 ID、字段物理结构或已有业务映射的 `1.2.0` 合同版本。外部导入目录由 42 张调整为 38 张；总定义仍为 114 张。这些数量表示定义范围，不代表已接入数据或已完成正式发布。

## 组件

- `backend/data_sources/models.py`：严格配置模型，拒绝未知属性与无界下载。
- `store.py`：SQLite 原子配置、乐观锁、不可变修订、脱敏凭据引用。
- `presets.py`：Tushare 接口与映射默认值；缺失来源字段明确保留未映射，不编造金融值。
- `mapping.py`：响应解析、受控字段转换、标准字段校验与预览；无 eval/任意 Python。
- `runtime.py`：冻结配置、跨进程共享限流、受控 HTTP 请求；Tushare 兼容适配。
- `services/data_source_routes.py`：配置、校验、接口采样与既有下载衔接。
- 前端所有目录和字段均由后端提供，不再维护第二份标准表。

## 配置合同

来源级：名称、类型、基础 URL、启用状态、凭据是否已配置、共享配额。
接口级：唯一 ID、来源 ID、版本、方法、路径/API 名、默认参数、响应格式（records/columns/CSV）、数据路径、字段数组路径、原始字段定义、分页策略、日期参数、下载限制和多目标映射。
映射级：标准表版本、来源字段→目标字段、常量、缩放、日期/时间转换、枚举转换；身份绑定与审计生成不等同于外部字段直写。
约束级：请求/分钟、行数/分钟、单次行数、最小间隔、并发、连接/读取超时、重试次数、退避和最大页数。所有请求共享来源配额，接口配额为附加约束，不能各线程重复发放。

## 安全和一致性

不接受任意 Python、SQL、文件路径或任意 SDK 方法。HTTP 禁止私网/回环/链路本地目标，禁用重定向，限制响应大小；凭据独立私有存储，API 永不回显。修改使用 expected_revision，冲突返回 409；运行使用冻结配置，不在一次任务中热切换映射。单位变化、未知枚举、无效日期和非有限数值必须报错。PIT 日期缺失不能替代为观测日期。
## 使用说明

1. 设置 → 数据源与接口映射，选择 Tushare、AKShare 或新建来源。已有配置均为普通可编辑记录；不会被后续初始化覆盖。
2. 选择接口，编辑默认参数、响应格式、来源字段、标准映射和下载限制，保存生成新修订；收到 409 时保留草稿并重新加载，不覆盖他人的修订。
3. 粘贴样本可离线验证；真实采样要求先保存、明确确认，最多一次请求，不写正式数据。
4. 所有来源均可在接口详情“下载与更新此接口”中指定范围，增量模式沿用同配置同产品断点。Tushare 原全市场流程保留旧入口；协议和分页可编辑，下载器按保存值执行，不兼容设置明确报错，不静默还原。
5. 下载后查看标准候选及多源结果；需要人员或基金产品人工身份对照的映射会明确提示。系统 ID、批次、哈希无需手填，系统维护字段有独立底色和文字标签。
6. 打开“多源取值规则”，调整来源顺序、表级覆盖、缺失/异常替代、冲突处理、必需字段和容差。保存后可对已下载候选执行取值，不会再次请求数据源。详情可查看替代原因、冲突字段、选中来源和批次。
## 普通配置与运行边界

来源地址、接口名称、方法、返回结构、分页、参数和映射均可修改。已有下载脚本仍提供 Tushare 的全市场日期/代码分片；独立接口下载走统一配置执行器。来源地址变更不能把已有凭据静默发往新主机：凭据绑定保存时的来源地址及认证协议，变更后需重新保存凭据。所有来源统一执行此约束。权限确认不是供应商权限证明，不伪造“已核实”。

## 多源取值

### 规则优先级

全局默认来源顺序（初始 Tushare → AKShare）可调整；每个标准业务表可覆盖来源顺序、必需数值字段、差异容差、允许值域、跳变阈值、缺失替代、异常替代和冲突处理方式。未纳入规则的来源不自动参与。配置修改使用 revision 乐观锁，运行冻结规则快照。

### 先可比，再比较

先按内部标的、业务日期和业务维度对齐。行情额外隔离 quote_type、currency、adjustment_basis；净值额外隔离 currency、adjustment_method、is_retrospective_adjustment 中与选择相关的复权语义。对单位净值比较不将供应商的复权算法标签作为单位净值的区别；涉及 adjusted_nav 时必须一致。不同日期、币种、价格/净值类型、前后复权不能相互替代。

同源修订先按可得时间、采集时间及修订序号锁定最新记录，再检查质量；最新记录异常时不静默回退该来源旧版本。同源同时间冲突不能随机选择。历史 as_of 过滤在修订选择之前执行；即使来源回填历史公告时间，as_of 后才采集的记录也不得混入。未知可得日期最多以采集时间作为保守界限；包含事后复权值的整条记录在严格历史模式下拒绝使用。

### 选择与质量

首版按整条记录选源，避免开高低收分别取自不同来源。数值质量计算下沉固定签名 NJIT：非有限值、非正价格/净值、负成交量/金额、OHLC 关系和用户阈值。跳变只是可疑证据，不宣称必然错误；除权、分红、拆分等会产生真实跳变。

- 主来源正常且一致：选主来源。
- 主来源缺记录/必需值：仅在“缺失时使用下一来源”打开时补充。
- 主来源未通过质量规则：仅在“异常时使用下一来源”打开且备用数据通过同一质量检查时替代。
- 双方均合法但超容差：默认隔离待处理；也可选择“按优先级取值并告警”。不得擅自平均，更不能把少数不同值自动判断为错误。
- 全部不可用：保留缺失并报错，不补零、不沿用其他日期。

float64 冲突判断为 |a-b| > max(absolute_tolerance, relative_tolerance × max(|a|,|b|))，支持字段级覆盖。金额/数量 Decimal、整数和文本按精确值比较，避免将大额金额转为浮点后误认相等；当前值域/容差自定义只对 float64 开放。来源来自同一上游站点不等于独立交叉验证，不能把一致视为真实性证明。

备用来源可能缺少附加字段。例如 AKShare 单位净值不能补出 Tushare 复权净值；要求复权净值的任务应把 adjusted_nav 设为必需字段，禁止不完整替代。

## 结果与可追溯

保留原始/标准化候选，不覆盖任何供应商记录。合并结果保存为独立不可变 Parquet 制品和决策明细：业务键、候选来源、选中来源、来源批次、拒绝/替代原因、冲突字段、规则 revision/hash、as_of 和构建时间。内容相同的重跑复用同一版本；规则变更创建新版本。先在临时目录完成 Parquet、完整决策和 manifest，再原子改名并登记结果；这里是候选制品的原子提交，不是正式市场版本激活。失败不暴露半成品。

输入与输出均核对 SHA256、路径边界和 Arrow 字段合同。取值运行 ID 包含引擎版本、规则修订、源输入哈希、日期与 as_of；引擎规则变更必须升级版本。重复运行复用不可变结果，数据库落库前中断可通过原子目录的 manifest 恢复，禁止覆盖已有制品。

历史缺少 checksum 的旧格式候选只作为拒绝标记，不采用其中的值；同业务键的新验证批次优先替代旧标记，旧文件不删除。仅当显式开启异常替代时，合格备用来源才能代替未验证来源。新批次使用独立 batch-v2 标识，重下载不会错误复用无校验和旧批次。已存在但不匹配的 checksum 视为制品被改写，直接阻断。

本阶段的正式研究仍使用既有活跃快照；“多源取值完成”表示统一候选生成，不表示历史业务读路径已迁移。页面必须区分“下载完成”“取值规则通过”“存在冲突”和“未发布”。不添加虚假的上线/发布按钮。后续 Repository 迁移再消费此合并层。

## 下载执行与容量边界

统一执行器按单接口与已选参数范围下载，不伪装成全市场调度。配置、产品范围与身份映射变更会隔离增量检查点；成功完整抓取后才推进断点，并重叠回查 3 天。空响应为 EMPTY，分页耗尽/触达截断阈值不写不完整候选，超过时限失败。下载结束自动应用全局或表级规则，亦可从取值页仅重算候选而不请求供应商。

单次下载/取值上限为 100000 条，候选扫描最多 1000 个批次；超限会明确要求缩小区间或归档分区，不截取部分输入冒充完整结果。不能从映射失败批次还原业务键时，保守标记该表来源异常；普通质量异常按业务键判断。没有跨日价格填补、源数据覆盖、擅自平均或自动下单。

## 数据源适配边界

HTTP、Tushare 和 AKShare 共用配置、映射、受控下载与候选协议。SDK 使用受控函数白名单和独立进程时限；平台默认限制不是供应商官方配额。代码格式映射必须明确，不按名称猜测同一产品；单位净值、累计净值和复权净值不得互换。

真实采样必须先保存配置并明确触发，最多一次请求且不写正式数据。更改来源地址后凭据必须重新绑定，不静默发送到新主机。Token 不回显，不进入文档、日志或运行制品。

新增或修改 Tushare 接口须按 AGENTS 的 tushare-fetcher 协议核定目录、账户、权限、限频及 smoke；这里不把历史账户积分或旧接口限制当作当前授权。

## 界面与错误

入口先显示连接、映射检查、同步／采样；只有需要修改时展开高级响应结构及参数。标准表只读，缺字段、未知枚举、单位不一致和身份待绑定直接说明原因。409 保留草稿并重新加载，不能覆盖他人修订。

下载完成后可只重算取值，不再次访问供应商。整条记录按可比口径选择来源，不按字段拼出一条虚构行情；所有来源不可用则保留缺失。
