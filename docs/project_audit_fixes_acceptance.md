## 3. 页面与测试契约修复

### 实际交互问题

1. 指标中心注册表迟到响应不再覆盖已经输入的名称、公式或参数，只初始化未修改的技术默认值；加载完成前桌面和移动入口均不允许校验、预览或保存。专门的延迟响应测试覆盖输入保留和按钮状态。
2. 平板宽度下，侧栏压缩编辑区，原来的三列布局会把滚动来源下拉框挤窄并产生遮挡。现在只有足够宽的屏幕才并排展示，其他宽度纵向排列；浏览器实测下拉宽度并真实点击选项，不用 force click 绕过。
3. 全屏图表的 ResizeObserver 同时调整真实 ECharts 画布与图内布局，避免只有布局变化、画布大小不变。检查实例生命周期，保持缩放、结果与数据请求不变。

### 工程检查

- 修复 ETL 测试类型错误、缺失类型/测试导入和重定义遮蔽；未降低 TypeScript/Ruff 检查标准。
- Excel 用例改为验证当前通用区间图的原生公式、标准差口径及条件聚合，而不是要求旧专用公式字符串。
- 浏览器按当前画布节点、页面区块和按钮归属定位，覆盖真实公式编辑/校验/保存/预览/导出，不仅检查静态标题。
- 数据源用例按“验证与使用 → 高级单接口下载”逐层展开；模拟用例核对实际请求中的21期与200条路径，不点击隐藏控件。
- 因子研究测试等待加载期间禁用的页签变为可操作，再复制模板；不以定时睡眠掩盖异步状态。
- 索引覆盖率测试固定研究日期，生产时效标准不变。ETL恢复测试跟随实际模块移动，不为旧测试恢复已删除导出。

## 4. 历史契约与性能边界

不修改已保存指标定义、revision、研究快照和发布引用。滚动实现标识为 `interval-rolling-1.5`，参与编译计划身份；作用域校验版本为 `typed-njit-causal-scope-3`。错误修复后的新计算不会通过改写历史文件冒充原结果。

数值路径仍使用稳定 dtype 数组和预热 NJIT。系统日期的 epoch-day 类型转换在边界执行；原始价格/收益数组进入每个窗口时使用视图，不构造 T×W 矩阵。允许结果和必要工作缓冲区分配，不宣称整个应用没有任何分配。

测试验证实际正式执行不触发编译函数、签名不增长、`python_fallback=0`；窗口地址测试确认对同一原始数组按步长取视图，异常路径分配测试检查 NRT 引用释放。
