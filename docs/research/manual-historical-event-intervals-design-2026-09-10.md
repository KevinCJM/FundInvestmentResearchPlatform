# 人工历史事件区间（事后识别）设计

## 目标

在历史情景识别中增加“人工历史事件区间”能力。用户选择一条用于观察的时间序列后，可手工定义任意历史事件的开始日、结束日、名称、颜色和说明；不同事件允许重叠。该能力仅用于事后研究，不产生实时交易信号。

## 产品语义

- “市场状态”是互斥枚举：一个观测时点只有一个最终状态。
- “历史事件”是多标签区间：同一个观测时点可以同时属于多个事件。
- 因此事件不能伪装成普通 state，也不能通过“事件 A > 事件 B”的优先级强行去重。
- 工作台继续复用现有定义、版本、运行和快照体系，但结果页对人工事件采用专门的事件轨道和事件表格。

## 人类操作流程

1. 在情景算法库选择“人工历史事件区间”。该模板只支持“事后识别”。
2. 选择或替换观察序列，例如沪深300、标普500或其他研究序列。
3. 在“人工历史事件区间”节点中点击“添加事件”。
4. 每个事件填写：名称、开始日期、结束日期、颜色、说明。
5. 事件允许重叠，不做冲突去重；只要求单个事件开始日不得晚于结束日。
6. 运行识别后，结果页展示观察曲线、事件轨道、事件列表、覆盖观测数、重叠观测数和最大同时事件数。

## 架构

### 图谱节点

新增 `annotation.manual_events`：

- 输入：`value: series<float64>`，仅提供真实时间轴及观察曲线。
- 参数：`events[]`，每项包含稳定 id、label、start_date、end_date、color、description。
- 输出：
  - `state`：内部兼容输出。0 表示至少一个事件覆盖，1 表示无事件覆盖。
  - `event_count`：每个观测时点同时覆盖的事件数量。
- 节点为非因果、仅事后研究；固定人工区间不会因未来数据自动改写，但其标签不是历史时点当时可知的信号。

### 多标签结果

事件名称、区间及覆盖统计作为冻结运行结果中的 `manual_events` / `manual_event_summary` 保存；不把事件名称压缩成互斥 state。

现有二态 `state` 仅用于兼容统一执行、快照和基础统计链路，前端人工事件结果不把“事件期 / 非事件期”作为用户的主要研究结果。

### 性能

事件投影使用固定签名 NJIT：

- 对已排序观测日期使用二分定位每个事件区间。
- 通过差分数组计算每个观测日的同时事件数。
- 复杂度约 `O(E log T + T)`，其中 E 为事件数、T 为观测数。
- 不构造 `T × E` 的完整多标签矩阵，避免事件数量增加时的内存膨胀。

### 时间语义

- 事件边界为日历日期闭区间 `[start_date, end_date]`。
- 事件不要求边界恰好是交易日；覆盖统计按实际观察序列中落入区间的观测点计算。
- 超出当前数据范围的事件仍保留定义，但覆盖观测数为 0。
- 事件允许重叠，重叠观测单独统计。
- 节点仅支持 retrospective；不能通过下游普通算子绕过实时门禁。

## 校验

- `events` 最多 100 个。
- id 必须唯一且稳定；名称不能为空。
- 日期必须是 ISO `YYYY-MM-DD`；开始日期不得晚于结束日期。
- 颜色使用 `#RRGGBB`。
- 说明最长 500 字。
- 重叠不是错误，也不产生 warning。

## 前端

### 定义页

人工事件节点使用专门编辑器，不要求用户编辑 JSON：

- 卡片式事件行，适配 320 / 768 / 1440 宽度。
- 添加、删除、修改名称/日期/颜色/说明。
- 明确提示“事件允许重叠；事件不是互斥市场状态”。
- 单个非法日期在本地直接提示，同时由后端进行最终校验。

### 结果页

人工事件运行显示：

- 观察曲线。
- 每个事件一条独立横向轨道；重叠事件天然显示在不同轨道，不混色、不覆盖。
- 事件表格：事件、开始、结束、覆盖观测数、说明。
- 摘要：事件数、任一事件覆盖观测数、重叠观测数、最大同时事件数。

## 兼容与治理

- 不修改已有模板或历史运行快照。
- 不把人工事件发布为可实时 TAA 信号；现有因果/发布门禁继续生效。
- 不新增另一套图谱或存储系统；复用现有 definition / run / artifact / preview 体系。
- 事件节点是领域原子能力，不拆成“开始比较 + 结束比较 + 多次 OR”的大量画布节点，因为事件列表本身是一个人工标注集合，继续拆分会显著恶化人类操作且不增加独立可复用计算语义。

## 验收

- 两个、多个事件可完全或部分重叠。
- 非交易日边界按真实观测点正确覆盖。
- 数据范围外事件保留但覆盖为 0。
- 周频/月频观察序列按对应观测轴计算覆盖数。
- 实时模式禁止运行人工事件节点。
- 事件编辑、保存修订、重新载入、试算、正式运行快照保持定义不变。
- 后端数值路径使用预热 NJIT，无请求时编译、无 Python 数值回退。
- 前端 320 / 768 / 1440 无横向溢出，并有文本/表格可读结果。

## 实现与验收记录

- 已新增 `annotation.manual_events` 与 `manual-historical-events-v1`，继续复用现有定义、版本、试算和正式运行快照链路。
- 人工事件使用固定签名 NJIT 差分投影与二分定位；不构造 `T × E` 多标签矩阵。
- 事件名称和重叠关系以冻结 `manual_events` 保存；内部二态只用于统一执行兼容，不作为用户主要结果展示，也不能通过正式回测/TAA 因果门禁。
