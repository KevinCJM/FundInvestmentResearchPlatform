## 1. 用户实际操作

入口 `/settings/risk-scales`，保留现有Settings侧栏、页面宽度与设计令牌。第一屏是当前默认和可用版本，不把用户直接丢进矩阵表单。

新建使用五步：**基本信息 → 参考资产 → 假设与约束 → 前沿与五档 → 核对发布**。选择已有来源可跳过重复录入；高级参数折叠。每步只设置一个主操作，未满足条件直接写明缺项。保存草稿、计算预览、发布、设为默认是四个不同动作。

参考输入支持引用已保存CMA，或在不依赖Mandate的情况下建立参考资产与假设。指数/产品使用真实来源类型，沿用现有读取与数据目录，不新增采集器、不下载数据，不把价格指数当总收益、不将缺失收益填零、不隐式归一化剩余成分。已有来源接口不支持的币种、FX、频率和方法明确显示不可用，不伪造。

系统模板只提供大类、口径、参数建议，不预填虚构市场收益、不冒充已发布默认。多套自定义版本可以并存；默认按币种及风险口径区分，只能指向已确认版本。

前沿区显示图、五档表、参考组合与失败原因；图表是辅助阅读，关键结果始终能从表格读到。C3是最高授权等级，不要求组合至少承担C3下界风险。ES/回撤仅为参考画像，缺少可靠数据时为 unavailable，不能从mu/Sigma编造。

## 2. 后端边界

沿用FastAPI模块化单体和 `backend/strategic_allocation` 领域，复用 `ArtifactRepository`、`AtomicJsonStore`、`cma_application.frozen_numeric_inputs`、已存在的数据解析及统计内核。新功能必须通过依赖注入在离线测试中运行，不能初始化或污染正式磁盘。

| 层 | 职责 | 不做什么 |
|---|---|---|
| reference输入 | 必需的共用来源/资产/假设接入与冻结 | 不重建独立CMA研究中心、不修改投前流程 |
| 矩参数前沿 | 直接读取冻结mu/Sigma，复用共享QP/LP内核 | 不构造伪历史数据、不调用历史HTTP接口 |
| 风险分档 | 形状DP、风险等距、弧长等分、人工阈值 | 不生成另一条前沿、不改变市场假设 |
| 服务编排 | 校验、读来源、计算准入、确定性哈希、结果封装 | 不承载数值循环、pandas计算 |
| 存储薄层 | 草稿修订、版本、幂等确认、默认CAS、退休 | 不重写历史、不复制第二套成果数据库 |
| 路由 | 类型化契约、错误映射、能力查询 | 不静默降级、不藏数值错误 |

共享层只修改本模块必须用到的接口；原签名保留时委托唯一当前内核，并进行既有调用回归。不得增加未使用的通用插件、任务平台或新依赖。

## 3. 有效前沿与分档的具体实现约束

### 3.1 复用现有SAA求解路线

固定采用目标收益扫描，不新增风险网格求解器：

1. 求GMV；对PSD且多最优的GMV进行最高收益并列处理。
2. 求最高可行预期收益，再取该收益面上最低方差作为右端。右端不是全空间最大方差。
3. 在两个端点收益之间生成101个目标点；每个目标求 `min w'Sigma w, mu'w >= target`。200点用于稳定性复核，保持现有上限，不擅自开放500/1000。
4. 直接消费矩，不在每个点重新计算统计或扫描历史收益。热启动须先保证新目标下可行；失败目标保留状态与缺口。
5. 共享QP需要的一般等式/可行初点支持只在单一内核及薄适配中补齐；结构矛盾、初点不可行、迭代耗尽、数值失败分开。没有证书不宣称严格不可行。

“按风险上限最大化收益”与“按收益下限最小化风险”是两种参数化，不是严格意义的拉格朗日对偶问题；本轮采用后者以复用存量实现。

### 3.2 四种可选分档

默认 `frontier_shape_dp_v2`：对标准化风险收益曲线的局部方向角作弧长加权连续DP。它反映方向变化，并非直接计算二阶微分曲率，也不声称发现客观投资偏好。

可选 `equal_volatility_v1`、`equal_arclength_v1`、`manual_volatility_bands_v1`。共同冻结算法ID、版本、参数和数值策略；切换仅重分档，不重拟合CMA/重求前沿。

自动切点满足最小边数、跨度、顺序约束，保持五个严格递增上限。最近节点需要全局约束选择时不宣称总是O(J)：采用有界DP并记录真实复杂度；不独立四舍五入产生重复点。形状法近直线退化到弧长须记录原因，与用户主动选弧长法区分。

人工模式保存五个上限及依据；超前沿范围无虚构代表组合。统一分类容差，等于边界属于较低档；超过C5返回above_scale；无值返回unavailable。

## 4. 前端修改方案

新增路由、Settings节点、独立工作台/版本详情/对比，以及职责单一的来源编辑、算法选择、结果表、发布操作组件。不修改现有目标、SAA、TAA页面。

复用 `components/ui.tsx`、现有研究数值输入、ECharts及国际化体系。新增 `riskScales.*` 中英文词条。禁止卡片套卡片、满屏JSON、没有label的输入、只有颜色的等级、不可读小字和多列嵌套滚动。

修改输入立即使旧确认失效；AbortController与generation双重防止迟到响应污染当前草稿。上游变更失效前沿，算法/阈值变更只失效分档，文字变更只需重新确认。已发布读取冻结结果，不自动重算。多套版本/算法对比不暗示哪个评级更优。

窄屏保留单列与可见主操作，矩阵/技术详情折叠；风险表格有可访问说明。验收至少覆盖320/768/1440px、加载/空/错误/禁用/已发布/冲突、中英文、键盘和真实图表。

## 5. 可靠性、内存与性能

所有新增数值走固定签名NJIT；预热绑定当前PID，正式请求禁编译、禁Python/object-mode回退，失败关闭。float64/int64只读输入；必要转换在边界一次完成，窗口用视图或索引，不重复复制原始面板。输出与求解工作区可以分配，但生命周期受控。

前沿缓存按完整来源哈希、约束、算法和口径键控，设总字节/条数/TTL边界；缓存仅优化，不作为不可变来源或发布资格。预览不写成果、不创建正式目录/锁。确认重新核验冻结引用，不信任客户端结果；幂等键不能让不同请求共享结果。

复用受控存储，默认切换带expected_revision。成果完整但索引登记未完成时要可恢复，不因重试产生第二个发布版本。所有写操作先检查磁盘和模式，不将离线存储替换为项目data。

本轮不建设身份平台：如现有运行没有真正的用户鉴权，明确受信任单工作区模式，不能伪称多租户隔离。默认/退休均为服务端独立确认动作。

不得为通过检查提高全站设计预算、删除测试、引入静默降级或清理其他需求改动。文档、测试、运行证据与代码保持一致；未执行项目明确记录。仅本地修改，不提交、不推送、不部署、不自动发布真实业务标尺。

## 发布审核补充：当前引用资格与列表治理

- SAA/TAA 历史记录继续读取冻结数值。当前产品应用额外按调用方明确传入的战略研究根目录读取标尺治理状态（生产装配读取 `STRATEGIC_ALLOCATION_DATA_DIR`，不把产品域目录当作成果目录）、校验引用指纹及冻结来源；停用、失效、无法读取或缺少上下文均不能获得当前应用资格。TAA 预览显示阻断原因，导出和直接产品写入在共享应用门禁重新检查，不能只信任保存时的可用标志。
- 列表删除当前默认版本必须勾选明确清空默认的确认；提交前重新读取默认状态。版本在对话框打开后变成默认时，要求补充确认，不能自动发送 `clear_default=true`。
- 发布版本行可选择恰好两个不同 ID 进入现有比较页，草稿不参与比较。选中状态可以跨已加载页面保留，删除版本会移除相应选择。
- 列表按 API 的 `next_offset` 逐页加载，保留先前行并按 ID 去重；不会把第一个 100 条当作全量。删除已加载版本后修正下一页偏移，避免跳过紧随其后的记录。

- 101/200 点自动分档复核不稳定时，研究版本仍可在确认警告后发布，但默认资格阻断；基于该不稳定算法的人工微调同样阻断。设置默认及读取已有默认时重新检查冻结的稳定性证据，不能沿用旧版本误记的 eligible=true。独立人工阈值模式保留原契约，本次未加入自动绕过。
- 版本查询单独返回 `current_default_eligibility`，详情页用当前默认资格禁用激活并显示原因；冻结 `preview.default_eligibility` 只作为发布时证据，不再作为旧版本当前可激活的唯一依据。
