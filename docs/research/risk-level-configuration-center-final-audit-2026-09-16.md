## 1. 业务范围结论

本次只实现风险等级配置中心及其必要共享基础能力：参考资产／Proxy、Reference CMA、矩参数有效前沿、C1–C5 分档、草稿、预览、不可变发布、默认切换、版本比较、退休和只读历史。

未改造投资目标、SAA、TAA、产品实施、分类、情景识别或交易业务。工作区仍存在其他需求的未提交文件，本次未清理、覆盖或把它们归入本功能。

## 2. 功能验收

用户可以完成以下完整流程：

```text
风险等级配置中心
  → 新建标尺
  → 配置参考资产与真实 Proxy
  → 冻结参考输入
  → 建立或选择 Reference CMA
  → 设置参考约束
  → 计算 101 点有效前沿 + 200 点稳定性复核
  → 选择 C1–C5 分档方法
  → 核对风险画像
  → 发布不可变版本
  → 独立设为当前口径默认
  → 读取历史版本 / 比较 / 退休
```

支持四种分档：

- `frontier_shape_dp_v2`：默认，按标准化风险收益曲线的局部方向变化与弧长权重做连续分段。
- `equal_volatility_v1`：风险轴等距。
- `equal_arclength_v1`：前沿标准化弧长等分。
- `manual_volatility_bands_v1`：人工五档上限并强制记录依据。

C1–C5 的语义保持为风险授权上限；选择 C3 不要求组合至少承担 C3 下界风险。

## 3. 数值与后端审核

### 3.1 有效前沿

复用现有 SAA 的目标收益扫描思想，不新增第二套风险网格求解器：

1. GMV 左端点。
2. 最高收益面上的最低方差右端点。
3. 在两端预期收益之间建立目标收益网格。
4. 每个目标求 `min w'Σw, μ'w >= target`。

风险中心直接消费冻结 CMA 的 `μ / Σ`，不伪造历史收益，不重新拟合已冻结 CMA。

### 3.2 AGENTS.md 计算约束

自审核确认：

- 新增核心数值均为固定签名 `@njit` 内核。
- 预热后关闭新签名编译；执行审计记录 `python_fallback=0`、`request_time_compilation=0`。
- 数值内核文件未使用 Pandas/DataFrame/Series 计算。
- 前端未复制协方差、前沿优化、分档或分类数学实现。
- 冻结矩与大数组按只读契约消费；输出和任务工作缓冲区独占。
- 分档切换复用相同前沿，不重算 Proxy 或 CMA。
- 数值失败保留状态，不插值缺口、不静默放宽约束、不自动换算法。

## 4. 前端验收

前端保持五步操作：

**基本信息 → 参考资产 → 假设与约束 → 前沿与五档 → 核对发布**

主要 UX 结论：

- 列表首页先告诉用户“当前默认是什么 / 没有默认怎么办”。
- 每一步只有一个主要下一步动作，禁用时给出原因。
- 高级矩阵、求解诊断和风险画像默认折叠。
- 图表与 C1–C5 表格联动，同时提供表格读取，不依赖颜色或 tooltip。
- 320px 下宽表使用局部横向滚动提示，不造成页面级横向溢出。
- 草稿恢复时重新读取并核验冻结 CMA，不信任浏览器保存的 CMA 副本。
- 币种、收益口径、研究日、期限等上游输入变化会清除不兼容的旧 CMA 和发布确认。
- 迟到请求由 AbortController + generation 双重拦截。
- 发布版本只读，不在页面打开时重新计算。

## 6. 代码自审核

### 6.1 通过项

- 后端按 contracts / reference inputs / service / kernels / store / routes 分层，未把整个功能堆到单个路由文件。
- 共享 QP、ArtifactRepository、CMA frozen inputs、ResearchSeries 数据能力均复用，没有另造私有求解器或成果数据库。
- 历史兼容 QP 入口保留为薄适配，调用唯一共享核心。
- 前端页面、编辑器、结果、来源选择、服务类型分离；没有把后端数学复制进 TypeScript。
- 没有 `old/legacy/backup` 的平行实现或静默 Python fallback。
- 没有虚构默认收益、默认产品或自动发布的系统标尺。
- 发布、设默认、退休三个动作彼此独立，历史成果不可变。
- 合约和版本哈希用于检测 stale preview；幂等发布和默认 CAS 均有回归覆盖。

### 6.2 非阻塞事项

1. **Numba 非连续数组性能提示**：已记录，当前零拷贝与实测性能优先，不作为本功能阻塞项。
2. **全站 Vite chunk 较大**：属于已有前端架构问题，不在风险中心范围内。
3. **AI Hermes 路由登记**：新文件目前尚未进入 Git 提交范围。路由工具要求稳定引用必须已被 Git 跟踪，因此本轮没有通过 stage/commit 绕过该规则。提交前应在风险中心文件进入正式提交范围后，再把入口、测试和最小回归命令登记到 `docs/repo_map.json` 并重跑 routing validator。当前仓库本身还存在其他未提交需求引用导致的 routing validator 错误，与风险中心运行正确性无关。
