# 数据同步用户流程

## 当前流程（2026-09-06）

默认入口“数据下载与更新”已统一为多来源，不再默认打开旧 Tushare 面板。

1. **按数据源下载**：选择来源 → 按业务分类勾选接口数据 → 查看默认参数并填写产品/日期 → 选全量或增量 → 确认顺序清单 → 执行。配置来源页会携带 source 参数跳转至同一入口。
2. **ETL 任务编排**：快速下载可转为流程，或新建流程。下载、字段映射、多源取值、指标快照是独立步骤；可跨来源、增删、上下移动并选择前置输入。流程可保存修订、另存和复用；运行前校验依赖和数据口径。
3. **运行记录与恢复**：展示每步状态、行数、耗时和错误；失败停止后续步骤。继续操作保留成功步骤，恢复前核验接口修订、执行代码及制品哈希。配置已变更时建立新运行，不改写旧运行契约。

全量表示重新获取指定接口/产品/区间，不删除仓库、不自动生成全市场循环。增量仅在映射成功后推进断点，回查 3 天。允许空结果须显式选择。快照要求本次明确输入的产品信息和基金净值，不把单位净值或行情当作复权净值，不悄悄读旧活跃数据。

“原 Tushare 全市场任务与旧快照维护”是按需展开的兼容入口，仍执行旧输出及发布规则。标准 ETL 制品继续是未发布候选；正式研究迁移和定时调度不在此次范围。完整设计见 `docs/etl_workflow_design.md`。

## 历史版本：2026-09-05 页面优化记录

以下为引入统一 ETL 之前的阶段记录，不代表当前来源下载能力。

### 当时的问题与边界

旧页面把配置、下载和结果拆散；日常更新默认勾选几乎所有模块，已配置凭据仍占整块表单，失败恢复在页面底部。用户也容易把“映射定义通过”“采样成功”“下载完成”“标准数据正式可用”理解为同一状态。

本次只优化用户操作与状态反馈，不改动供应商接口、下载范围的后端能力、数据单位或正式发布机制。自定义 HTTPS 来源仍仅支持配置、验证与采样；不伪装为已支持批量同步。定时任务不在本次范围。

## 两条用户路径

- 日常 Tushare：同步数据 → 确认凭据 → 选择常用方案/自定义范围 → 检查本次清单 → 启动更新 → 查看任务结果/数据质量。
- 新来源：数据源与映射 → 新建来源及凭据 → 新建接口 → 配置返回字段 → 映射标准表 → 离线校验/单次采样。配置与采样成功不代表已开放批量同步。

## 页面规则

1. 数据同步、来源配置和数据质量共享导航，保留原有 URL。
2. 日常默认只选择基础、ETF、场外基金；指数与宏观使用明确的研究方案或手动选择。
3. 已配置凭据折叠显示，未配置时自动打开；共享限流等技术设置按需展开。
4. 启动前展示实际模块、具体内容、更新方式和自动依赖，未选择的数据不得提交。
5. 正在启动、正在运行、正在重建、状态失联时禁用冲突操作；提供重新检查状态的入口。
6. 任务失败优先展示可执行恢复：已拉取但后处理失败则仅重建；未拉取完成则恢复原任务。不得把二者同时推荐为同等下一步。
7. 新标准表候选批次与现有研究数据明确分开，不能因为字段验证通过就标记“可用于正式研究”。
8. 配置页提供来源摘要、待完善筛选和结果修复入口，复杂接口字段折叠；未保存草稿切换前确认。
9. 错误使用中文和具体下一步，不显示 [object Object]；刷新状态失败不能继续使用过期“可启动”状态。
10. 桌面、平板、手机均可完成核心操作，技术表格仅在内部横向滚动。

## 验收

覆盖默认方案、范围依赖、空选择、只读/运行锁、状态失联、全量二次确认、恢复优先级、映射与下载状态分离、配置页筛选和草稿保护。使用离线测试和浏览器响应式检查，不触发真实下载，不重启用户正在使用的服务。
