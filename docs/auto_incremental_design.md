# 自动增量下载设计与实现

## 2026-09-11 持仓数值冲突隔离

- 目标：完整采集与质量放行分离。供应商稳定返回不同数值不等于网络故障，不盲目重试同一完整日期；也不按最后值/最大值/求和捏造答案。
- 批次边界：同一完整采集响应集合内同键多值才作为待核验冲突；前后两批各自唯一且有效的新值不同属于供应商修订，继续由唯一的 `append_incremental_rows` 按业务键 Update 私有候选，保留新采集时间，不能误报冲突或覆盖旧快照。分页复读中的内容漂移不能直接局部 Update，需重新取得完整一致的一批，避免混合页造成漏行。
- 分页发生键重叠或同页冲突时，必须先取得原始末页，再按相同 offset 完整复读并校验内容/顺序哈希。只有稳定且完整的响应才进入隔离处理；分页缺失、重放、漂移、超时及预算问题仍停止。
- 冲突的全部原始变体独立保存，候选表保留唯一业务键占位，四个数值字段为缺失，`availability_status=source_conflict`。不影响其他记录，不将旧基线的值冒充本轮确定值。
- 冲突检查点附带哈希、行数、身份及记录时间；恢复必须同时验证原始变体和空值占位。最终 Parquet 与冲突证据通过质量清单绑定，已下载不代表已经解决数值冲突。
- 前端摘要和步骤显示“采集完成 · 数据待核验”，披露冲突数量、原始证据和不可发布状态。含冲突结果禁止作为自动增量基线、下游计算输入或活跃研究快照；独立节点继续执行。
- 验收：同页/跨页和微小浮点差异不被舍入掩盖；顺序/数值漂移仍失败；重复运行幂等、损坏证据失败、跨版本迁移保留证据；占位值必须缺失且不得伪装 `announced_date`。本次为 I/O 校验与隔离，不新增金融数学内核，不涉及 NJIT 回退。

## 需求与边界

“自动”指用户触发后自动推断取数范围，不是定时任务。保留手动增量和全量模式；新增 `options.mode=auto_incremental`。用户只选数据集，先看只读计划，再确认下载，不填写日期。

原数据集 ETL 只识别同流程且整次成功的私有基线。没有该基线时，即使选择增量也可能初始化全部历史。自动模式默认使用当前活跃快照；用户可显式选择完成下载补足缺失表，没有基线绝不降级全量，不修改既有运行及其冻结参数。

## 用户流程

1. 设置 → 数据下载 → **自动增量（无需日期）**。
2. 选择数据集，服务端目录的 `requires/provides` 自动展开目录、日历等前置步骤。
3. **分析快照并预览区间**：只读 Parquet 元数据和交易日历，不访问供应商、不创建下载任务。
4. 展示快照名称、各数据集已有最新日、回查开始日、请求截止、更新策略及阻断原因。
5. **确认计划并开始自动增量**：携带计划 ID；锁内复查快照和来源配置，变化则要求重新预览。
6. 运行记录保留已确认的日期与基线。用户更改选择或启动失败后，旧预览失效。

ETL 编排器也提供自动模式：隐藏日期型运行参数，必须先“分析自动增量区间”。自动模式使用服务端数据集合同，不执行节点上原先写死的全量策略或旧日期。单接口下载/映射流程继续使用原手动模式；不把一个接口配置推测为完整市场数据集。

## 区间规则

| 数据类型 | 自动行为 |
| --- | --- |
| ETF / 场外基金净值、ETF 行情与份额 | 各自读取真实文件最新日期，含该日向前回查 5 个 SSE 交易日；截止上海时区昨日 |
| ETF / 场外基金净值、ETF 行情中的无历史代码 | 在全市场逐日更新前，单独按代码补齐；取已有快照历史起点与产品生命周期起点的较晚者，不重拉已有代码历史 |
| 指数行情与估值、基金复权、宏观利率 | 使用登记的文件/日期列推断；多文件分组采用最早的所需回查起点，传给已有分片采集器 |
| 持仓披露、分红 | 优先读取与基线 Parquet 绑定的公告日查询覆盖；补未查询日期，已查询且仍新鲜的日期复用。修订复核独立配置，不套用 5 个交易日 |
| 日历 | 先补至昨日，已经覆盖则复用；没有可用 SSE 日历时阻断 |
| 目录、经理、基准、增长通胀/货币/发布日历 | 按原有采集器刷新；宏观旧 vintage 保留。不宣称这些接口都是增量接口或常数时间 |
| 本地派生/指标快照 | 使用前置完整候选数据重建，原 NJIT 计算链不变 |
| 指数成分与权重 | 暂不开放自动区间合同，界面明确标示手动更新，禁止猜测日期 |

昨日只是请求上界，不是“数据已经披露”的断言。净值实际请求仍遵循现有交易日批次与空响应确认策略；迟报及修订通过重叠窗口重取。无历史代码已确认无数据仍记录采集器检查点，不用零填补。

**不承诺修复全部历史缺口**：现有代码在最近 5 个交易日之前的稀疏缺失，以及更早的修订，不由最新日期推断出来，仍需数据质量诊断和手动补历史。对于从快照中读出的最早待补范围超过一年的情况，失败关闭，要求分段手动补齐。空文件、未知日期、未来净值、失效 manifest、无基线都不能静默初始化。

## 后端实现

- `auto_incremental.py` 管理数据集范围合同与只读 planner。日期优先读取 Parquet row-group statistics；缺统计时只分批投影日期列，不读取完整净值矩阵。
- 扩展现有 `POST /api/data-sources/etl/validate` 返回 `auto_plan`；`POST /runs` 要求 `auto_plan_id`。旧 API 参数保持兼容。
- 计划 ID 包含执行图、日期策略、基线文件 size/mtime、来源/接口配置修订。启动采用现有全局下载锁，再验证计划；复制前后检查文件身份。
- 只复制所需时序基线和日历，宏观相关任务额外保留小型 vintage 文件。使用现有 macOS Copy-on-Write 或安全复制，不使用可写硬链接；私有清单存 checksum，后续恢复沿用冻结制品。
- 工作进程接收固定 `auto_step`；新模式没有 `has_baseline` 或已确认步骤时拒绝执行。已有代码走逐日/分页增量；无历史代码补齐后仍使用最初冻结的日期窗口，不能被新写入数据的 latest 截断。
- 原有 16 线程池、来源/API 双层共享配额、请求超时、重试、分页与行数上限不提升、不绕过。沿用已配置接口，不引入新供应商权限。
- 新增逻辑只涉及元数据读取、日期调度、文件复制和结果封装，不新增金融数学内核、不改变 NJIT 数值计算或启动预热。

## 数据发布与重复运行

自动下载结果仍是私有兼容数据和映射候选，**不会自动激活或覆盖正式快照**。最新日期只依赖实际返回的数据，不能提前推进到请求截止日。研究基线默认不变；用户可明确选择已完成任务作为采集基线，不把未发布的候选当作正式研究数据。

## 查询覆盖与事件增量优化（2026-09-10）

- `event_coverage.py` 是唯一事件覆盖规划实现，记录最新数据日之外的公告日查询覆盖、复核时间、基金身份集合、来源配置哈希和结果 Parquet 校验和。每个数据集只增加一个 `*.coverage.meta.json`，经现有清单/CoW 传递，不引入数据库迁移或为每个空基金生成长期覆盖文件。
- 只有完整分片及最终合并均通过后，才能提交覆盖；已独立复核的空响应可以推进查询覆盖，但绝不生成虚构数据行。缺失、损坏、来源变化、未完成 SPLIT 均不是可跳过的凭据。预览只读小型清单；启动/执行核验实际数据 checksum。必要代价为流式哈希读取，不解码完整金融矩阵，不新增金融数值计算或 NJIT 回退。
- 默认 `event_update_purpose=update`、复核间隔 7 天、近期窗口 90 个自然日；可改为主动 `recheck`。默认只更新未查询日期以及到期的已覆盖近期日期；同一截止/范围/有效覆盖重复运行不请求供应商。旧数据无覆盖证据时从最新公告日重查，不编造历史覆盖，也不自动回退完整历史。
- `auto_baseline_scope=acquisition` 必须配合明确选择成功任务，允许用较新的候选数据及其覆盖作为本次私有采集基线；旧客户端保持 `missing_only` 兼容语义。候选不得比活跃表更旧，不能借用只有覆盖却没有对应数据的记录。活跃研究文件和 manifest 永不改写。
- 持仓增量按全市场 `ann_date + offset/limit` 顺序分页，校验日期、页长和业务键；原始行数决定游标与末页，不能用去重后行数提前结束。跨页键重叠或同页数值冲突时，取得末页后按原 offset 完整复读全部页面，逐页全字段、原始顺序和 SHA-256 均一致才合并完全相同记录；无重复或冲突时不增加整轮复核。稳定数值冲突按本文上方隔离合同留档，不能当作质量通过；整页无新键、复核变化、未知末页、权限错误仍失败关闭。两轮读取及空页复核共享原请求预算、限流、超时与取消，不扩张逐基金遍历。全历史按基金/公告区间二分的现有合同保留，转型前历史不按当前成立日删除。
- 第一个空页只由调用方复核，后续空末页由分页器复核，修复空基金/日被复核两层而产生 4 次请求的问题；正常空查询固定 2 次成功请求，不取消独立复核。共享配额、连接/读取超时、有界重试及取消契约不变。
- 有覆盖时新增持仓基金身份单独按原历史起点补齐，再合并本次市场日期；分红不猜测未核定的单基金区间接口，目录变化时复核已有公告日。执行中暴露该变化；超出冻结范围或不支持的部分工作区迁移仍失败关闭，保留证据，不能强行按成功复用。
- 自动增量跨代码版本恢复沿用原 `auto_plan` 和 `task_baseline`，不按恢复当天重算日期。任务合同不变时，可复用非连续的成功节点，但它们的必需 `inputs` 上游必须全部成功；`after` 只约束顺序。逐一校验所有已经执行但未完成的工作区，分别迁移检查点，不只处理第一个失败节点；从未执行的节点在上游完成后才解析输入。共用正式执行的多输入清单解析。原文件/行数/校验和、分片和空复核均校验后导入新任务，SPLIT 仅审计而非完成；旧运行不改写。旧非自动单链合同仍要求成功前缀连续。
- 前端提供更新目的和修订间隔，区分最新公告日、已查询至、最近复核、本次新增/复核/复用天数和分页成本参考。运行页区分日期进度、分页位置、逐基金进度；分页安全上限不是总页数。累计接收不冒充新增/修订行数，未逐键比较的行数明确不作推断。

验收覆盖：相同截止零重复请求、截止增加一天只查询新日、覆盖空洞、到期与主动复核、损坏或不同来源拒绝复用、空查询 2 次、全市场跨页无逐基金扩张、旧图冻结基线/日期的跨版本恢复及旧记录不可变。时间策略和计数属于 I/O/编排元数据，不新增数值算子。

本轮验证：后端定向回归 300 项、前端组件 37 项、320/768/1440px 页面用例 6 项通过，包含展开修订策略表单后的布局。生产构建通过；全仓 TypeScript 和路由校验仍有其他模块/未跟踪文件的既有限制，不宣称全仓通过。供应商临时目录单请求 smoke 返回 66 行，另经共享配额验证全市场公告日分页的相邻页无重复、同页重取一致；实测不是完整历史数据验收。已保存持仓分页配置为每页 1,000 行、最多 1,000 页，限频仍为每分钟 400 次。

## 2026-09-10：可处理的拦截项与启动门禁

- 区分 `AUTO_BASELINE_NOT_ACTIVE`（已下载未启用）、`AUTO_BASELINE_REQUIRED`（缺少基线）、`AUTO_BASELINE_EMPTY`（空表或无日期）和 `AUTO_UNSUPPORTED`（尚无自动区间合同）。错误携带 `step_id/file`，不能把阻断步骤展示成准备刷新。
- `options.auto_baseline_run_id` 是显式选择，不是隐式 fallback。只接受成功完成、来源为 Tushare、最终清单可验证且接口字段/映射一致的候选。最多查询最近 20 条成功记录的小型清单，不扫描旧目录、不在预览阶段校验 GB 文件全量哈希。
- `auto_baseline.py` 负责候选发现与排除建议；`auto_incremental.py` 仍是唯一日期规划器。`missing_only` 只补活跃快照中不存在的登记时序表；明确选择 `acquisition` 时可将较新的候选作为私有采集基线，但不改活跃表。空表、符号链接、损坏表不能借此绕过校验。实际文件日期仍须通过未来日期/一年缺口门禁。
- 计划哈希包含所选候选文件的路径、校验和及 stat 身份；启动锁内重算计划并校验所选文件哈希、复制品哈希与快照身份，再交给执行器。复制使用现有 CoW/安全复制；不会把原工作区可写硬链接进新运行。
- “仅保留可增量步骤”是显式、可审阅的草稿修改，不是把失败伪装成成功。现有图的真实 `inputs` 依赖闭包一并排除，只剔除失效的 `after` 顺序边；不放松用户自定义硬依赖。旧串行模板须另行确认按服务端合同重排连线，原保存定义和历史记录不变。修改后的草稿必须重新校验，可保存为独立流程。
- 自动工作台的新图直接区分 `inputs` 和 `after`，避免把执行顺序误当数据依赖。按钮始终可见；自动模式未预览、校验失败、正在处理、状态未知、已有任务或只读时置灰，旁边给出原因。手动下载校验失败同样置灰，提供重新校验入口。配置或视图变化立即使旧结果失效，忽略过期响应。
- 候选复用保留跨日期/PIT 风险提示，不宣称历史可得一致，不绕过发布门禁。最初仅处理候选和按钮门禁时没有修改供应商调用；后续事件增量优化的分页配置与真实 smoke 以本文上方的本轮验证记录为准。
