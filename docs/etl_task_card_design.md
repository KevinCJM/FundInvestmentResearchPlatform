# 下载任务：当前状态优先

## 问题与目标

恢复是同一次下载工作的继续，不应被用户理解为又新增一次独立下载。原页面将执行记录直接平铺，并在每次迁移时累加“（恢复）”，导致历史失败淹没当前进度。保留审计记录，但将“任务”和“执行记录”分层。

## 页面结构

- 每条恢复链一个主卡片：稳定名称、当前状态、已完成步骤数、更新时间。
- 顶部操作只针对卡片的当前运行：运行中取消，停止后恢复；恢复需要确认跨日与供应商请求风险。
- 进行恢复校验时展示校验阶段与日志，不把旧失败步骤作为当前下载进度。大文件核验不伪造百分比。
- 正常下载在上方突出当前步骤及其进度、心跳和日志；“查看全部步骤”默认折叠，展开后按原顺序展示所有步骤（包含上方已展示的当前步骤），不跳号。两处复用同一份步骤状态和进度。
- “历史记录”是卡片内的小信息栏，默认折叠、限制高度。显示旧时间、当时状态、失败步骤、原因、记录编号；不放旧任务的恢复/取消按钮。
- 跨日风险、未发布状态及采集时点证据继续显示；视觉合并不等于数据合并或 PIT 认证。
- 手机端标题与按钮换行，历史编号断行；恢复后刷新页面仍维持一条卡片。
- 来源目录加载失败时，独立读取的任务状态仍可查看；编辑权限未知时禁用操作，不能把配置错误误当下载停止。

## 唯一事实与接口

`GET /api/data-sources/etl/runs?view=current` 根据显式 `recovered_from` 关系聚合，先分组再限制30个任务。返回最新运行及只读 `history`：根任务ID、显示名、续跑次数、历史摘要、关系异常提示。原无参数列表接口和单记录接口继续保留审计兼容。

不按名称猜测任务关系。同名独立任务、分叉后继分别展示；仍运行的祖先不隐藏；缺失祖先或循环关系有提示。仅显示名清理旧机器后缀，新迁移不再追加后缀。原记录、冻结合同、执行指纹、制品与已发布快照均不改写。

旧执行记录包含较大的冻结合同。轮询只读取ID、更新时间和取消标记，仅当记录变化时加载正文；进程内单路初始化缓存，避免多个网页重复全量扫描外接磁盘。新运行、状态改变和取消请求仍由数据库版本驱动更新，不缓存当前进度的静态副本。

控制库为这三个列增加覆盖索引，避免即使只查版本列也需要遍历大JSON记录的溢出页。只增加查询索引，不迁移或重写业务记录；离线测试检查实际查询计划使用覆盖索引。

焦点指向旧记录时定位对应当前卡片，轮询不将旧记录再追加回主列表。迁移目标刚创建、尚未续跑时，卡片继续展示同链正在进行的恢复任务，避免显示无响应或误导为再次失败。

## 本地数据库锁故障修复

2026-09-09 的最新成分下载不是4163项都失败：4163项中4项 `dc_member` 出现 `SOURCE_DB_BUSY`；旧截图的全部失败属于此前配置缺失。具体长期占锁者未被证实，不能据此认定供应商限流或PIT后台审计是直接原因。

配额预留/释放和原始批次登记只对已回滚的本地 SQLite BUSY/LOCKED 事务最多重试3次，每次锁等待最多15秒，加短指数退避与抖动。网络请求和文件落盘不在重试闭包内；磁盘满、I/O、权限与数据合同错误立即失败。配额按实际拿锁时刻记账，仍使用原来源/API共享限额。

实机还确认：目录GET调用预设初始化，原先即使预设未变化也会申请写锁；同时，旧任务轮询反复完整读取冻结合同。改为预设只读预检，无变更不申请写锁；需要初始化/更新时才原子核验写入。状态正文按版本缓存，缩短读锁持有。测试验证另一连接持有写锁时，已初始化目录预检仍可完成。

迁移只接收完整的成员查询阶段：核验冻结前置文件、输入合同、采集时点、请求参数、文件名、校验和、完整Parquet内容、行数、身份与日期。双空复核的成功回执也保留原采集时间。未知文件、损坏回执、孤立文件、软链接和无对应迁移规则的权重阶段文件拒绝导入，不能静默丢弃。保留原记录，生成新执行合同，正常续跑校验后再补未完成查询。

实机补充发现：原工作进程参数仅按 `attempt > 1` 开启resume，迁移后的新运行首次执行反而关闭缓存。修正为依据已存在且通过输入/任务/执行版本核验的工作区标记启用检查点复用；首次正常新建工作区仍不复用。回归测试必须使用真实payload.resume，不得在测试采集器中强制写成True。运行75ee的误重复请求已通过取消接口停止，旧源运行a221检查点仍保留；后续从最新取消运行核验迁移，同日新请求也保留原采集时间，不静默回写旧数据。

## 验收

- 超过30条恢复记录仍归一，原API与原记录不变。
- 同名独立任务、分叉、环、缺祖先及活动祖先安全展示。
- 操作只作用于当前ID；连接中断、取消中、恢复中状态不混淆。
- 校验和/日期/身份/行数/回执/路径/阶段错误均失败关闭。
- 离线迁移测试证明完整查询不重请求、前置结果和活跃快照不变。
- 真实小样本使用现有共享配额，全部输出在临时目录；本轮16请求得到35,110条规范化成员、300条权重，再次执行零请求。部分成员缺少历史纳入日期的标准映射拒绝仍保留，不伪造PIT历史。
- 前后端回归、构建及320/768/1440宽度交互验证。
